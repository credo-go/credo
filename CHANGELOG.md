# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Credo is pre-1.0: minor (`0.x`) releases may contain breaking changes; when they do, the break is called out explicitly under **Changed** or **Removed**.

The `store/sqldb` submodule is versioned in lockstep with the root module (path-prefixed `store/sqldb/vX.Y.Z` tags — see [CONTRIBUTING.md#releasing](CONTRIBUTING.md#releasing)); its changes are recorded here.

The `v0.1.0` section records the initial public development baseline; it was not published as a Git tag. Tagged root and `store/sqldb` releases begin with `v0.2.0`.

| Release module | Compatible root module |
| --- | --- |
| `github.com/credo-go/credo/store/sqldb vX.Y.Z` | `github.com/credo-go/credo vX.Y.Z` |

## [Unreleased]

### Added

- `SecureConfig.DisableXFrameOptions` turns `X-Frame-Options` off, for an application whose `Content-Security-Policy` sets `frame-ancestors`.
- A framework `log` section: `log.level` (`debug`, `info`, `warn`, `error`) and `log.format` (`text`, `json`) select the App's logger when none is passed with `WithLogger`. A reload applies both to the logger and to every logger derived from it.
- `credo.New` records what its automatic configuration load read: the files found, the `.env` file and the environment prefix, never a key or a value. The record is at Info when a file was read and at Debug otherwise, so a test that counts the records of the App's logger at Debug sees one more.
- `config.Sources` and `(*config.Config).Sources()`, the same list for an application that loads explicitly.
- `Context.T` and `Context.TPlural` warn in debug mode when the key is not in the catalog, naming the key, the locale and the route.
- `config.Section[T].Exists(src)` reports whether a section is present in any `RawConfig`, decoding nothing.
- An App that has health checks and never called `UseHealth` warns once when it starts, since no endpoint runs them.
- `credo.View()`, on `Provide` and `ProvideValue`, declares a binding a view of a resource another registration owns: a wrapper beside the handle it embeds, the interface an adapter's constructor returns, or one pointer under a second type. The App starts the resource, asks its `Ready` and shuts it down through the owner alone, and a consumer of a view starts after the owner. A view's owner exists before the view's value: an owner handed in (`ProvideValue`, `Manage`) may come before the view or after it, and an owner a constructor builds needs the view built from its binding — an `Alias`, or a constructor that takes the binding, with `credo.View()`.
- In debug mode the App names each binding whose `Close` it leaves open. When shutdown begins — the drain, a `Shutdown` before the start, or the rollback of a failed start — it logs one record at Warn, with `component=<binding name>`, for each built binding whose type shows `Close() error`, `Close()` or `Close(ctx) error`, that claims nothing, is not a view and whose resource no registration owns. The record gives the remedies: `credo.CloseOnShutdown()` when the App should close it or its `Close` releases nothing, `credo.View()` when another registration owns what it holds, and, for a `ProvideValue` binding, `credo.Borrowed()` when the caller closes it. `Close` is still never discovered.

### Changed

- **BREAKING (behavior): text after a catch-all panics at registration.** A pattern such as `/a/{p...}/x` can never match; it now panics with the message `middleware.Rewrite` gives such a pattern, and so does a catch-all in a `Mount` or `Static` prefix.
- **BREAKING: `ContractGuard` requires a Content-Type on a body by default.** A body-carrying request without one fails a `MetaAccept` contract with 415; `ContractConfig.AllowMissingContentType` lets it pass, and `RequireContentType` is removed.
- **BREAKING (behavior): a `UseHealth` that mounts no endpoint is the App's `UseHealth` call.** A second `UseHealth` after it panics, where it was accepted.
- **BREAKING (behavior): `middleware.Secure` fills the zero fields of a config it is given.** A `SecureConfig` that sets some fields still sends `X-Content-Type-Options: nosniff` and `X-Frame-Options: SAMEORIGIN`, where it sent neither. `DisableContentTypeNosniff` and `DisableXFrameOptions` turn them off, and the `ContentTypeNosniff` string is removed.
- **BREAKING (behavior): `middleware.Secure` sends no `X-XSS-Protection` by default.** Set `SecureConfig.XSSProtection` to send it.
- **BREAKING: a zero config field selects its default, and the `Default*Config` constructors are removed.** `DefaultContractConfig`, `DefaultCORSConfig`, `DefaultCSRFConfig`, `DefaultRewriteConfig`, `DefaultSecureConfig`, `DefaultTimeoutConfig` and `DefaultSkipper` leave `middleware`, with `ratelimit.DefaultConfig` and `httpclient.DefaultRetryConfig`: the zero config is the default one, and a nil `Skipper` skips no request.
- **BREAKING: `auth.Middleware[T](a, cfg ...auth.Config)` replaces `auth.Middleware[T](a, onError)`.** The failure callback is `Config.ErrorHandler`, a `func(*credo.Context, error) error` with the context first, and `auth.ErrorFunc` is removed.
- **BREAKING: `store.Kind` and the `store.Kind*` constants are removed.** Use `fault.Kind` and `fault.Kind*`, which they aliased; `store.Error.Kind` and `store.KindOf` have that type.
- **BREAKING: `validation.ValidationError`, `validation.Errors` and `validation.NewError` are renamed `validation.Violation`, `validation.Violations` and `validation.NewViolation`,** after the wire's `violations`. No behavior changes.
- **BREAKING: `log` is a framework section, decoded strictly.** An application section of that name with other keys fails `credo.New`, naming the unknown key: rename it, or pass the logger with `credo.WithLogger`, which leaves the section unread.
- **BREAKING (behavior): an XML request body with content after its root element is refused** with 400 `trailing_data`; white space, comments and processing instructions are still accepted. A body that passes the size limit after its root element is a 413.
- **BREAKING: `AddLivenessCheck` and `AddReadinessCheck` take a `func(context.Context) error`.** The `HealthChecker` interface is removed: pass `checker.Check`, or the function itself.
- **BREAKING: the `HealthConfig` switches are plain bools.** `Disabled`, `DisableLiveness` and `DisableReadiness` replace the `*bool` fields `Enabled`, `Liveness` and `Readiness`; the zero config still mounts both endpoints.
- **BREAKING: `App.State()` returns a `credo.State`,** with the constants `StateBuilding`, `StateStarting`, `StateRunning`, `StateStopping` and `StateStopped`. A comparison with a string literal still compiles.
- **BREAKING: `App.ConfigExists` takes a `config.Section[T]`,** as `GetConfig` does. A literal key converts with the type argument, `app.ConfigExists[CacheConfig]("cache")`.
- **BREAKING: `DIPanicError` is `PanicError`, a type of the root package.** `DIPanicPhase` is `PanicPhase`, a string type, and `DIPanicConstruction`, `DIPanicStart`, `DIPanicShutdown` and `DIPanicLateCleanup` are `PanicConstruction`, `PanicStart`, `PanicShutdown` and `PanicLateCleanup`.
- **BREAKING (behavior): the text of a `PanicError` begins with `credo: panic during`,** where it began with `di: panic during`. So does the text of a dependent's error or a `LifecycleError` that carries one, and the `error` attribute of the container's shutdown and late-cleanup log records.
- **BREAKING: `HTTPError` has no JSON member names.** `json.Marshal` of one writes Go field names; the error bodies are unchanged. Return the error and let the pipeline render it, or build a body from `ErrorInfo` in an `ErrorRenderer`.
- **BREAKING: a route is read as its `RouteInfo`.** `Context.Route()` returns a `RouteInfo` value, not `*Route`, and the zero `RouteInfo` when no route matched: test with `c.HasRoute()`, not against nil. `Exchange.Route()` returns the `RouteInfo`, not the pattern, and `Exchange.RouteName` is removed. `App.GetRoute(name)` returns `(RouteInfo, bool)`. `c.Route().GetMeta(key)` is unchanged.
- **BREAKING: `*Route` is the registration handle only.** `GetName`, `GetMethod`, `GetPattern` and `GetHost` are removed, and `BuildURI` and `BuildURL` are methods of `RouteInfo`.
- **BREAKING (behavior): meta read without a matched route is "not set".** `c.Route().GetMeta(key)` on such a request panicked on the nil route; it now reports false, so a guard on `PreRouting` that takes "not set" for "nothing required" passes every request. Check `c.HasRoute()` first and register the guard with `app.Middleware`.
- **BREAKING (behavior): `BuildURL` of a host-scoped route returns a network-path reference,** `//acme.myapp.com/users/42` where it returned `acme.myapp.com/users/42`. Prefix `https:` for an absolute URL.
- **BREAKING (behavior): `BuildURI`, and `BuildURL` of a route without a host, return an error for a path that begins with `//`,** which a root catch-all builds from a value that begins with `/`: a client reads such a reference as a host.
- **BREAKING: `Context.T` and `Context.TPlural` take a `credo.MessageKey`.** A literal key is unchanged; a `string` variable or a computed string converts, `c.T(credo.MessageKey("status." + code))`.
- **BREAKING (behavior): `testutil.CheckMessageKeys` checks the first argument of `T` and `TPlural`,** so a test that passed may fail for a key there that no catalog defines. A computed key written as a literal or string-constant prefix ending in `.`, followed by the computed part, is a family: the check fails when no catalog has a key under the prefix, where it reported every such conversion.
- **BREAKING (behavior): one registration owns a resource.** The first registration that claims a resource — its value has `Shutdown`, or it carries `credo.CloseOnShutdown()` or `credo.Borrowed()`; for a constructor, when its value is built — owns it, and a second claim is refused unless it is a view (`credo.View()`, or `app.Alias` for an interface): `ProvideValue` and `Manage` panic at the call, and a constructor's value fails its build, naming the owner and the remedies. A wrapper bound beside the handle it embeds, or a second binding of one pointer, was accepted, with the registry picking a holder of record and checking that the registrations agreed on the tier and the readiness options.
- **BREAKING (behavior): a view takes none of the options that shape a resource.** `credo.Ingress()`, `credo.ComponentName`, `credo.OptionalReadiness()`, `credo.CloseOnShutdown()` and `credo.Borrowed()` beside `credo.View()` panic at the call: give them to the owner's registration, whose name, options and tier the resource's readiness entry and teardown carry.
- **BREAKING (behavior): a value a constructor builds that holds a resource another registration owns fails the start.** A worker constructor, or a constructor handed to `Manage`, whose value is a binding's value or embeds a bound handle no longer defers to the binding: register the run function `(*T).Run` in place of a worker constructor that returns the binding's value, drop a `Manage` call over one, and hold the handle in a named field of a wrapper.
- **BREAKING (behavior): a binding whose interface hides its value's `Start`, `Ready` or ingress tier is refused whatever else holds the resource.** `app.ProvideValue[Querier](db)` panics before `app.ProvideValue(db)` and after it, where it was accepted after it: declare it a view with `credo.View()`, or bind the interface with `app.Alias`.
- **BREAKING (behavior): a `Provide` whose `credo.ComponentName` name another component has panics at the call,** where it failed the start.
- Health checks are collected in any order: `AddLivenessCheck` and `AddReadinessCheck` are accepted before `UseHealth`, after it, and beside a `UseHealth` that mounts no endpoint, where they never run.
- A strict unknown-key error names the `.env` entry or environment variable that set the key.
- A SIGHUP under `Run` over a configuration that cannot reload is logged at Info as ignored, with the signal and the configuration's type, instead of being dropped.

### Fixed

- A field promoted from an unexported embedded struct is bound from a query or form and named in its violation, as `encoding/json` promotes it; a field promoted through an embedded pointer is named as well, where its violation had an empty field.
- `App.Routes` on an App with host routes may be called while another goroutine prepares the App; it read the host list that preparation sorts.

## [0.26.0] - 2026-11-09

**Pre-v1 reshaping.** This release reshapes the contracts v1 will freeze so that each has one way to do each thing:

- An error has one status channel, and a message key is a catalog key.
- A request value or a route meta entry is a typed key over one context head.
- Route meta is read after the match by a routed middleware tier, and a mount is a route.
- Configuration decodes strictly and is read through typed section descriptors; a section that must follow a reload is declared live, and certificate files rotate when they change.
- The access log is one observer of the final response.
- The Context is not pooled.
- Validation names a field as the client sent it and validates slices and nested values.
- JWT verification moves to `auth/jwtauth`.
- `store/sqldb` uses Bun's exported API only and counts only a query it can prove.
- Application modules register every service before any handler resolves.

Each change is breaking where it says so. The parallel APIs left beside each contract go. The [release notes](docs/releases/v0.26.0.md#check-this-first) list first the changes that compile unchanged, and the [migration guide](docs/guides/pre-v1-migration.md#v0260-at-a-glance) maps every removed or renamed call.

### Changed

#### Errors and message keys

- **BREAKING (behavior): one status channel.** The `HTTPStatus() int` channel is gone. An error's status comes from, in order:
  - `*HTTPError`;
  - `*fault.Error`;
  - the validation errors;
  - `*BindError`;
  - any other `fault.Provider`.

  Anything else renders 500. An error type that only has `HTTPStatus() int` renders 500.
- **BREAKING (Go API): a message key is a catalog key of type `credo.MessageKey`.** `WithMessageKey`, `HTTPError.MessageKey`, `ErrorInfo.MessageKey`, `RenderMessageKey`, `RenderInfo.MessageKey` and `validation.ValidationError.MessageKey` take one. A `string` variable no longer compiles there; `I18nConfig.ResolveMessageKey` still returns a `string`.
- **BREAKING (behavior): a missing catalog key is never rendered as text.** A key the catalog does not define falls back to the built-in message for the code, then to the status text.
- **BREAKING (behavior): a fault without an explicit code renders its kind as the code.** The codes are `already_exists`, `constraint`, `serialization`, `deadlock`, `contention`, `conflict`, `timeout`, `unavailable` and `read_only`; they were `conflict`, `gateway_timeout` and `service_unavailable`. `not_found` and every status are unchanged.
- **BREAKING (behavior): client input moves into `Details`.** This covers an unsupported content encoding (`encoding`), an unsupported content type (`content_type`), and `ContractGuard`'s rejected content type (`content_type`), required header (`header`), query parameter (`query`) and scope (`scope`). These rejections, and the API-version, body-size and decompressed-size ones, render their code's built-in message and carry no message key.
- **BREAKING (behavior): two misuses are internal errors.**
  - An unsupported bind field type is a 500 `invalid_bind_target` with the reason logged (was 400 `unsupported_bind_field_type`).
  - `Response.Redirect` with a status outside 300..308 is a 500 with the reason logged.
- `middleware.Timeout`'s 503 sets no message key, so `I18nConfig.ResolveMessageKey` maps its code `request_timeout`.
- The lifecycle's 503 takes its code from its status (`service_unavailable`, unchanged on the wire).

#### Context, values and meta

- **BREAKING (Go API): typed keys.** `Context.Set(key Key[T], val T)` and `Context.Get(key Key[T]) (T, bool)` replace `Set(string, any)` and `Get(string) any`.
- **BREAKING (Go API): typed meta.**
  - `SetMeta` and `RemoveMeta` on App, Group, Route and StaticRoute take a `Key[T]`.
  - `Route.LookupMeta(string) (any, bool)` becomes `Route.GetMeta[T](Key[T]) (T, bool)`.
  - `Group.SetMeta` and `RemoveMeta` now return `*Group` for chaining.
- **BREAKING (Go API): `RouteInfo.Meta map[string]any` is replaced by `RouteInfo.GetMeta[T]`.**
- **BREAKING (Go API): the meta keys are typed values.**
  - `credo.MetaAccessLog` and `credo.MetaRawResponse` are `Key[bool]` values, no longer string constants.
  - The ContractGuard keys `MetaAccept`, `MetaRequireHeaders`, `MetaRequireQuery`, `MetaAPIVersion` and `MetaScope` are `Key[[]string]` vars, and `MetaMaxBody` is a `Key[int64]`. A value of the wrong type no longer compiles, so the 500 for an unrecognized meta value is gone.
  - A `nil` contract list is an empty list and lifts the contract; `RemoveMeta` restores the group's.
- **BREAKING (behavior): one context head.**
  - `Context.Set` and `SetUser` no longer copy the request. Each pushes one context node; a key set again replaces its node, so a loop setting one key does not grow the chain.
  - Assigning `c.Request().Request` no longer changes `c.Context()`; `c.Within(ctx, next)` does, and debug mode logs one warning per route for the assignment.
  - The embedded request's own `Context()` lags the head after a `Set`.
- `middleware.Timeout` and `WrapStdMiddleware` run the rest of the chain in a scope. A value set by an inner middleware or handler, the user for one, is visible after the scope ends: to access-log filters, observers and error rendering. A mounted `http.Handler` sees the values set before the mount.
- `auth`, CSRF, static files, `Mount` and `httpclient` tracing read the request through `Request.Std()`, so they see the values set before them.
- **The Context is not pooled.**
  - Each request allocates one Context, which embeds its `Request` and `Response` by value and keeps the first four route parameters and the first two request values in fixed arrays. The five pooled allocations fold into one.
  - A `*Context` kept past its request reads that request's state — values, user, path, parameters, response status — never a later request's.
  - A `*Context` is still not safe for concurrent use, and its response cannot be written after the handler returns.
  - Cost at saturation behind `net/http`: −3.2% requests per second and +1 allocation per request (ADR-008).
  - `Request.RouteParams()`'s map is no longer recycled after the request.

#### Routing, middleware and observers

- **BREAKING (Go API): `App.GlobalMiddleware` is renamed `App.PreRouting`.** It is named for when it runs: before the match, on every request, the router's 404 and 405 included. The user tiers are PreRouting → routed → Group → Route (see **Added** for the routed tier).
- **BREAKING (behavior): a mount is a route.** A request a `Mount` matches carries a `*Route` for the mount: the mount's prefix as its pattern, the App's meta, no name, and an empty `GetMethod()`.
  - `HasRoute` is true for it.
  - Its handler runs inside the routed tier, through a compiled chain. Group and route middleware still do not apply to a mount.
  - `RouteInfo.GetMeta` on a mount reports the App's meta.
  - Its access record names the mount's prefix pattern.
  - For a mounted QUERY request without a Content-Type, the routed and pre-routing middleware now run before the 415, as for a route.
- **BREAKING (behavior): `middleware.ContractGuard` fails closed without a route.** Registered with `PreRouting`, it answers 500 for every request and logs one Error naming the registration and the remedy. It used to let every request through.
- **BREAKING (behavior): `middleware.Rewrite` matches the wire form, as the router does.**
  - Rules match the canonical wire path the router matches (every escape decoded except those of the RFC 3986 reserved characters and of `%`), not the decoded `URL.Path`. The rewritten path is stored in wire form, with `Path` and `RawPath` consistent.
  - A `From` pattern matches as a route pattern. An encoded slash is data inside a segment: `/old/{name}` matches `/old/a%2Fb` and rewrites it to `/new/a%2Fb`, which the router reads as one parameter `a/b`. A rule that matched across an encoded slash no longer does: `/old/{a}/{b}` does not match `/old/x%2Fy`.
  - A `{name:regex}` parameter is one segment, and its constraint is checked on the whole decoded value. It no longer matches across segments (`/p/{rest:.+}` does not match `/p/a/b`), and `%31` satisfies `[0-9]+`.
  - A `{name}` parameter ends at the byte that follows it in the pattern: `/d/{a}-{b}` splits `x-y-z` into `x` and `y-z`, where it used to split at the last `-`.
  - A catch-all keeps its slashes, and a captured value is decoded once, by the router.
  - Literal `From` text matches only its literal spelling: `%` meets the client's `%25`, and `;` does not meet `%3B`.
  - A custom `Regexp` rule is matched against the same canonical path and may still span segments.
  - `To` is a wire-form path: an escape in it stays data, and a literal `%` is written `%25`.
- **BREAKING (behavior): a `Rewrite` rule that cannot be right panics when the middleware is built.**
  - A malformed escape in a target's path: `credo: middleware.Rewrite rule 1: To "/new/100%" has a malformed escape at byte 8; To is a wire-form path, so write each escape as %XX with two hex digits and a literal % as %25`. A target's query string is not checked.
  - Text after a catch-all, which could never match: `credo: middleware.Rewrite rule 0: pattern: text "/x" after the catch-all {p...} in "/a/{p...}/x": a catch-all takes the rest of the path, so end the pattern with it`.
  - A malformed escape produced at request time, which only a `Regexp` group that splits an escape can cause, is an error naming the rule and the rewritten path, and the request is left unchanged.
- **BREAKING (Go API): `StaticRoute.BuildURI(filePath ...string) string` becomes `BuildURI(filePath string) (string, error)` and escapes each segment of the file path.**
  - A static URL whose file path needs escaping is now escaped (`a b/ü.txt` → `/static/a%20b/%C3%BC.txt`), so it routes back to the file.
  - The error names the path and the reason for a path no URL can represent: one that is not valid UTF-8, or one with a `.` or `..` segment.
  - `BuildURI("")` returns the prefix with its trailing slash. The prefix is joined as registered.
- **BREAKING (Go API): `AccessLogConfig.ResultFilter` is `func(ex *credo.Exchange) bool`** (was `func(*credo.Context, credo.AccessLogEntry) bool`).
- The access log is an observer. `UseAccessLog` registers it among the observers, at the position of the call. Its records are unchanged byte for byte. Its `Skipper` skips the access record alone: a skipped request still reaches every other observer.
- `Context.Rewrite` is gone (see **Removed**), so routed, group and route middleware run once per request.

#### Configuration and reload

- **BREAKING (behavior): configuration decodes strictly by default.**
  - `config.Load` and `config.LoadBytes` build a `*config.Config` whose every typed decode refuses a key that maps to no field of the target and converts no value across kinds (a boolean into a number, a number into a string, a scalar into a list). That covers `Unmarshal`, a reload's candidate, and the framework's own `server` section in `credo.New`.
  - Strings parse into the basic type of their target (`int`, `bool`, `float64` and the other numeric kinds), as duration strings and `TextUnmarshaler` targets already did. An environment or `.env` override such as `CREDO_SERVER__PORT=9090` therefore decodes.
  - Each failure names its full key path (`config: unknown key "server.prot"`, `config: key "app.port": expected type 'int', got unconvertible type 'bool'`), and every offending key of one decode is reported.
  - A failure that weak coercion would accept names `config.WithWeakDecoding()` (see **Added**).
- **BREAKING (Go API): `App.GetConfig` and `App.MustGetConfig` take a `config.Section[T]`.**
  - `app.GetConfig(AppSection)` infers `T`.
  - `app.GetConfig[AppConfig]("app")` keeps compiling, since the untyped key converts; a key held in a `string` variable needs `config.Section[T](key)`.
  - Both reject an empty key, which used to decode the whole tree.
- **BREAKING (behavior): `testutil.NewApp`'s empty configuration has no sections.** With no `WithConfig` pairs, it returns the not-found error a loaded `*config.Config` returns from `Unmarshal`, instead of accepting every key and leaving the target unchanged. `Exists` stays false.
- **BREAKING (Go API): `App.Reload(ctx)` returns `(config.ReloadResult, error)`,** the result `Config.Reload` returns, and logs it:
  - an abort at Error;
  - restart keys and overridden keys at Warn;
  - callback failures at Error;
  - a summary at Info.

  Values are never logged. Over a configuration that is not a `*config.Config` built by `config.Load` or `LoadBytes` (a custom `RawConfig`, or `testutil.NewApp`'s empty configuration), it returns an error naming the type and `config.Load`.
- **BREAKING (Go API): `Config.Reload()` becomes `Config.Reload(ctx)` and returns `(ReloadResult, error)`.** It validates and publishes the live sections and runs their callbacks, serialized.
- **BREAKING (behavior): a reload no longer re-reads the certificate pair or follows new `server.tls.*` paths.** The pair rotates when its files change (see **Added**), and a changed path is reported as needing a restart.
- **BREAKING (behavior): the restart report is computed against the start.** It lists every key whose value differs from the one the start read and that no live section covers, a `Decode`-bound section's key included. The key is reported on every reload until it reverts. The report used to list the keys this reload changed that no subscriber covered.

#### Validation

- **BREAKING (behavior): a violation is named by its source.** A violation of `BindQuery`, or of a form or multipart `BindBody`, names its field by the `query` or `form` tag.
  - The engine still names by `json`; the bind renames the violations the target's `Validate` returns (`validation.Errors` or `*validation.ValidationError`, not one wrapped inside another error) along the target's type. It does so only when validation fails, over tables cached per type.
  - A JSON body is unchanged, and an XML body keeps the `json` names.
- **BREAKING (behavior): `Field` runs the value's `Validate` once the field's rules pass,** for a field with rules as for one without. A field whose rules fail reports their violations only. The pair `Field(&x, NotNil[T]())` + `Field(&x)` now validates `x` twice; keep the first.
- **BREAKING (behavior): `Field` validates the elements of a slice or array** whose elements implement `Validatable`, or are structs whose pointer does.
  - Each element is validated through its own address, so a pointer-receiver `Validate` keeps what it normalizes.
  - Nil elements are valid.
  - A slice type with a `Validate` of its own is validated by it, not element by element.
  - Violations are named `field[i].name`.
  - An `Each` rule on the same field still runs, and never reports a violation twice with the element walk.

#### Authentication

- **BREAKING (Go API): the JWT authenticator is in `auth/jwtauth`.** Only an application that verifies JWTs now compiles golang-jwt; one that imports `auth` for `auth.Middleware`, the API-key or the Basic authenticator no longer links it. The package stays in the root module. The types drop the `JWT` prefix the package now names, and the errors take golang-jwt's `ErrToken` stem:

  | Before | After |
  | --- | --- |
  | `auth.JWTConfig[T]` | `jwtauth.Config[T]` |
  | `auth.JWTAdvanced[T]` | `jwtauth.Advanced[T]` |
  | `auth.JWTClaims` | `jwtauth.Claims` |
  | `auth.JWTAuthenticator[T]` | `jwtauth.Authenticator[T]` |
  | `auth.NewJWTAuthenticator[T]` | `jwtauth.NewAuthenticator[T]` |
  | `auth.ErrJWTMissing` / `auth.ErrJWTInvalid` | `jwtauth.ErrTokenMissing` / `jwtauth.ErrTokenInvalid` |

  Behaviour (extraction, key selection, the two tiers, validation) is unchanged.
- **BREAKING (error text): the JWT errors' text has the `jwtauth:` prefix.**
  - The sentinels read `jwtauth: token is missing` and `jwtauth: token is invalid` (was `auth: jwt token is …`).

#### Store and `store/sqldb`

  - A provable query meets three conditions:
    - it is built without `Apply`, `Unwrap` or a `Relation` callback;
    - its model's type does not implement `bun.BeforeSelectHook`;
    - it carries `GroupExpr` or `Distinct`, or it has no raw `ColumnExpr` and no `Having`.

## [0.25.0] - 2026-11-09

**Bootstrap simplification.** The composition root shrinks to what only the application knows. A bound store is an ordinary component: `app.ProvideValue(db)` alone pings a `*sqldb.DB` at start, reports it in `/ready` and shuts it down after its consumers, and `store.Register` goes; every readiness entry carries its latency, and `credo.OptionalReadiness()` reports an entry without letting it gate readiness. The first `Resolve` finalizes the container. `Provide` takes its binding's type from the constructor, an interface is bound with `Alias`, and a capability the binding's type hides is refused. A WebSocket server declares its ingress tier, and framework modules log through the App's logger, with one key, `component`, naming the application part. Workers move into the root package under `app.Workers()`, registered as a value, a run function or a constructor; rate limiting moves into `middleware/ratelimit`; `credo.Named` and `credo.Closer` are renamed `credo.ComponentName` and `credo.CloseOnShutdown`. Two defects of nested validation are fixed. The release is breaking; several changes compile unchanged and behave differently, and the [release notes](docs/releases/v0.25.0.md#check-this-first) list them first. The [pre-v1 migration guide](docs/guides/pre-v1-migration.md#v0250-at-a-glance) gives every replacement. `store/sqldb` now imports the root package and requires `credo v0.25.0`.

### Changed

- **BREAKING (behavior): every bound database gates readiness.** Every component whose binding's type shows `Ready` — a `*sqldb.DB` bound with `ProvideValue` or `Provide` among them — is pinged at start and enters `/ready`, whether or not `store.Register` named it before; a database bound without `store.Register` was absent from `/ready`. A borrowed database is no longer pinged, since its owner starts it. A dependency that must not gate readiness is bound with `credo.OptionalReadiness()` (see **Added**).
- **BREAKING (behavior): the `/ready` body.** Every entry carries `latency`; the top-level status gains `degraded`; a database's entry is named `*sqldb.DB` or by `credo.ComponentName`; a resource held by two registrations — a raw handle and a wrapper that embeds it — reports one entry, its holder of record's, where two `store.Register` calls reported two; a failure is logged in the check shape (`credo: health check failed`, with `latency`). The health engine's store-status normalization goes: a store adapter's `Ready` decides, so a result that was up with a cause is what `Ready` returns, and `*sqldb.DB` reports `down` for any status but UP. The entry for a name that a component and a named check share is `credo.contributed_name_conflict.<i>` (was `credo.store_name_conflict.<i>`).
- **BREAKING (behavior): a WebSocket server is ingress by its type.** `websocket.Server` implements `credo.IngressComponent` (see **Added**), so a server registered without `credo.Ingress()` moves into the ingress tier, and an internal component that depends on it fails `Finalize` with the path and its two remedies. The never-started message is `credo/websocket: the server was never started; hand it to the App with app.Manage(server), or bind it`.
- **BREAKING (logs): one key names an application part.** A constructor's `Infra` logger writes `component=<binding name>` — the binding's type as the lifecycle prints it (`*users.Service`), or its `credo.ComponentName` name — in place of `service=<short type name>`, which wrote `service=Service` for both `users.Service` and `orders.Service`; `app.NewInfra(name)` writes `component=name` in place of `service=name`; the `http.Server.ErrorLog` bridge writes `module=net/http` in place of `component=net/http`; a worker's records write `component=worker:<name>` in place of `worker=<name>` (`module=worker`, `kind`, `status` and `reason` stay); WebSocket connection logs gain `module=websocket`; `sqldb`'s pool warning carries `module=sqldb` in place of `component=store` and `store=<name>`, with `component=<name>` when it goes to the App's logger.
- **BREAKING (behavior): the first `Resolve` finalizes.** The first `Resolve`, `ResolveAll`, `MustResolve` or `MustResolveAll` finalizes the container when nothing has, then resolves, where it panicked (`called before Finalize; call Finalize first …`, removed). `app.Finalize()` stays as an optional early check. `Has`, `GetConfig`, `MustGetConfig` and `ConfigExists` never finalize, and routes registered after the first `Resolve` are accepted until the App is prepared. A failed implicit `Finalize` is the triggering call's error, `MustResolve` panics with the whole report, and every later `Resolve` returns it; concurrent first resolvers finalize once. A `Resolve` after a bootstrap `Shutdown` froze a never-finalized container returns an error wrapping `ErrDIClosed`.
- **BREAKING (message): a late registration names what finalized the container.** A `Provide`, `ProvideValue`, `Alias`, `BindMany`, `credo.Override()`, `Manage` or `Workers().Continuous`/`Scheduled` call after the freeze names the trigger — `Finalize`, the first resolving call with its type, `Run`, `RunContext`, `ServeContext`, `Start`, or the first `ServeHTTP` call — its site, the first frame outside Credo's packages and `testutil`, and up to three callers: `credo: App.Provide[*app.Mailer]: called after the container was finalized by Resolve[*app.Hub] at /src/wiring/wiring.go:17 (called from /src/main.go:31); register before that call`. It replaces `called after Finalize; make every registration before Finalize, …`; the after-shutdown message is unchanged.
- **BREAKING (behavior): a capability the binding's type hides is refused.** A component whose binding's type hides its value's `Start`, `Ready` or `IngressTier` fails — `ProvideValue` panics at the call, a value a constructor builds fails once it is built, at the start or in the `Resolve` that builds it — where the capability was skipped without a word. The message names the binding, the methods its type hides and the remedy: bind the concrete type, and bind the interface with `Alias`. `credo.Borrowed()` is exempt, a type that hides only `Shutdown` is still torn down, and a view of a resource whose holder of record plans the capability is accepted: `ProvideValue(db)` followed by `ProvideValue[Querier](db)`, or a constructor that returns the bound handle as an interface. `ProvideValue` decides against the registrations made before it, so the view bound first is refused.
- **BREAKING (behavior): an alias is a binding.** A direct binding (`Provide`, `ProvideValue`) of an interface bound with `Alias` panics as a duplicate, naming the alias; with `credo.Override()` it replaces the alias.
- **BREAKING (behavior): a value a constructor builds claims nothing.** A value built by a constructor handed to `Manage`, or by a worker's constructor, that holds a resource a binding or a value handed to `Manage` also holds defers to that registration, its holder of record: it adds no readiness entry and never runs the teardown, so `/ready` shows the registration's entry with its name and options, and the teardown carries its name and tier, whatever the registration order. A constructor handed to `Manage` with `credo.ComponentName`, `credo.Ingress()` or `credo.OptionalReadiness()` whose value defers fails the start, naming the binding and the remedies. `Manage` of a constructor whose value embeds a handle bound with `ProvideValue`, borrowed or not, now starts, where it failed the start.
- **BREAKING (behavior): the registrations of one resource agree.** Registrations that hold one resource — a raw handle bound internal and a wrapper that embeds it bound with `credo.Ingress()`, say — agree on its tier, where the first registered decided the teardown's tier without a word, and on the options that shape its one readiness entry: `credo.OptionalReadiness()` on all of them or none, and one `credo.ComponentName` name. A disagreement panics at the second `ProvideValue` or `Manage`, or fails the start when a binding's constructor builds the value, naming both registrations and the remedies; a borrowed resource is exempt from the tier check.
- **BREAKING (Go API): `App.Provide(constructor, opts...)` has no type parameter.** The binding's type is the constructor's first result type: `app.Provide[T](NewT)` becomes `app.Provide(NewT)`, and `app.Provide[I](NewConcrete)` becomes `app.Provide(NewConcrete)` with `app.Alias[I, *Concrete]()`, or a constructor declared to return `I`. A message that names a binding keeps the form `App.Provide[*Mailer]`.
- **BREAKING (Go API): `credo.Named(name)` is renamed `credo.ComponentName(name)`.** The name labels a component in logs, `/ready` and lifecycle errors and is not a DI key; it applies to `Provide` and `ProvideValue` as well as `Manage`, is validated as a health name, panics on a binding that is not a component and on a duplicate name. A duplicate binding where either registration carries it says that the name is not a DI key, beside the wrapper-type remedy. No alias is kept.
- **BREAKING (Go API): `credo.Closer()` is renamed `credo.CloseOnShutdown()`.** It stays opt-in, and `Close` is never discovered. No alias is kept.
- **BREAKING (Go API): `websocket.New(cfg ...Config)` replaces `websocket.New(infra, cfg...)`.** The server settles its logger in `Start` — `Config.Logger` (see **Added**), else the App's, else the framework default — and refuses upgrades until then; `slog.Default()` is no longer a fallback.
- **BREAKING (Go API): workers live in the root package.** `app.Workers()` returns the App's one `*credo.Workers` registry — created on first use, the same value on every call, not bound in DI, registering nothing by itself — whose `Snapshot` and `Lookup` cover every worker of the App; a duplicate name panics at the second registration whoever made the first. The `worker` package is deleted, with no aliases: `worker.Use(app)` → `app.Workers()`; `Supervisor` → `Workers`; `Info` → `WorkerInfo`, whose JSON is unchanged; `Kind`, `KindContinuous`, `KindScheduled` → `WorkerKind`, `WorkerKindContinuous`, `WorkerKindScheduled`; `Status` and its constants → `WorkerStatus`, `WorkerStatusPending`, …; `Restart` → `RestartPolicy`; `RunInfo`, `CurrentRun` → `WorkerRun`, `CurrentWorkerRun`; `ErrRunTimeout` → `ErrWorkerRunTimeout`; `Worker`, `ContinuousConfig`, `ScheduledConfig`, `Schedule`, `ParseSchedule`, `DefaultMinRestartDelay` and `DefaultMaxRestartDelay` keep their names. Registration panics read `credo: Workers.Continuous("x"): …` and `credo: Workers.Scheduled("x"): …`, and `ParseSchedule`'s errors start with `credo: `. The engine moves to `internal/worker`, and `internal/kernel` is deleted.
- **BREAKING (Go API): a worker registration takes three forms.** `Continuous(name, w any, cfg...)` and `Scheduled(name, expr, w any, cfg...)` take a worker — a `credo.Worker` or a `func(context.Context) error`, named function types included; a run function, which takes exactly one `context.Context`, in any position, and returns only an `error`, whose other parameters are resolved from the container once, after their components have started — the method expression `(*OutboxRelay).Run` registers a worker that is a binding other code uses; or a constructor of a worker, `func(deps...) W` or `func(deps...) (W, error)`, which the start walk builds after its dependencies and which never becomes a binding. A constructor adds two components that are not bindings, its built value `worker-value:<name>`, internal and torn down after its loop, and the loop `worker:<name>`; each registration calls its constructor separately, so two registrations of one constructor no longer panic. A worker value passed in stays the caller's: the App never calls its `Shutdown`. Any other shape panics naming the forms accepted, and a function that takes two contexts, or a context and returns anything but a lone `error`, panics naming the run function's shape. In DI and lifecycle messages, a worker's units are named by its registration call (`di: missing dependency: Workers.Continuous("orphan") → *app.Queue (not registered); …`); the component names `worker:<name>` and `worker-value:<name>` are unchanged.
- **BREAKING (Go API): rate limiting moves into `middleware/ratelimit`,** so that importing `middleware` — for `CORS`, say — no longer links go-limiter: `middleware.RateLimit(cfg...)` is `ratelimit.Middleware(cfg...)`, `middleware.RateLimitConfig` is `ratelimit.Config`, and `middleware.DefaultRateLimitConfig()` is `ratelimit.DefaultConfig()`. `Config.Skipper` keeps the type `middleware.Skipper`. The package stays in the root module.
- **BREAKING (Go API): `store/sqldb` requires `Start` and `Ready` of a store adapter.** `*sqldb.DB` implements both (see **Added**); a store adapter of the application's own implements `Start`, `Ready` and `Shutdown`, as every component does.
- A registration option a call does not accept is refused with a message naming the options it accepts: `credo: App.Alias does not accept credo.Ingress(); it accepts credo.Override()`.
- Dependency bumps: `golang.org/x/text` v0.43.0 and `go.yaml.in/yaml/v3` v3.0.6 in the root module; `github.com/jackc/pgx/v5` v5.12.0, `github.com/go-sql-driver/mysql` v1.10.1 and `modernc.org/sqlite` v1.61.1 in `store/sqldb`.

### Added

- `credo.OptionalReadiness()`, a registration option on `Provide`, `ProvideValue` and `Manage` wherever the registration plans a readiness entry, and the one option of `AddReadinessCheck`: the entry is reported in `/ready` and logged when it fails, shown `down`, without gating readiness; while every gating entry is up and an optional one is not, `/ready` answers 200 with the top-level status `degraded`. During the drain `/ready` still answers 503 `shutting_down`. On a registration that plans no readiness entry it panics.
- `App.AddReadinessCheck(name, checker, opts ...credo.RegistrationOption)`: the variadic parameter keeps every existing call compiling; an option other than `credo.OptionalReadiness()` panics, naming it and the option accepted. `AddLivenessCheck` takes none.
- `latency` on every readiness entry, a named check's included, rendered with `Duration.String()`, and on the failure log.
- `(*sqldb.DB).Start(ctx)`: pings the database under `sqldb.Config.PingTimeout`, a new field — zero means `sqldb.DefaultPingTimeout` (5 s, moved from `store`), and a negative value fails `Open` with `sqldb: ping timeout must be >= 0, got <d>`. A failed ping closes the database and fails with `sqldb: ping did not answer within <d>: …` on the deadline, `sqldb: ping: …` otherwise. After a successful ping it logs each pool warning once at Warn (`credo: store configuration warning`, `code=sqldb.pool.max_open_unlimited`, `module=sqldb`), read from the effective pool.
- `(*sqldb.DB).Ready(ctx)`: nil when `Health` is UP, else `sqldb: database is <status>: <cause>`, wrapping the cause.
- `sqldb.WithOptionalStart()`: a failed ping at `Start` is logged at Warn and `Start` returns nil, leaving the pool open, since `database/sql` opens connections on demand once the server is back; `Ready` keeps pinging, so the database gates readiness until it answers unless it is bound with `credo.OptionalReadiness()`. On the App's logger the warning carries the component's name.
- `sqldb.WithLogger(l)`: the database's own logger, used unscoped; without it the database logs to the App's logger, scoped to its component.
- `credo.InfraFrom(ctx) credo.Infra`: the scoped `Infra` the App puts in the context of every call it makes on a component — `Start`, `Ready`, `Shutdown`, the `Close` of a `credo.CloseOnShutdown()` binding — and on an `OnStart` or `OnStop` hook, whose logger writes `component=<name>`; `context.WithoutCancel` keeps it. Outside such a call it returns the zero `Infra`. It is the path for a framework module whose value is built outside the App and started by it.
- `websocket.Config.Logger`: the server's own logger. With it, every record goes there, and each connection log carries `connection_id` and `request_id`.
- `credo.IngressComponent` (`interface { Component; IngressTier() }`): a registration whose type implements it is planned in the ingress tier without `credo.Ingress()`, which stays accepted and redundant. `IngressTier` is never called, so `Finalize` validates the tiers before anything is built. `websocket.Server` implements it.
- `App.Alias[I, T](credo.Override())`: points `I` at `T` in place of its earlier alias or direct binding; `Alias` accepts no other option. `Finalize` drops the type an overridden alias pointed at when no other alias, `BindMany` entry or constructor parameter reaches it: it is never built or started, and `Resolve` of it names the override.
- `App.Workers()`, `credo.Workers` with `Continuous`, `Scheduled`, `Snapshot` and `Lookup`, and a bare `func(context.Context) error` as a worker.
- `middleware/ratelimit`, with `Middleware(cfg...)`, `Config` and `DefaultConfig()`, maturity `beta`.

### Removed

## [0.24.1] - 2026-10-08

**Bug-fix release.** Three defects in how the lifecycle components of v0.24.0 treat one resource that several bindings hold are fixed. No exported API is added, removed or renamed; each fix changes what an application can observe, and the [release notes](docs/releases/v0.24.1.md#check-this-first) list them. `store/sqldb` has no code changes; its tag follows the lockstep policy.

### Fixed

- **lifecycle:** a resource that several bindings hold is started once. The start walk called `Start` for every binding whose type showed it, so one pointer under two types, or a handle and a wrapper that embeds it, was started twice and shut down once; `Start` now runs through the first holder the walk reaches whose binding plans one. A resource that any holder binds with `credo.Borrowed()` is not started through any holder: a wrapper over a borrowed handle that showed `Start` through the embedding made the App start the caller's resource and never stop it ([ADR-024](docs/adr/024-lifecycle-components.md#resource-identity-one-resource-one-teardown)).
- **lifecycle:** a holder that obtains a resource through one of its consumers no longer blocks the drain. Grouping the holders of one resource took on every holder's dependencies, so an interface view that a constructor read from a service using the resource made the resource wait for the service while the service waited for the resource; `Shutdown` stopped neither and reported each as `kept_open` by the other. The dependency that would close such a cycle is dropped when only a holder that reached the resource through another holder contributes it, so the service stops first and the resource after it; every other dependency holds — a holder's own, and a real dependency between two such groups ([container spec](docs/specs/container.md#resource-identity-and-teardown)).
- **lifecycle:** a value the container refuses after its constructor built it is released. A `ResourceIdentity` that returns an unusable token, or a component found only on its built value that depends on an ingress one, fails the construction; the value was dropped without its `Shutdown` or `Close`. When no other holder carries it, the drain now releases it in dependency order, or the late cleanup does after the deadline. A value refused because its holders disagree on the teardown's kind or owner is the shared resource and is left to its owner.

### Documentation

- ADR-024, the container and lifecycle specs, the `Starter`, `ResourceIdentifier` and `Borrowed` godoc and the dependency-injection guide state that a shared resource is started once, that a borrowed resource is started through no holder, how a holder's route to the resource is treated in the drain and which refused values the drain releases; ADR-024 records the rejected alternatives.

## [0.24.0] - 2026-10-08

**Lifecycle components, sequential bootstrap and a seven-method DI surface.** The App has one lifecycle abstraction, the component — a value with `Shutdown(ctx) error` whose teardown the App owns, started when its binding's type shows `Start`, asked for readiness when it shows `Ready`, and stopped in two tiers after its consumers — which replaces `Shutdowner`, `OnPreDrain`, `OnDrain` and `OnShutdown` ([ADR-024](docs/adr/024-lifecycle-components.md)). Bootstrap is sequential: registration panics on misuse, `Finalize` reports the whole graph, and the start phase reports what touches the outside world. Stores, the WebSocket server, i18n and workers run on the components; the DI surface is seven methods and `Finalize`; a validation rule's plain error is internal; `StatusHandler` refuses the codes it never consults. Most breaks are compile errors, but several compile unchanged and behave differently — the [release notes](docs/releases/v0.24.0.md#check-this-first) list them first, and the [migration guide](docs/guides/pre-v1-migration.md#v0240-at-a-glance) gives every replacement. `store/sqldb` changes only in its documentation and tests; its tag follows the lockstep policy.

### Changed

- **BREAKING (behavior): a validation rule's error is internal unless it is a violation.** A rule reports a client-visible failure with a `*validation.ValidationError` (built by the new `validation.NewError(code, message)`) or `validation.Errors`. Any other error — `errors.New` in a `validation.By` function, a database error from a lookup inside a rule — used to become a 422 `validation_failed` violation with code `invalid` and the error's text as its message, while validation went on with the other fields. It now stops validation and leaves `Validate`, `BindBody` and `BindQuery` unchanged, so the error pipeline renders a plain error as a 500 whose text is only logged, and a fault with its mapped status (`store`'s unavailable kind → 503). The 422 told the client its input was wrong when the server had failed, and put internal text such as a driver error into the body ([ADR-011](docs/adr/011-validation-strategy.md#rule-errors-client-messages-and-internal-failures), [error-handling guide](docs/guides/error-handling.md#rule-errors-client-messages-and-internal-failures)).
- **BREAKING (behavior): an explicit `HTTPError` wins over the validation errors it wraps.** `credo.NewHTTPError(409, "tenant_conflict").WithInternal(vErrs)` rendered 422 `validation_failed`, because classification looked for validation errors anywhere in the chain first; it now renders 409 `tenant_conflict`, and the wrapped errors stay in `ErrorInfo.Err`. A single `*validation.ValidationError` that no `HTTPError` wraps — returned from `Validate` — renders 422 `validation_failed` with one violation instead of a 500 ([ADR-009](docs/adr/009-handler-and-error-handling.md#an-explicit-status-wins)).
- **BREAKING (behavior): workers and stop hooks drain in two tiers.** The drain stops the ingress tier — its `OnStop` hooks LIFO, then its components concurrently — beside the HTTP drain, waits for an in-flight reload, then stops the internal tier: its `OnStop` hooks LIFO, then its components in reverse dependency order, all under one shared deadline. Every worker's context used to be cancelled when the drain began, before the HTTP drain, with the pool waiting for the workers beside it; a scheduled worker now stops with the HTTP drain, but a continuous worker now stops after it — once the handlers that enqueue its work have finished — and before the components it depends on, unless it declares `Tier: credo.TierIngress`. A worker `Run` that ignores cancellation past the deadline is abandoned with the components it depends on kept open, where the teardown used to go on closing them. The former `OnShutdown` hooks, now `OnStop`, run before their tier's components stop instead of after DI teardown, and also on bootstrap teardown and on the rollback of a failed or interrupted start ([lifecycle spec](docs/specs/lifecycle.md#shutdown-in-tiers)).
- **BREAKING (behavior): `OnStart`'s context ends with the call.** It used to live for the App and be cancelled at shutdown, so a goroutine launched from a hook on it now stops as soon as the hook returns. Background work becomes a component whose `Start` launches it on `context.WithoutCancel(ctx)` with its own cancel and whose `Shutdown` stops it, or a worker. A component's `Start` context follows the same rule.
- **BREAKING (behavior): a shutdown during startup interrupts the start.** The first signal in `Run`, the context of `RunContext` or `ServeContext`, or `Shutdown` — now accepted while the App is starting, waiting for the rollback within its own context — cancels the running `Start` or start hook, starts nothing further and rolls back what was built under the shutdown timeout; the listener never accepts and `Run`/`RunContext` return nil after a clean rollback. A shutdown used to wait for every `OnStart` hook, log "server started" and then drain, and `Shutdown` refused a starting App.
- **BREAKING (behavior): a binding whose type shows `Start` and `Shutdown` is started by the App.** The start walk builds it — even when nothing resolved it — and starts it in dependency order, so an `OnStart` hook that also starts it makes it start twice: delete the hook. Behind an interface that hides either method, the hook alone starts it. A binding whose type shows `Shutdown` and `Ready(ctx) error` is likewise built in the start phase, and `/ready` aggregates its `Ready` under the component's name.
- **BREAKING (behavior): a resource several bindings hold is shut down once.** One pointer under several bindings, an adapter constructor that returns the same pointer, or a wrapper and the `*sqldb.DB` it embeds used to be shut down once per binding, the first time before its consumers. Holders that share a resource identity are now one component, torn down once through the holder registered first among those with a teardown, after the consumers of every holder; holders that disagree on the kind of teardown (`Shutdown` or `credo.Closer()`) or on its owner (`credo.Borrowed()`) panic at registration or fail the later construction. A wrapper that releases state of its own holds the handle in a named field instead of embedding it ([container spec](docs/specs/container.md#resource-identity-and-teardown)).
- **BREAKING (behavior): `ServeHTTP` refuses an App with start work until `App.Start` has succeeded.** An App served by an external `http.Server` or `httptest` that has a component with `Start` or `Ready`, a constructor handed to `Manage`, a start hook, a store registration, `UseI18n` catalogs, a WebSocket server or a worker panics on every request until `app.Start(ctx)` (`testutil.Start(t, app)` in tests) has run; it used to serve without starting anything, and `OnStart` hooks never ran. After a failed or interrupted `App.Start` the stopped App answers with the default 503 `service_unavailable` envelope. An App with nothing to start serves as before ([lifecycle spec](docs/specs/lifecycle.md#the-start-gate-on-servehttp)).
- **BREAKING (behavior): stores are pinged in the start phase.** A store's constructor and ping run in the start phase, not at registration, and a failed ping is a start failure that rolls back what was built. Each store's readiness probe is built once there, so `/ready` resolves nothing per request and has no store checks before the App has started. A store's binding is an ordinary one: an override of it is what the App pings, reports and shuts down. A raw `*sqldb.DB` and a wrapper that embeds it may both be registered; each is pinged and reported under its own name, and the database is shut down once ([store spec](docs/specs/store.md#lifecycle-of-a-bound-database)).
- **BREAKING (behavior): registration misuse panics.** `Provide`, `ProvideValue`, `Alias`, `BindMany` and `UseI18n` return nothing, so a call whose error was ignored compiles and now panics at its line on misuse — a constructor of the wrong shape, a duplicate binding, types that do not fit, a call after `Finalize` or after shutdown began — with a message naming the call and the remedy (`credo: App.Provide[*app.X]: *app.X is already registered; …`). `Resolve`, `ResolveAll` and their `Must` forms panic before `Finalize` instead of returning a "not finalized" error; after a failed `Finalize` they return its error. Registration comes from the goroutine that builds the App and is no longer safe for concurrent use ([container spec](docs/specs/container.md#sequential-bootstrap)).
- **BREAKING (behavior): `Finalize` reports the whole graph.** Every missing dependency is reported with its whole path from the registration that needs it (`di: missing dependency: *app.OrderService → *app.PaymentClient → *http.Client (not registered); provide *http.Client before Finalize`) and every cycle, joined in registration order with the same text on every run, where it reported the first cycle and each missing dependency by its direct consumer (`di: Validate: …`). It also reports an internal component that depends on an ingress one, with the path and both remedies.
- **BREAKING (behavior): `UseI18n` reads its locale files in the start phase.** The call validates the configuration, compiles the programmatic catalog and panics on misuse — more than one config, `Dir` with `DirFS`, an `i18n` section that does not decode, an invalid `Default` or programmatic message, a second call. A missing explicit `Dir`/`DirFS` or a malformed locale file, which used to be the call's error, fails the start ([i18n spec](docs/specs/i18n.md)).
- **BREAKING (behavior): the `worker` configuration section is no longer read.** `worker.restart_delay` and `worker.max_restart_delay` set the restart floor and cap of every continuous worker; every worker now runs with the package defaults (3 s, 1 min) unless its registration sets `Restart{MinDelay, MaxDelay}`. A leftover section is ignored — it is an unknown key only when the application decodes the whole tree into a struct under `WithStrictDecoding`.
- **BREAKING (behavior): the worker snapshot and statuses.** `Info` carries `schedule` at the top level and the resolved configuration under `continuous` (`tier`, `restart.disabled`, `restart.limit`, `restart.min_delay`, `restart.max_delay`, `unready_when_failed`) or `scheduled` (`tier`, `run_on_start`, `run_timeout`, `max_consecutive_failures`, `unready_when_failed`, `unready_until_first_success`, `unready_after_success_age`), and `last_started_at`/`last_succeeded_at`, where it carried `config.*`, `last_run` and `last_success`. The statuses are `pending`, `running`, `backoff` (a continuous worker waiting to restart), `waiting` (a scheduled worker between activations), `stopped` and `failed`; `idle` is gone.
- **BREAKING (logs): one worker log vocabulary.** `scheduled worker run failed` and `scheduled worker run completed` become `worker run failed` and `worker run completed` with `kind=scheduled`; `worker ticks skipped` becomes `worker activations skipped`; `worker exceeded max restarts`, `worker exceeded max consecutive failures` and `worker schedule has no future activation` become one terminal `worker failed` line with `reason=restart_limit`, `failure_limit` or `schedule_exhausted` (and `restart_disabled` for `Restart{Disabled: true}`); `worker started` carries `run_on_start=true` instead of `start_immediately=true`. Update log queries and alerts.
- **BREAKING (behavior): `StatusHandler` panics for any code but 404 and 405.** Only those two are consulted, so a handler for 403 or 500 was accepted and silently never called; it now fails at startup with `credo: App.StatusHandler(403): only 404 (http.StatusNotFound) and 405 (http.StatusMethodNotAllowed) are consulted; …`. A 5xx handler would re-enter application code inside error rendering; shape such responses with `UseErrorRenderer` ([ADR-007](docs/adr/007-router-and-routing.md#status-handlers)).
- **BREAKING (behavior): `testutil.WithOverride[T]` panics without an earlier binding of `T`.** It replaces through `credo.Override()`; it used to add a binding when the wiring had none, which is `testutil.WithWiring`'s job.
- **BREAKING (behavior): a failed start returns a `*credo.LifecycleError`.** `Run`, `RunContext`, `ServeContext`, `App.Start` and `Shutdown` report a failed or interrupted start and an incomplete drain as one `*credo.LifecycleError`, whose entries name each component or hook (`OnStart[i]`, `OnStop[i]`, `worker:<name>`) with its tier, phase and outcome; a failed start hook used to read `credo: Run: OnStart hook [i]: …`.
- **BREAKING (Go API): registration calls return nothing and take registration options.** `Provide[T](ctor, opts...)`, `ProvideValue[T](v, opts...)`, `Alias[I, T]()`, `BindMany[I, T]()` and `UseI18n(cfgs...)` drop their `error` result; `if err := app.Provide[T](ctor); err != nil` no longer compiles. `OnStart(fn, opts...)` accepts `credo.Ingress()`.
- **BREAKING (Go API): `store.Register[R Lifecycle](app, opts...)` names a binding instead of taking a value.** Bind the store where its ownership is decided — `app.ProvideValue(value)`, or `app.Provide[R](ctor)`, with `credo.Borrowed()` for a handle the caller shares — and register it by type. It does no I/O, returns nothing, panics on misuse, and a registration whose `R` has no binding fails `Finalize` ([data-access guide](docs/guides/data-access.md#what-a-bound-database-does)).
- **BREAKING (Go API): `websocket.Use(app, cfg...)` is replaced by `websocket.New(infra, cfg...)`.** `New` registers nothing; the server is an ingress component whose `Start` opens admission: `app.Manage(ws, credo.Ingress())`, or a binding with `credo.Ingress()` when controllers take it as a dependency. A server that was never started refuses every upgrade with a 500 and logs the missing registration ([WebSocket guide](docs/guides/websocket.md#registering-the-server)).
- **BREAKING (Go API): workers are lifecycle components.** `worker.Use(app)` returns a `*worker.Supervisor`, a registry with no lifecycle of its own; `Continuous(name, w, cfg...)`, `Scheduled(name, expr, w, cfg...)`, `ContinuousProvided[T](name, cfg...)` and `ScheduledProvided[T](name, expr, cfg...)` each add one component named `worker:<name>` and panic on misuse. Scheduled workers default to the ingress tier, continuous workers to the internal tier; a provided worker is a constructor over `T`, built after its dependencies have started and stopped before them. Per-kind `ContinuousConfig{Tier, Restart, UnreadyWhenFailed}` and `ScheduledConfig{Tier, RunOnStart, RunTimeout, MaxConsecutiveFailures, UnreadyWhenFailed, UnreadyUntilFirstSuccess, UnreadyAfterSuccessAge}` replace the functional options; `Snapshot()` and `Lookup(name)` replace `Pool.Workers()`; `Info.Continuous`/`Info.Scheduled`, `Info.Schedule`, `Info.LastStartedAt` and `Info.LastSucceededAt` replace `Info.Config`, `Info.LastRun` and `Info.LastSuccess`; `StatusPending` replaces `StatusIdle`; `DefaultMinRestartDelay` replaces `DefaultRestartDelay`; `worker.CurrentRun(ctx)` with `RunInfo{Worker, ID, ScheduledAt}` replaces `RunID`, `WorkerName` and `ScheduledAt` ([ADR-023](docs/adr/023-worker-system.md), [worker guide](docs/guides/worker.md)).
- **BREAKING (Go API): `credo.Shutdowner` becomes `credo.Component`** with the same method set, so every `Shutdowner` is a component without a change; rename the assertions. **`*credo.DIShutdownError`** (with `DIShutdownEntry` and `DIShutdownState`) becomes **`*credo.LifecycleError`** with `LifecycleEntry`, `LifecyclePhase` and `LifecycleOutcome`.
- **BREAKING (Go API): `OnShutdown` becomes `OnStop`,** which runs before its tier's components stop; a hook that closed a resource becomes a component — a binding with `Shutdown` or with `credo.Closer()`, or a value handed to `app.Manage` — or moves after `Run` returns. The rename makes the moved slot a compile error rather than a silent change.

### Added

- **Lifecycle components** ([ADR-024](docs/adr/024-lifecycle-components.md), [lifecycle spec](docs/specs/lifecycle.md#components-and-the-start-phase)): `credo.Component` and the optional capabilities `credo.Starter` (`Start(ctx) error`), `credo.Readier` (`Ready(ctx) error`) and `credo.ResourceIdentifier` (`ResourceIdentity() any`), planned from the binding's type at registration; `credo.Tier` with `TierIngress` and `TierInternal`, which encode as `"ingress"` and `"internal"`.
- **Registration options** (`credo.RegistrationOption`), each checked at the call: `credo.Ingress()` (the ingress tier, for components and hooks), `credo.Borrowed()` (on `ProvideValue`: the caller keeps starting and stopping the value; its `Ready` still counts), `credo.Closer()` (a binding whose type has `Close() error`, `Close()` or `Close(ctx) error` becomes a component the App closes), `credo.Override()` (replaces an earlier binding before `Finalize`, panicking when there is none) and `credo.Named(name)` (names a managed component).
- `App.Manage(v, opts...)` adds a component that is not a DI binding — a value, or a constructor over DI parameters that the start walk builds — and a mounted child App through `parent.Manage(child)`.
- `App.Start(ctx)` runs the start phase without a listener, for an App served through `ServeHTTP` by an external `http.Server` or in a test; it is accepted once, while the App is building. `testutil.Start(t, app)` starts an App for a test and shuts it down when the test ends.
- `App.OnStop(fn, opts...)`, a stop hook that runs LIFO before its tier's components stop.
- `*credo.LifecycleError` with `LifecycleEntry{Name, Tier, Phase, Outcome, Err, KeptOpenBy, Duration}`, `LifecyclePhase` (`start`, `shutdown`) and `LifecycleOutcome` (`failed`, `panicked`, `abandoned`, `kept_open`); `credo.DIPanicStart` for a panicking `Start`.
- `/ready` aggregates the components' `Ready`, built once when the App starts, beside the stores' health and the application's checks.
- `validation.NewError(code, message)` builds the client-visible `*ValidationError` for a custom rule or a `validation.By` function.
- **worker:** `Supervisor`, `ContinuousConfig`, `ScheduledConfig`, `Restart` (with `Disabled`, which makes the first failed run terminal), `Supervisor.Lookup`, `CurrentRun` with `RunInfo`, `StatusPending` and `StatusBackoff`, and a per-worker `Tier`.
- `websocket.Server.Start`, which opens admission when the App starts the server.

### Removed

- **BREAKING (Go API): `App.OnPreDrain` and `App.OnDrain`.** What drained beside the HTTP server is an ingress component (`credo.Ingress()` on its binding, or `app.Manage(v, credo.Ingress())`) or `app.OnStop(fn, credo.Ingress())`; what drained before infrastructure is an internal component ordered by its constructor's dependencies.
- **BREAKING (Go API): `App.Replace` and `App.MustReplace`.** An override is `credo.Override()` on `Provide` or `ProvideValue` before `Finalize`, or `testutil.WithOverride` in tests; the replaced value is never handed back, because it never becomes the App's. A `Replace` after `Finalize` has no equivalent.
- **BREAKING (Go API): `App.ProvideProtectedValue`, `App.ProtectBinding`, `App.AdoptValue` and `App.CanProvideValue`.** Nothing framework-owned is bound in the application's container any more, so there is nothing to protect; `Has[T]` is the presence probe ([ADR-004](docs/adr/004-dependency-injection-and-infra.md#the-public-surface)).
- **BREAKING (Go API): `App.MustProvide`, `MustProvideValue`, `MustAlias` and `MustBindMany`.** The plain calls panic on misuse themselves. `MustResolve` and `MustResolveAll` stay.
- **BREAKING (Go API): `store.Registry` with `HealthAll`, `store.WithLifecycle`, `store.WithCallerOwnedLifecycle` and `store.LifecycleIdentityProvider`.** `/ready` reports every registered store; a value that is not a `store.Lifecycle` is registered through a wrapper type that implements it, with `credo.Borrowed()` for caller ownership; resource identity is `credo.ResourceIdentifier`, the same method.
- **BREAKING (Go API): `worker.Register`, `worker.MustRegister`, `worker.RegisterProvided`, `worker.MustRegisterProvided`, `worker.Pool`, `worker.Option` with its `With*` constructors, `worker.Config`, `worker.ReadinessPolicy`, `worker.StatusIdle`, `worker.DefaultRestartDelay`, `worker.RunID`, `worker.WorkerName` and `worker.ScheduledAt`.** The replacements are listed in the workers entry under **Changed**.
- **BREAKING (Go API): `websocket.Use`**, replaced by `websocket.New`.

### Fixed

- **lifecycle:** the defects that the component model closes ([ADR-024](docs/adr/024-lifecycle-components.md#context)). The last job an HTTP handler enqueued during the drain was lost, because the worker pool ran on the lifecycle context, cancelled before the HTTP drain began; a continuous worker now stops after the HTTP drain and before the database it writes to. A pointer held by two bindings was shut down twice, the first time before its direct consumer. `OnShutdown` hooks ran after DI teardown, so they could never use a singleton. A shutdown requested during startup waited for every start hook and then let the server accept. An App served through `ServeHTTP` silently started nothing. A failed start now stops exactly the components that were built, except the one whose `Start` failed. Both acceptance scenarios are pinned by tests.
- **validation:** a rule's internal failure no longer reaches the client as a 422 violation carrying its text (see **Changed**).
- **router:** a `StatusHandler` for a code the router never consults no longer registers silently (see **Changed**).
- **tests:** the test that asserts a 431 header-limit rejection is never logged matched `431` anywhere in the captured log, so a listener port such as 43163 or a timestamp's milliseconds failed it — this stopped the v0.23.0 release gate until a rerun. It now removes network addresses and the time attribute before matching.

## [0.23.0] - 2026-10-06

**Bug-fix release.** Fixes in the HTTP write path (informational statuses, flushes), routing (an empty catch-all rest, repeated and reserved parameter names), YAML configuration parsing and the release gate, found while shipping v0.22.0. Three change behavior an application can observe — a catch-all matches an empty rest, a pattern that repeats a parameter name panics at registration, and a YAML config with more than one document fails to load; the [release notes](docs/releases/v0.23.0.md#check-this-first) list what to check. `Response` gains `FlushError`; nothing is removed or renamed. `store/sqldb` has no code changes; its tag follows the lockstep policy.

### Changed

- **BREAKING (behavior): a catch-all matches an empty rest.** `/files/{path...}` now serves `/files/` with `path` = `""`, as chi and `net/http.ServeMux` do; it used to need at least one byte, so the prefix with a trailing slash answered 404, or a trailing-slash redirect to a sibling route without the slash. A mount now reaches its own root through `/admin/` (and `/t/acme/` under a parametric prefix), where it was redirected to `/admin` or answered 404 with `WithRedirectTrailingSlash(false)`; `Static` serves `/static/` directly instead of redirecting to `/static`; `POST /files/` on a GET-only catch-all is 405 instead of 404; `/files` without a route of its own is redirected to `/files/`; and `BuildURI`/`BuildURL` accept an empty catch-all value. An application that registers both `GET /files` and `GET /files/{path...}` now serves `/files/` from the catch-all instead of redirecting it to `/files`. The rewrite middleware's `{name...}` already matched an empty rest; the router now agrees with it ([router spec](docs/specs/router.md#url-parameters), [migration guide](docs/guides/pre-v1-migration.md#router)).
- **BREAKING (behavior): a pattern that repeats a parameter name panics at registration.** `/a/{id}/b/{id}` used to register, and the request then answered `RouteParam("id")` with the first capture but `RouteParams()["id"]` and `credo.URLParam` with the last. The check runs on the whole registered pattern — a route, a group prefix joined to its routes, a `Mount` prefix, `Static` under a parametric group (`/t/{_static}`) — and on rewrite rules (`middleware.Rewrite` `From`), as in chi and `net/http.ServeMux`. `app.Host` likewise panics on a repeated host parameter name (`{a}.{a}.example.com` kept the leftmost label's value only), a parameter without a name (`{}`, `{:[a-z]+}`, readable only as `RouteParam("")`) and an empty constraint (`{org:}`, which matched no host). `Mount` and `Static` reserve the name of the capture they add below their prefix: a mount prefix parameter called `_mount` read the rest of the path instead of its own value, and a group prefix parameter called `_static` under `Static` was served as the file path; both now panic (`credo: Mount "/t/{_mount}": the parameter name "_mount" is reserved`), and a name either prefix repeats is reported against the pattern the caller wrote ([router spec](docs/specs/router.md#url-parameters)).
- **BREAKING (behavior): a YAML config with more than one document fails to load.** The YAML parser read the first document of a stream and dropped the rest without a word: `a: 1` / `---` / `b: 2` loaded `{a: 1}`, a second document with a syntax error loaded too, and a file that opened with two `---` markers loaded an empty config. `Load`, `LoadBytes`, `Reload` and `Stage` now fail with `yaml: a config file holds one document; found another after the first` (or the second document's syntax error), as JSON already rejected trailing data. A trailing `---` opens an empty second document and is rejected as well; a leading `---` and a closing `...` stay valid, and an empty or comment-only file is still an empty config ([config spec](docs/specs/config.md#single-pass-loader-model), [migration guide](docs/guides/pre-v1-migration.md#configuration)).

### Fixed

- **response:** a flush commits the response, and `Response` now records it. net/http writes status 200 when a flush comes before any status, but `Response` stayed uncommitted, so an error the handler returned afterwards was rendered into the response already on the wire — its envelope appended to the flushed 200. Such an error is now logged (`credo: error after response committed`), as after any other commit; a flush a stdlib middleware makes through `WrapStdMiddleware` is recorded the same way. `Response` gains `FlushError`, which `http.ResponseController` prefers: it reports `http.ErrNotSupported` and commits nothing when no writer in the chain can flush, where the controller used to report success. Under `UseCompress`, a flush before the first write sent the 200 header without `Content-Encoding` while the body that followed was compressed; the compression decision is now made at the flush, so the flushed header carries `Content-Encoding`.
- **response:** an informational status other than 101 — `WriteHeader(103)` for Early Hints — is sent at once and no longer recorded as the response status. The handler's final status used to be dropped, so the client saw 103 followed by an implicit 200; under `UseCompress` the compression writer also made its decision on the 1xx and left the body uncompressed. `Response.Status()` and `Committed()` stay 0 and false until the final status. A status outside 100–999 now panics before `Response` or the compression writer records anything, as net/http's own check does: the response used to be recorded as committed with the invalid code, so recovery could not answer, the access record carried that code and the exchange ended with an empty 200.
- Release candidate validation confines its git commands to the throwaway clone it creates (`GIT_CEILING_DIRECTORIES`), so a directory that is not a repository root fails instead of resolving to an enclosing work tree. Go 1.27's `testing.T.TempDir` places test directories under `GOTMPDIR`; with `GOTMPDIR` inside a Credo checkout, the gate's own tests wrote the synthetic `v0.11.0` and `store/sqldb/v0.11.0` tags into that checkout. A checkout where the tests ran that way restores the published tags with `git fetch --force origin refs/tags/v0.11.0:refs/tags/v0.11.0 refs/tags/store/sqldb/v0.11.0:refs/tags/store/sqldb/v0.11.0`.

### Documentation

- The [pre-v1 migration guide](docs/guides/pre-v1-migration.md#configuration) gains a Configuration section and the v0.23.0 rows of its Router section. Tracked files no longer point at an untracked contributor file; the dependency allowlist the import-boundary test enforces is described in [CONTRIBUTING.md](CONTRIBUTING.md#coding-standards).

## [0.22.0] - 2026-10-06

**Bun v1.3.0 release.** `store/sqldb` moves from Bun v1.2.18 to v1.3.0 and from pgx v5.10.0 to v5.11.0. The curated `store/sqldb` API keeps its signatures; the break is where an application reaches Bun directly (`int64` for `Limit`, `Offset` and `Count`) and in what the database accepts (NUL bytes, duplicate migration IDs, soft-delete `WhereOr` precedence). The pre-v1 [migration guide](docs/guides/pre-v1-migration.md#data-access) lists the consumer-visible changes in one table. The root module has no code changes; its tag follows the lockstep policy.

### Security

- **sqldb:** Bun v1.3.0 carries three upstream security fixes; no Credo code had a defect of its own, and applications upgrade to inherit them. A negative number rendered right after a `-` in the SQL text — `Where("x = -?", n)` with `n = -1` — formed the line comment `--1` and cut the statement short (CVE-2024-44906 class, [uptrace/bun#1396](https://github.com/uptrace/bun/issues/1396)); Bun now separates the two with a space. Credo hands every argument to Bun's formatter rather than to driver placeholders, so this reached any Credo query with that shape. A string argument carrying a NUL byte is rejected instead of silently shortened ([uptrace/bun#1406](https://github.com/uptrace/bun/pull/1406); the **Changed** entry below has the per-database behavior). `pgdriver` verifies the server certificate under `WithInsecure(false)` ([uptrace/bun#1402](https://github.com/uptrace/bun/pull/1402)); Credo's PostgreSQL driver is pgx, so this fix does not reach a Credo application.

### Changed

- **BREAKING: `store/sqldb` requires Bun v1.3.0** (`github.com/uptrace/bun` and its three dialect modules, from v1.2.18). Bun now stores and accepts `LIMIT` and `OFFSET` as `int64` and `Count` returns `int64`. The curated `SelectQuery.Limit`, `Offset` and `Count` keep their `int` signatures, so code written against them compiles unchanged; code that reaches the native query — an `Apply` closure, `Unwrap`, `db.Conn(ctx)` — and passes an `int` variable to Bun's `Limit` or `Offset` stops compiling and needs `int64(n)`. `Count` returns an error instead of a truncated total when the `int64` count does not fit in `int`, which is possible on 32-bit platforms only. The private-field compatibility layer behind `Count` and `Page` is taught the new field types; its layout test pins Bun v1.3.0.
- **sqldb:** `SelectQuery.Limit` and `Offset` forward every value to Bun, and `Page` executes any window whose offset fits in `int`. Both used to reject values outside the signed 32-bit range before the query ran, because Bun v1.2.18 stored them in `int32` fields; with `int64` storage there is no range to guard. The remaining pre-execution checks are unchanged: `Page` still rejects a nil request, a non-positive `Page` or `PerPage` and a native `int` offset overflow with `pagination.ErrInvalidPageRequest`, and zero or negative `Limit`/`Offset` values still omit the clause.
- **sqldb:** a string argument that contains a NUL byte (`0x00`) fails the statement on SQLite and PostgreSQL instead of being stored with the byte removed. Bun v1.2.18's dialects dropped the byte, so a value that an application had validated — `"admin\x00x"`, distinct from `"adminx"` — was persisted as another value; Bun v1.3.0's base dialect refuses to render it and the database rejects the statement with an error that `store.KindOf` leaves unmapped. MySQL is unchanged: its dialect still strips the byte ([uptrace/bun#1443](https://github.com/uptrace/bun/issues/1443)), which a canary subtest of the real-MySQL job pins so that the documents are updated when upstream changes it. Reject NUL at the validation boundary ([data-access guide](docs/guides/data-access.md#nul-bytes-in-strings)).
- **sqldb:** `github.com/jackc/pgx/v5` v5.11.0 (from v5.10.0). On Go 1.27 pgx scans PostgreSQL types through `database/sql` directly (`driver.RowsColumnScanner`); combined with Bun v1.2.18 that deadlocked every scan of a `jsonb`, `bytea` or `numeric` column into `map[string]any` ([uptrace/bun#1434](https://github.com/uptrace/bun/issues/1434)), which Bun v1.3.0 fixes and a real-PostgreSQL subtest pins under a deadline. pgx's own behavior changes that reach an application through `sqldb`: a `timestamptz` scanned from the text format is returned in `time.Local` (or the codec's `ScanLocation`), as the binary format always was; `date` rejects impossible dates such as `2024-02-30` instead of normalizing them; the OS user account is looked up only when the connection string, environment and service file name no user ([pgx v5.11.0 release notes](https://github.com/jackc/pgx/releases/tag/v5.11.0)).
- **sqldb:** `migrate.Migrations.Discover` returns `migrate: duplicate migration ID …` when two migration files share a numeric prefix under different names ([uptrace/bun#1357](https://github.com/uptrace/bun/pull/1357)). Bun v1.2.18 let the later file replace the earlier one's `Up`/`Down` silently, so one of the two never ran. `RegisterMigrations` is not reached with such a set; rename the file.
- **sqldb:** a top-level `WhereOr` on a soft-delete model, or next to `WherePK`, renders `WHERE (a OR b) AND deleted_at IS NULL` instead of `WHERE a OR b AND deleted_at IS NULL` ([uptrace/bun#1321](https://github.com/uptrace/bun/issues/1321)). A query that relied on the old precedence — a soft-deleted row reachable through the OR branch — changes its result set. `SelectQuery.Clone` carries the OR state along.

### Removed

- **sqldb:** `ErrInvalidLimitOffset`. Nothing returns it any more (see the `Limit`/`Offset` entry above); an `errors.Is` check against it stops compiling and can be deleted.

### Fixed

- **sqldb:** the COMMIT or ROLLBACK error of a transactional SQL migration (`.tx.up.sql`) reaches `Migrate`, so a commit that fails leaves the migration unapplied. Bun v1.2.18 discarded that error ([Bun #1389](https://github.com/uptrace/bun/issues/1389), fixed in v1.3.0), and the documents advised a Go migration with an explicit transaction wherever the commit result had to gate the applied marker; that advice is withdrawn. The contract is pinned by a conformance test — a deferred foreign key violated at COMMIT — on SQLite and PostgreSQL.

### Documentation

- Every Bun reference in the tracked documents and package comments is re-pinned to v1.3.0 after re-verification against its source, and the [pre-v1 migration guide](docs/guides/pre-v1-migration.md#data-access) gains a Data access section with the consumer-visible changes of this release.

## [0.21.1] - 2026-10-04

**Security and bug-fix release.** A fail-open defect in `middleware.ContractGuard` is closed, eight defects are fixed and YAML decoding moves to its maintained module. No exported API is added, removed or renamed; the [release notes](docs/releases/v0.21.1.md#check-this-first) list the fixes that change what a request does.

### Security

- **middleware:** `ContractGuard` no longer skips a declared contract whose route-meta value has a type it does not recognize. The guard read `string`, `[]string` and `[]any` values (`int`, `int32`, `int64` for `MetaMaxBody`) and treated every other type as "no requirement", so the route ran without the check it declared. With `MetaScope` that was an authorization bypass: `SetMeta(middleware.MetaScope, Scope("admin"))` — a named string type — let every request through where the plain string `"admin"` answers 403. `MetaRequireHeaders` and `MetaRequireQuery` were skipped the same way, a `MetaMaxBody` given as `uint`, `float64` or a string was ignored, a route-level `nil` silently switched off the contract inherited from its group, and a `[]any` lost its non-string elements. (`MetaAccept` and `MetaAPIVersion` were not skipped: an unreadable value already rejected requests, with 415 and 400; they now answer 500 like the others.) **Affected:** every release up to v0.21.0, in applications that declare a `ContractGuard` contract with a value outside the documented types. **After upgrading**, the guard rejects the request with the generic 500 instead of calling the handler, and the `credo: server error` log record names the route, the key, the value's Go type and the fix: `contractguard: route GET /api/reports: meta "scope" has unsupported type main.Scope; use string or []string (convert a named type, e.g. string(v); …); request denied`. **What to change:** convert the value where the contract is declared (`string(scope)`); replace a `nil` that was meant to lift an inherited contract with the value that requires nothing — `[]string{}` for `MetaScope`, `MetaRequireHeaders` and `MetaRequireQuery`, `"*/*"` for `MetaAccept`, a negative `MetaMaxBody`. The accepted types themselves are unchanged ([middleware spec](docs/specs/middleware.md#framework-meta-keys)).

### Changed

- **config:** YAML is decoded with `go.yaml.in/yaml/v3` v3.0.5 instead of `gopkg.in/yaml.v3` v3.0.1. It is the same decoder under the module path of the YAML organization, which took over its maintenance after the original author labelled the project unmaintained in April 2025. No Credo API changes, and the two modules coexist in one build, so an application that imports `gopkg.in/yaml.v3` itself is unaffected. One decoding difference reaches `config.Load`: a mapping with a non-string key that merges (`<<`) a mapping keyed by a sequence or a mapping made the old decoder panic; the load now fails with an error. The new module requires nothing, so the root module's three indirect requirements (`gopkg.in/check.v1`, `github.com/kr/pretty`, `github.com/rogpeppe/go-internal`) are gone.

### Fixed

- **router:** a route that matches the path but not the method no longer answers 405 while a less specific route serves the method. With `GET /users/new` and `POST /users/{id}`, `POST /users/new` was rejected with 405; it now reaches the parameter route (`id` = `new`), as it does in chi and `net/http.ServeMux`. The same holds for regex, catch-all and mount candidates: with `GET /api/users` and `Mount("/api", h)`, `POST /api/users` now reaches the mounted handler. The route that answers runs its own group and route middleware, which may differ from the more specific route's. A request is a 405 only when no route matching the path serves its method, and `Allow` then lists the methods of all of those routes instead of the most specific one's ([router spec](docs/specs/router.md#matching-order-and-method-not-allowed)).
- **router:** `Mount` supports a prefix with parameters. `Mount("/t/{tenant}", h)` was accepted, but the mounted handler was handed the path `/` for every request and no parameter: the prefix was cut off the path as literal text, which a parameter never matches, and the route context holding the value was not passed on. The handler now receives the real remainder — `/t/acme/x/y` arrives as `/x/y`, spelled for the wire as under a static prefix (`/t/acme/a%2Fb` → `/a%2Fb`) — and each parameter of the prefix as a path value: `r.PathValue("tenant")` or `credo.URLParam(r, "tenant")` in a stdlib handler, `ctx.Request().PathValue("tenant")` in a mounted Credo app, whose `RouteParam` keeps returning its own route parameters only. Several parameters, also within one segment (`/v/{major}.{minor}`), and regex-constrained ones are supported; an encoded slash inside a parameter stays data (`/t/ac%2Fme/x` → `tenant` = `ac/me`); nested parametric mounts add up, so the innermost handler sees every prefix. The values are set on a clone of the request, which leaves the path values of a request the caller still holds — an `http.ServeMux` in front of the app — as they were. `credo.URLParam`, which returned `""` in every mounted handler, now falls back to the request's path value. Static mounts are unchanged ([router spec](docs/specs/router.md#sub-router-mounting)).
- **bind:** the temporary files of a multipart form are removed when the form was parsed on a copy of the request. `net/http` removes them only for the request it created; after `ctx.SetUser`, behind `middleware.Timeout` or a `WrapStdMiddleware` middleware that substitutes the request, and inside a handler attached with `Mount`, the form lives on a copy, so every upload beyond the in-memory threshold left its `multipart-*` file in the temporary directory. The executor now removes the files of the form `BindBody` parsed and of the current request's form on every way out of the handler — normal completion, a returned error, a panic, a failed compressor; the layers that substitute the request hand a form parsed below them to the request that outlives them; and `Mount` removes the form a mounted handler parsed on its child request. As under `net/http`'s own cleanup, an uploaded file is gone once the handler has returned ([context spec](docs/specs/context.md#bindbody)).
- **lifecycle:** a panic in an `OnStart` or `OnShutdown` hook is recovered and reported as that hook's error, as it already was for `OnPreDrain`, `OnDrain` and reload hooks. A panicking `OnStart` hook used to unwind past the teardown — under `Run` it ended the process with the listener bound and no hook, drain or DI shutdown run; it now fails startup like a returned error: the full teardown runs, the listener is released and `Run` returns `credo: Run: OnStart hook [1]: panic: …`. A panicking `OnShutdown` hook used to skip the remaining hooks and leave the App short of `stopped`; the remaining hooks now run and `Shutdown` returns the joined errors. Each recovered panic is logged once at Error (`credo: OnStart hook panic` / `credo: OnShutdown hook panic`) with `hook_index`, the panic value and the stack. The order of the hooks is unchanged ([lifecycle spec](docs/specs/lifecycle.md#apponstartfn-opts-and-apponstopfn-opts)).
- **http:** a response written by a stdlib middleware adapted with `WrapStdMiddleware` is recorded. A middleware that answered by itself — a 401, a redirect, a file — reached the client correctly but left `Response` uncommitted: the access record said `status=200 bytes=0`, and an error returned further up the chain, or a panic in the middleware after it had answered, appended an error envelope to the response already sent. Once the middleware returns, `Response.Status()`, `Size()` and `Committed()` now report what it wrote, the access record carries it, and a later error is logged as `credo: error after response committed`. A connection the middleware hijacks is reported by `Response.Hijacked()`: an error returned afterwards is logged as `credo: error after response hijacked` instead of being written to that connection, a write that under `UseCompress` ended in `credo: response compression failed` and an aborted handler. The body of a response the middleware wrote is still the middleware's own; it does not pass the error pipeline. The adapter allocates one small writer per request for this ([middleware spec](docs/specs/middleware.md#stdlib-adapter)).
- **errors:** the internal cause of a client error is logged, at debug level. The `BindError.Internal` godoc, the error-handling guide and the CSRF documents said that the cause attached to an error — `HTTPError.WithInternal`, the decoder error behind a `BindError`, the reason of a CSRF rejection — "is logged", but below 500 the error pipeline wrote nothing at any level. A 4xx `*HTTPError` or `*BindError` that carries an internal cause now writes one `credo: client error` record at Debug with the status and the cause; nothing is added at the default level, and client errors without such a cause (a fault provider, an `HTTPStatus()` error, validation errors) still write nothing ([error-handling guide](docs/guides/error-handling.md)).
- **di:** `Finalize` reports validation errors in registration order. The container walked its registration map, so the same broken wiring listed its missing dependencies in a different order on every run, and with more than one dependency cycle it was random which one was reported and at which member its text began. The report now follows registration order and reads the same on every run ([container spec](docs/specs/container.md)).
- **testutil:** `NewApp` with `WithConfig` values loads only those values. Its godoc promises that a test App never loads configuration from disk, but the document built from `WithConfig` went through the loader with its default sources on: a `.env` file in the test's working directory and `CREDO_*` variables in the environment were merged on top of the test's values, and a `CREDO_ENV_FILE` naming a missing file failed the test. The loader now runs with `config.WithoutDotenv()` and `config.WithoutProcessEnv()`, so a test behaves the same in a developer's shell and in CI. A test that relied on the environment reaching its App sets the value with `WithConfig` instead. `NewApp` without `WithConfig` is unchanged.

### Documentation

- `CONTRIBUTING.md` no longer says that the root package has zero external dependencies. Its own imports are the standard library and in-module packages; through `config` and `internal/i18n` it links three modules — `go.yaml.in/yaml/v3`, `github.com/go-viper/mapstructure/v2` and `golang.org/x/text` — which is what an application importing `github.com/credo-go/credo` alone builds in. An architecture test now fails when that set changes without its allowlist changing in the same commit.
- The `StatusHandler` godoc, the router spec and ADR-007 state what the code does: a custom status handler is consulted for 404 (no route matches) and 405 (the path matches, the method does not) only. The documents promised handlers for "404, 405, 500" and "other status codes"; a handler registered for another code is accepted and never called, and an error a route handler returns — `credo.ErrNotFound` included — goes through the central error pipeline, not through the custom 404 handler ([router spec](docs/specs/router.md#statushandler-system-goyave-inspired)).
- The v0.21.0 notes on the static-file fix are corrected, in the CHANGELOG entry and in the in-repository release notes. They said that `/static/%252e%252e/secret` answers 404; the request reaches the literal path `%2e%2e/secret`, so it serves that file when it exists and answers 404 when it does not — and the listed outcomes are those with SPA fallback disabled. They also said that "no path ever escaped the served directory", which claims more than the fix shows: the second decode did not bypass the lexical traversal checks, while protection against symlink escape depends on the filesystem passed to `app.Static` — `os.DirFS` does not provide it, `os.Root.FS()` or `credo.DirFS` does ([static-files guide](docs/guides/static-files.md#osroot-production-symlink-safe)). The behavior shipped in v0.21.0 is unchanged.

## [0.21.0] - 2026-09-20

**Restart backoff and startup features.** Continuous workers back off between restarts, the managed start line lists the built-in HTTP features in effect, and static files whose names contain `%` are served again. One change compiles unchanged but behaves differently — check it before upgrading:

> **BREAKING (behavior): continuous worker restarts back off.** Every restart used to wait the fixed restart delay (3 s by default), so a worker whose dependency stayed down restarted about 28,800 times a day. The first restart still waits the restart delay; repeated failures now wait longer, with jitter, up to a one-minute cap — about 1,920 restarts a day. A worker with `WithMaxRestarts(N)` therefore reaches `failed`, and a `FailWhenFailed` readiness check drops, later than before: roughly 48–93 s of waiting for N = 5 instead of 15 s. The same value in `WithRestartDelay` and `WithMaxRestartDelay` keeps a fixed delay.

| v0.20.x | v0.21.0 |
| --- | --- |
| every continuous restart waits the fixed restart delay (3 s by default) | the first restart waits the restart delay; repeated failures back off with jitter up to `DefaultMaxRestartDelay` (1 min) or `worker.max_restart_delay`; a run that lasted at least the cap resets the sequence |
| `WithMaxRestarts(N)` reaches `failed` after N fixed waits (15 s for N = 5) | the waits back off, so `failed` and a `FailWhenFailed` readiness drop come later (roughly 48–93 s for N = 5) |

The [pre-v1 migration guide](docs/guides/pre-v1-migration.md#workers) carries the same rows.

### Added

- **worker:** `worker.WithMaxRestartDelay(d)` and `worker.DefaultMaxRestartDelay` (1 minute) set the cap of the restart backoff for a continuous worker, and the `worker.max_restart_delay` configuration key sets it for the pool. An omitted option takes the pool value, then the default, raised to the worker's restart delay when that is longer; an explicit zero skips the pool value and selects `max(DefaultMaxRestartDelay, restart delay)`; an explicit positive cap below the restart delay, a negative value, or the option on a scheduled worker is a registration error ([worker spec](docs/specs/worker.md#restart-backoff)).
- **worker:** `Config.MaxRestartDelay` (`max_restart_delay` in JSON) reports the effective cap; it is zero for scheduled workers. The continuous `worker run failed` line carries `next_restart_in`, the selected wait, when a restart is planned — not when the failure exhausted `WithMaxRestarts` and not when shutdown was already observed.
- **lifecycle:** the managed start line, `credo: server started`, carries a `features` attribute listing the built-in HTTP features in effect, in a fixed display order: `recover`, `request_id`, `access_log`, `decompress`, `compress`, `i18n`, `error_renderer`, `success_renderer`, `health`. The list comes from the App's effective state after preparation, not from registration calls: a `UseI18n` whose conventional discovery found no catalogs is not listed, and neither is a `UseHealth` with both probes disabled. A default App reports `["recover"]`; with every feature off the value is an empty array, never `null`. The summary adds no Warn for features that are off. Only `Run`, `RunContext` and `ServeContext` write the line. This makes the v0.19.0 switch of RequestID and AccessLog to default-off visible at startup ([HTTP features spec](docs/specs/http-features.md#startup-visibility)).

### Changed

- **BREAKING (behavior): continuous worker restarts back off** — see the note above. After a failed run for which a restart is planned, the wait is drawn uniformly from `[max(base, ceiling/2), ceiling]`, where `ceiling = min(base × 2^(k−1), cap)` for the k-th failure in a row. `base` is the effective restart delay (`WithRestartDelay` → `worker.restart_delay` → `DefaultRestartDelay`) and the first wait is exactly `base`; the cap is `WithMaxRestartDelay` → `worker.max_restart_delay` → `DefaultMaxRestartDelay`. A run that lasted at least the cap resets the sequence but never `Restarts` or the `WithMaxRestarts` budget. Scheduled workers are unchanged ([ADR-023](docs/adr/023-worker-system.md#restart-backoff)).

### Fixed

- **static:** `app.Static` decodes the requested path once, as the router does for every parameter, instead of decoding the already-decoded capture a second time. Files whose names contain `%` are served again (`/static/100%25.txt` answered 400 and now serves `100%.txt`; the matching `Browse` link was broken the same way), and a double-encoded request reaches the file it names: `/static/a%252Fb.txt` serves a file literally named `a%2Fb.txt` — or answers 404 when there is none — instead of serving `a/b.txt`. `/static/%252e%252e/secret` reaches the literal path `%2e%2e/secret` — 404 when there is no such file, the case the static-files guide lists — instead of answering 400. These outcomes are those with SPA fallback disabled. Sanitization is unchanged: null bytes, backslashes and explicit `..` segments are still rejected with 400, and the second decode did not bypass these lexical traversal checks. Protection against symlink escape depends on the supplied filesystem: `os.DirFS` does not provide it; `os.Root.FS()` or `credo.DirFS` does. The gap dates from v0.19.0, when route parameters started to be decoded by the router.

### Documentation

- The routing guide warns that route parameters are not file names: a decoded value can contain `/` or `..` (`/files/..%2F..%2Fetc` gives `{name}` the value `../../etc`), so a handler that opens files confines the access with `os.Root` (or the `fs.FS` from `credo.DirFS`); `filepath.Join` is not a check, `filepath.IsLocal` is lexical only, and a regex constraint narrows the format but does not confine file access. The router spec states the boundary, and the static-files and pre-v1 migration guides link to it. The guide's canonical-form sentence is corrected: escapes of all RFC 3986 reserved characters and of `%` are kept, not only the encoded slash.
- The worker guide, worker spec and ADR-023 state that cron schedules have no per-worker time zone selection: the process's local zone applies, with platform-accurate advice (`TZ` on Unix, `time/tzdata` for images without zoneinfo, the OS setting on Windows), and `@every` is not a substitute for a calendar rule.
- ADR-023 records the restart backoff decision ([Restart backoff](docs/adr/023-worker-system.md#restart-backoff)) and ADR-010 the startup summary ([Startup visibility of effective features](docs/adr/010-middleware-architecture.md#startup-visibility-of-effective-features)). The worker guide gains a Restart Backoff section with the waits under the defaults, the recovery trade-off and the fixed-delay recipe, and the lifecycle spec documents the startup record.

## [0.20.1] - 2026-09-19

### Fixed

- **worker:** an error that joins the shutdown cancellation with another error is no longer classified as a graceful stop. `errors.Join(ctx.Err(), flushErr)` — a final write that failed while the application was stopping — used to end the worker as `stopped` with no failure line, no counter change and an empty `LastError`, because one branch of the joined error matched `context.Canceled`. A return value is now a graceful stop only when it is nil or nothing but a context error: every branch of its unwrap/join tree must end in `context.Canceled` or `context.DeadlineExceeded`. A single wrap chain (`fmt.Errorf("query: %w", ctx.Err())`, a `*url.Error` around a cancelled dial) is still graceful; a joined error — `errors.Join`, or `fmt.Errorf` with several `%w` verbs — that carries any other error is a failure, recorded and logged with its full text. The gap predates v0.20.0.

### Documentation

- The v0.20.0 migration tables (this file, the pre-v1 migration guide and the release notes) gain the row they were missing: the `restart` attribute of the continuous `worker run failed` log line is now `restarts` and counts started restarts rather than failed runs.
- The worker guide states that a run timeout and a shutdown are told apart by which came first: a timeout that fired before shutdown stays a timed-out failure, nil return included.

## [0.20.0] - 2026-09-19

**Worker contract.** The `worker` package gets its pre-v1 contract ([ADR-023](docs/adr/023-worker-system.md), [worker spec](docs/specs/worker.md)). The release is breaking, and one change compiles unchanged but behaves differently — check it before upgrading:

> **BREAKING (behavior): a continuous worker whose `Run` returns nil while the application is running is restarted.** It used to stop silently and permanently. The early return is now a failure: logged at Error as `worker run failed` with `unexpected_exit=true` and `LastError` = `worker: Run returned nil before shutdown; a continuous worker must run until its context is cancelled`, restarted after the restart delay (3 s by default) — indefinitely unless `WithMaxRestarts` is set — and marked failed once a positive limit is exhausted, which `ReadinessPolicy.FailWhenFailed` now observes. Move finite work to `app.OnStart`, or end `Run` with `<-ctx.Done()` after the work. A nil return after the context is cancelled remains a graceful stop.

### Added

- `worker.RegisterProvided[T Worker](app, name, opts...) error` and `worker.MustRegisterProvided[T]` register a worker the DI container provides as `T`. `T` is resolved once when the pool starts (the `OnStart` phase, after the implicit `Finalize`, before the server accepts traffic), so the call may precede or follow `app.Provide[T]`, and `T` may be an interface bound with `app.Alias`. Start is all-or-nothing: a missing provider, a constructor error or panic, or a nil result fails startup with the joined errors, each naming the worker and the type, and no worker runs. User constructors run outside the pool lock, and a `Shutdown` that arrives during resolution wins.
- `worker.WithRunTimeout(d)` bounds every run of a scheduled worker, including the `WithStartImmediately` startup run, by cancelling the run context with the cause `worker.ErrRunTimeout`. A run cut short by the timeout is a failure whatever `Run` returns — recorded as `worker: run timed out after <d>[: <error>]`, logged with `timed_out=true`, counted toward `WithMaxConsecutiveFailures` — so it can never stamp `LastSuccess` or satisfy `RequireFirstSuccess`. The timeout is cooperative: it never abandons the goroutine, and at most one run per worker is active. Zero means no timeout; a negative value, or the option on a continuous worker, is a registration error.
- `worker.Config` — the effective, immutable configuration of a worker (`Schedule`, `StartImmediately`, `RunTimeout`, `MaxConsecutiveFailures`, `MaxRestarts`, `RestartDelay` after option → `worker.restart_delay` config → default resolution, and a copy of the `Readiness` policy), reported as `Info.Config` both before and after the pool starts.
- `worker.Kind` with `KindContinuous` and `KindScheduled`.
- Snake_case JSON tags on `worker.Info`, `worker.Config` and `worker.ReadinessPolicy`; `last_run`, `last_success`, `last_error` and `config.readiness` are omitted while zero, every other field is always present, and durations encode as integer nanoseconds under the response profile.
- Lifecycle log lines: exactly one `worker started` (with `kind`; scheduled workers add `schedule` and `next_run` or `start_immediately=true`) and exactly one `worker stopped` (with `status` and `reason=shutdown|failed`) per worker, whatever path ends it; a Debug `scheduled worker run completed` line with `run_id`, `scheduled_at` and `duration`.
- Compile-checked `worker` package examples for both registration forms.

### Changed

- **BREAKING (Go API): the name is registration identity.** `Worker` has one method, `Run(ctx) error`; `Register(app, name, w, opts...)` and `MustRegister` take the name. `worker.Func` is a function type (`worker.Func(fn)`, in the `http.HandlerFunc` style); a nil `Func` or typed-nil worker is rejected at registration instead of failing each run. Names must be non-empty, unique, and free of surrounding whitespace and control characters; they are no longer trimmed. `WorkerName(ctx)`, every log line, the snapshot and the readiness check `worker:<name>` all report the registered name, including the panic path that used to call the instance's `Name()`.
- **BREAKING (behavior): continuous workers are permanent** — see the note above.
- **BREAKING (behavior): `WithMaxRestarts(N)`, `N > 0`, allows the first run plus N restarts.** It used to mark the worker failed after N failures (N−1 restarts); `WithMaxRestarts(1)` now restarts once. `Info.Restarts` counts restarts that actually started — it advances when the next run is admitted, so a shutdown during the restart delay does not count one. `WithMaxRestarts(0)` stays unlimited.
- **BREAKING (Go API): `Info` reshaped.** `Info{Name, Kind, Config, Status, Restarts, ConsecutiveFailures, LastRun, LastSuccess, LastError}`: `Schedule` moves to `Config.Schedule`, `Kind` is `worker.Kind` (comparisons with string constants still compile), and `Attempts` is split into `Restarts` (continuous) and `ConsecutiveFailures` (scheduled).
- **BREAKING (behavior): run outcomes are classified in one fixed order, and the loop exit is decided afterwards.** Panic → failure; timeout cause → failure; pool stopping with a nil or context-error return → graceful stop; other error → failure; scheduled nil → success; continuous nil while alive → failure. A scheduled `Run` that returns nil once shutdown cancellation has begun is a graceful stop, not a success: `LastSuccess` and `ConsecutiveFailures` keep their values. A graceful stop — at the end of a run, while waiting, or at admission — changes only the status and keeps `LastError`, which now always means "the most recent failed run; a successful scheduled run clears it". A failure during shutdown keeps its diagnostics and ends `Stopped` unless it exhausted the limit.
- **BREAKING (behavior): panics keep their stack out of the error text.** A recovered panic is recorded as `worker: run panicked: <value>`; the stack is the separate `stack` attribute of the failure log line and never reaches `Info.LastError` or the readiness failure text. A panic whose value is a context error during shutdown is a failure, never a graceful stop.
- **BREAKING (behavior): `@every` rejects what it used to rewrite.** A zero, negative or non-whole-second duration is a registration error (`@every duration must be positive, got …`, `@every duration must be a whole number of seconds, got 1.5s`) instead of silently becoming a one-second period; the registered expression is the effective schedule.
- **BREAKING (logs):** `worker stopped during scheduled run` and the path-dependent continuous `worker stopped` are replaced by the single `worker stopped` line; the per-activation `worker tick skipped` Warn is replaced by one `worker ticks skipped` line per resumption (`skipped`, `first_scheduled_at`, `last_scheduled_at`). The continuous `worker run failed` line renames its `restart` attribute to `restarts` and changes what it counts: it used to be the number of failed runs (`1` on the first failure) and is now `Info.Restarts`, the restarts that actually started (`0` on the first failure) — update log queries and alerts that read it. Both failure lines (`worker run failed`, `scheduled worker run failed`) add `run_id` — equal to `worker.RunID(ctx)` inside the run — and `duration`, plus `timed_out`, `unexpected_exit` or `stack` when they apply. The alerting Error lines keep their text.
- A published continuous worker reports `idle` until its first run is admitted; the run-admission commit is the only writer of `running`. Before the pool publishes its runners — including after a failed or pre-empted start — `Pool.Workers()` reports every registered worker as `idle`.
- `App.Resolve` godoc names the three shutdown hooks that must not resolve (`OnPreDrain`, `OnDrain`, `OnShutdown`); `OnStart` hooks may.

### Removed

- **BREAKING (Go API): `worker.Attempt(ctx)`.** A scheduled activation is not a retry of the previous one; use `RunID`/`ScheduledAt` to identify a run and `Info.Restarts`/`Info.ConsecutiveFailures` for counters.
- **BREAKING (Go API): `Worker.Name()`** from the interface (a type that still has the method keeps compiling) and the exported `worker.Definition`, which no API returned; `worker.Config` is its public projection.

### Fixed

- A scheduled worker could start a run with an already cancelled context when the activation timer and shutdown were ready together. Every run — first run, restart, activation and startup run — is now admitted in one step after a cancellation check; when the check observes cancellation, no run starts and neither `LastRun` nor `Restarts` changes.
- A continuous worker that returned nil while the application was alive disappeared without a log line and stayed invisible to readiness.
- Exit logging depended on the path: the recommended `case <-ctx.Done(): return nil` and cancellation during a wait logged nothing.
- A burst of skipped activations no longer writes one Warn line per activation.

### Documentation

- The worker spec graduates from its draft status to the contract form, ADR-023 records the worker system's decisions and rejected alternatives, and the worker guide covers `RegisterProvided`, timeouts, finite background work and the log lines. The pre-v1 migration guide gains a Workers section.
- `CONTRIBUTING.md` describes the `main` → feature branch → pull request → `main` workflow; the stale `dev` integration branch is gone.

## [0.19.0] - 2026-09-06

### Added

- `App.Has[T]() bool` — registration-presence check (direct or alias) that never constructs, adopts or protects; a snapshot, not a reservation.
- `App.AdoptValue[T](validate func(T) error) (T, error)` — the one registration-time read: it reads a pre-built binding, validates it and atomically compare-and-protects that same binding against `Replace`. It never runs a constructor (a constructor binding is rejected with an explanatory error), a failed validation leaves the binding repairable, and a `Replace` or `Finalize` that wins during validation fails the adoption instead of protecting a stale instance. `store.Register` and `worker.Register` adopt a pre-provided Registry/Pool through it.
- `App.ConfigExists(key string) bool` — the `RawConfig.Exists` counterpart of `App.GetConfig`, for registration-time reads that must not resolve.
- DI diagnostics: `credo.ErrDIClosed` (resolution rejected once DI teardown has begun, matched with `errors.Is`), `*credo.DIPanicError{Type, Phase, Value, Stack}` with `DIPanicConstruction`/`DIPanicShutdown`/`DIPanicLateCleanup` (unwraps an error-valued panic), and `*credo.DIShutdownError` — an immutable per-singleton snapshot (`DIShutdownEntry` with `DIShutdownState`, blockers, failure and timing) with `Unwrap() []error`, reachable through `errors.AsType` from the joined `Shutdown` result.
- **Bootstrap teardown.** `App.Shutdown` is accepted in the `building` state: it claims `building → stopping`, freezes HTTP and DI writes without requiring a successful `Finalize`, runs the shared drain with no servers (OnPreDrain, cancellation, OnDrain, DI teardown, OnShutdown) and ends `stopped`. Composition roots can clean up after a later bootstrap failure and `ServeHTTP`-only tests can release DI resources; externally owned servers are still drained by their owners.
- **Lifecycle 503.** A request that reaches `ServeHTTP` after the App stopped — or while stopping with no handler ever prepared — receives the default `service_unavailable` envelope (headers only for HEAD) from a callback-free branch that never prepares, resolves, dispatches, or runs user middleware, status handlers, custom renderers or locale detection.

- **Framework HTTP features with one registration each.** `App.UseRequestID(cfg ...RequestIDConfig)`, `App.UseAccessLog(cfg ...AccessLogConfig)`, `App.UseCompress(cfg ...CompressConfig)` and `App.UseDecompress(cfg ...DecompressConfig)` install request correlation, access logging, response compression and request-body decompression; the config types (`RequestIDConfig{Header, Generator, Limit}`, `AccessLogConfig{Logger, MinLevel, Skipper, ResultFilter}`, `CompressConfig{Skipper, Level, Types}`, `DecompressConfig{Skipper, MaxBytes}` with `DefaultDecompressMaxBytes`) now live in the root package. Each call takes zero configs for the defaults or one config, succeeds at most once, validates off to the side (a rejected call installs nothing) and panics on misuse — more than one config, a second call, `Level` outside 1–9, negative `MaxBytes`, a typed-nil `MinLevel`, a credential header name (`Authorization`, `Proxy-Authorization`, `Cookie`) as `RequestIDConfig.Header`, or a call after the App prepared to serve or shut down. `Use*` call order never affects request execution order.
- `App.UseErrorRenderer(r)` / `App.UseSuccessRenderer(r)` — single-install renderer registrations; the window stays open after `Finalize`, so a renderer may be a method of a DI-resolved service. A nil renderer, a second call or a late call panics.
- `credo.WithRecoverConfig(RecoverConfig{Logger, DisableStackTrace, StackSize})` customizes the default-on panic recovery; it never re-enables recovery, and `WithoutRecover()` wins regardless of option order.

### Changed

- **BREAKING (Go API): `Resolve` is admitted only after `Finalize`.** Constructors never run during registration; `Resolve`/`ResolveAll` before `Finalize` return a "not finalized" error. A composition root that resolves controllers before `Run` adds an explicit, error-checked `app.Finalize()` after its last DI write — `Run`'s implicit Finalize remains only a safeguard. `Finalize` is DI-only: routes, hooks and renderers stay open until the App prepares to serve, so DI-backed route binding after `Finalize` keeps working.
- **BREAKING (Go API): `Replace`/`MustReplace` return the superseded instance.** `Replace[T](value) (old T, existed bool, err error)` and `MustReplace[T](value) (old T, existed bool)`: on success the container owns the new value and no longer tracks or closes the old one, whose cleanup belongs to the caller. `existed` is true only when an already-created instance was superseded; an unbuilt constructor yields zero/false and is never run just to return it. A superseded `Shutdowner` is logged at Warn. Statement-form calls keep compiling; `if err := app.Replace…` sites become `if _, _, err := …`. Bindings adopted through `AdoptValue` are Replace-protected like `ProvideProtectedValue` ones.
- **BREAKING (behavior): dependency-ordered DI shutdown.** `container.Shutdown` closes consumers before the singletons they were constructed from (constructor parameters, aliases and `BindMany` edges; value bindings included, dependencies hidden inside pre-built values excluded) using a Kahn ready queue with reverse registration order as the tie-break — previously the pass was reverse registration order alone. Each `Shutdowner` gets one sequential attempt bounded by the shared shutdown context through a helper goroutine; a callback that ignores the deadline keeps its dependencies blocked and is reported, never retried and never closed around. A build still in flight blocks its dependencies while independent entries proceed. Only construction that completes after the shutdown context ended gets one separate fixed five-second best-effort cleanup attempt (not configurable). Panics in construction, shutdown and late cleanup are recovered on the invoking goroutine and reported as `DIPanicError`. Failure or incompleteness returns `*DIShutdownError`; full success returns nil with Debug timings.
- **BREAKING (behavior): path parameter names belong to the endpoint.** The radix tree identifies a route by its method and name-stripped shape (`/users/{}`), captures values positionally and lets the matched endpoint name them (adapted from Chi's endpoint-key model). Routes that share a dynamic segment may now name it differently — `GET /customers/{id}` and `GET /customers/{customer_id}/timeline` coexist, and each handler's `RouteParam`/`RouteParams` sees only its own names — so the `credo: radix: conflicting path/regexp/catch-all parameter … must use the same parameter name` registration panic is gone. Duplicate detection stays strict and now spells the collision out: registering the same method on the same shape under another name panics with `credo: duplicate route: GET "/users/{name}" is already registered as "/users/{id}" (parameter names do not distinguish routes)` plus both call sites. Structural conflicts (two regex matchers at one level, mismatched regex tails), automatic HEAD twins, `Mount` preflight, `BuildURI`/`BuildURL` (names from the route's own pattern) and host-pattern matching are unchanged; path matching keeps its allocation profile.
- **BREAKING (wire): route parameters are percent-decoded once and constraints apply to the decoded value.** Matching runs on the canonical form of the wire path (`URL.EscapedPath()` with every escape decoded except those of the RFC 3986 reserved characters and of `%`), so segment boundaries and reserved spellings come from the client while `/caf%C3%A9`, `/caf%c3%a9` and `/%63af%C3%A9` all reach a route registered as `/café`; an encoded unreserved delimiter is the delimiter (`%2D` and `-` spell the same URI, RFC 3986 §2.3) and an encoded reserved character keeps its distinct meaning (`%3B` is not `;`, §2.2: it never meets static `;` text or a `;` delimiter and reaches a mounted app as `%3B`, while a captured `%3B` decodes to `;`); each captured value is decoded exactly once and `RouteParam` reports the decoded form (`%2F` is `/` inside one segment, `%252F` is `%2F`, `%31` is `1` and satisfies `[0-9]+`, `+` stays `+`, `%C3%A7` is `ç`). A regex constraint must match the whole decoded value — it no longer matches a prefix of a segment — and a `{name}` or `{name:regex}` parameter never spans a raw slash, even with a tail byte (`/{name}.json` no longer matches `/a/b.json`; `{name...}` captures the remainder with its slashes and decodes each segment). A parameter candidate that decodes to invalid UTF-8 (`%FF`) yields 400 with the new code `invalid_path_encoding` when no route matches; malformed escapes such as `%zz` are still rejected by net/http. `Context.OriginalPath` reports the wire-form path, `Context.Rewrite` takes a wire-form target (`/files/a%2Fb` reaches the handler as `a/b`) and rejects malformed escapes, and mounted handlers receive the raw remainder (`URL.Path` decoded, `URL.RawPath` when the spellings differ) instead of a decoded path with `RawPath` cleared. Path matching keeps its allocation profile.
- **BREAKING (Go API): `Route.BuildURI` and `Route.BuildURL` validate and escape their values.** Values are decoded parameter values: each path value is checked against its regex constraint and percent-encoded for one segment with `url.PathEscape` (`a/b` becomes `a%2Fb`, `ç` becomes `%C3%A7`, `+` stays `+`), catch-all values keep their slashes and escape each segment, and host values must be one valid label (letters, digits, hyphens and underscores, plus the label's constraint) and are never encoded. An empty value, a constraint failure or an invalid host label returns an error. Callers that pre-escaped values must pass raw values.
- **BREAKING (behavior): terminal construction results.** A constructor runs once and its outcome — value, error or panic — is shared by the first, concurrent and later callers with no retry. A constructor panic surfaces as `*DIPanicError`, so `MustResolve` now panics with that error as its payload instead of the original value. Construction failures are diagnostics only and do not fail `Shutdown`. Once DI teardown begins, `Resolve` returns an error wrapping `ErrDIClosed` even for cached results; instances created by already-admitted builds remain owned and cleaned up by the container.
- **One stored preparation.** Managed serving (`Run`, `RunContext`, `ServeContext`) and direct `ServeHTTP` share a single Finalize → compile → publish result stored once. Managed serving claims `building → starting` before preparing and rolls back to `building` on failure, returning `credo: Run: prepare: …`; the failure is stored and every later serve attempt returns it. Direct `ServeHTTP` prepares on the first request and panics with the stored preparation error (finalize error or compile panic, logged with its stack) on every request while lifecycle admission is open. HTTP registration now freezes at preparation or shutdown admission rather than at compile, and the guard message is `credo: <what> called after app was compiled or shut down`.
- `App.Shutdown` outside `building`/`running` reports `credo: Shutdown: server in state "<state>", expected "building" or "running"`.
- `store.Register` rejects a Registry registered through a constructor with an explanatory error and never invokes it; a ready Registry value is validated and adopted, and a typed-nil one stays repairable with `Replace` before `Finalize`. `worker.Register` reads the optional `worker` config section through `App.ConfigExists`/`App.GetConfig`, and a `*worker.Pool` registered through `Provide` is rejected without running the constructor. Both read at most one health seam at request time, after the implicit `Finalize`.
- Lifecycle hooks (`OnPreDrain`, `OnDrain`, `OnShutdown`) must capture their dependencies at registration time instead of resolving; a `Resolve` while the App is stopping is logged at Debug (`credo: Resolve during drain`) because an in-flight request may still legitimately resolve.
- `testutil.NewApp`'s cleanup now tears down every singleton the test created whether or not the App was run (bootstrap teardown); tests resolve services after `app.Finalize()` or after serving a request.
- The `examples/saas` composition root finalizes before resolving `TenantService`.
- **BREAKING (behavior): a default App enables panic recovery only.** Request IDs and access records are no longer produced by `credo.New()`; enable them with `app.UseRequestID()` and `app.UseAccessLog()`. Neither call enables the other: `Context.RequestID()` returns `""` and access records carry an empty `request_id` until `UseRequestID` is installed. Framework diagnostics (recovery, server errors, lifecycle, health) and application logs are unaffected by the access-log switch.
- **BREAKING (behavior): one request executor runs the framework features around the Global → Group → Route chain.** Request ID → access-log start → decompression → compression writer → user chain → centralized error rendering → recovery → compressor finalization → access-log observation → Context release, in that fixed order. Consequences: the access record is observed after error rendering, recovery and compressor finalization (status is the committed status, `AccessLogEntry.Bytes` counts the post-compression body bytes the transport accepted, `Duration` runs from executor entry through finalization and excludes the result filter and log emission); error envelopes, 404/405 and panic responses are compressed like handler output; decompression runs before Global middleware, so body-reading middleware and binders see the same decoded stream, and its `Skipper` is evaluated once on the original request (no route or user data; a rewrite does not re-evaluate it); a `ResultFilter` panic is logged as a framework error and skips that record; a compressor `Close` failure is logged and aborts started output with `http.ErrAbortHandler` instead of appending a JSON body. Recovery covers every feature callback; with `WithoutRecover` the panic propagates after request cleanup.
- **BREAKING (Go API): `I18nConfig.Detect` is `func(*Context) string` and runs lazily.** Detection happens on the first `Locale`/`T`/`TPlural` or automatic error/field translation of a request and is memoized for that request; requests that never translate do not call the detector, and `UseI18n` installs no middleware. The detector sees the request state at that moment (`ctx.GetUser` is available only if authentication already ran); calling `Locale` or a translation from inside it panics; a detector panic caches the default locale and takes the 500 path. A successful `UseI18n` whose conventional discovery found no catalogs consumes the single registration (a second call panics `credo: App.UseI18n called twice`); load/validation errors still return and leave it retryable.
- `HealthConfig.LogRequests` only matters once `UseAccessLog` is installed; probes stay silent by default either way.
- The `examples/saas` composition root calls `UseRequestID`, `UseAccessLog` and `UseCompress` explicitly.
- **Performance (wire hot paths).** Error bodies encode with a JSON option set joined once in `New` instead of on every error response (`BenchmarkWireJSONOptions/ErrorOptions`: 26.7 ns / 1 alloc → 0.6 ns / 0 allocs). Translation lookups for an already resolved request locale skip Accept-Language parsing and matching through a canonical-string table on the bundle (`BundleTranslate/CanonicalString` 344 ns / 6 allocs → 42 ns / 0 allocs; `UseI18n_T` 1.10 µs / 13 allocs → 0.19 µs / 1 alloc; a two-field validation error 4.14 µs / 50 allocs → 1.53 µs / 13 allocs). Access logging without a `ResultFilter` checks the target logger's level before building the entry (`WireObservability/AccessLog/HandlerFiltered` 136 ns / 1 alloc → 66 ns / 0 allocs); with a filter the entry is always built, so the filter keeps observing every response. Measured with `-count=10` and benchstat; no behaviour changes.
- **Performance (`Response.ReadFrom`).** `Response` implements `io.ReaderFrom`: `Response.Stream` and `io.Copy` into a response no longer allocate a 32 KiB copy buffer per call for a Reader-only source. On an uncommitted response the first buffer's worth of the source always passes through `Response.Write`, so the commit is recorded by `Response` ahead of any later failure in the source; the rest of a larger source is delegated to the underlying writer's own `ReadFrom` when it has one (net/http's HTTP/1.1 writer: pooled buffer, sendfile/splice on a plaintext TCP connection for file and socket sources) and otherwise copied through the pooled buffer (compressing or other wrapping writers, HTTP/2). `Size()` counting, partial-write errors and the hijack refusal are unchanged; nothing is committed before the first byte (a source that fails up front leaves the handler's error to the error pipeline, as with `Write`) and a source that panics after its first bytes leaves the response committed, so recovery logs the panic and never appends an error envelope to the 200 already on the wire, with `Size()` and the access record's byte count covering the delegated part too (the delegated source is wrapped in the `io.LimitedReader` that net's sendfile and splice paths unwrap, so the zero-copy path survives); verified against live HTTP/1.1, TLS and HTTP/2 servers with and without the compression feature. `WireSuccess/Core/StreamReaderOnly` (4 KiB body): 5.36 µs / 32.8 KiB / 3 allocs → 0.21 µs / 24 B / 2 allocs; the wrapped-writer variant 5.10 µs → 0.19 µs.

### Removed

- **BREAKING (Go API): `App.ProvideFactory` and `App.MustProvideFactory`.** The closure factory's dependencies were invisible to `Finalize` validation, cycle detection and dependency-ordered shutdown, and constructors now run only after `Finalize`. Register typed constructors with explicit dependency parameters; capturing `app.Resolve` inside a constructor is unsupported.
- **BREAKING (Go API): converted middleware.** `middleware.Recover`, `middleware.RequestID`, `middleware.AccessLog`, `middleware.Compress`, `middleware.Decompress`, their config types, `middleware.GetRequestID` and `middleware.RequestIDKey`. Recovery is configured with `WithRecoverConfig`; the others are the root `Use*` features above, and handlers read the ID with `ctx.RequestID()`. Per-group/per-route recovery and second route-scoped access loggers have no replacement wrapper: write ordinary middleware, or select records with `MetaAccessLog` and `AccessLogConfig.ResultFilter`.
- **BREAKING (Go API): `WithoutRequestID`, `WithoutAccessLog`, `WithAccessLogLogger`, `WithAccessLogMinLevel`, `WithAccessLogSkipper`, `WithAccessLogResultFilter`.** Optional features are off unless their `Use*` call is made; the four field helpers are the fields of `AccessLogConfig`.
- **BREAKING (Go API): `App.SetErrorRenderer` and `App.SetSuccessRenderer`.** Replaced by the single-install `UseErrorRenderer`/`UseSuccessRenderer`.

### Fixed

- **Compress: bodiless responses with a compressible `Content-Type` aborted the connection.** A 204 or 304 that carried `Content-Type: application/json` started a compressor; closing it wrote the gzip header and trailer, net/http rejected that body and the client saw EOF. A body-forbidding status never starts a compressor now; verified against a real server.
- **Router: static pattern text with non-ASCII or percent-encoded spellings did not match.** `/café/{id}` answered 404 to `/caf%C3%A9/42`, and `/%75sers` never met `/users`. Static text and the request path now meet in one canonical form (see the wire-minor entry above); generation writes static text in its wire spelling (`/caf%C3%A9/42`), trailing-slash redirects spell `Location` for the wire, and a mount below such text hands the child the right remainder.
- **URL generation produced URIs that could not route back.** `BuildURI("a.b")` for `/files/{name}.json` produced `/files/a.b.json`, which matching cuts at the first `.` (404), and an invalid UTF-8 value produced a URI the router answers with 400. Both are generation errors now: a value must be valid UTF-8 and its wire spelling must not show the byte that delimits its parameter in the pattern, checked in the canonical form where matching cuts — a slash-delimited value may contain a slash and a `;`-delimited value a `;` (both escaped by `url.PathEscape`), a `=`-delimited value cannot contain `=`, and a `%` delimiter (`/x/{id}%done`, spelled `%25` on the wire) is matched as that unit and no longer mistaken for the `%` of another escape, so `BuildURI("/")` = `/x/%2F%25done` routes back.
- **DI shutdown could leave a failed build's dependencies blocked.** When a pending constructor failed while another singleton's `Shutdown` was running, the pass could conclude nothing was pending before absorbing the completion, and the dependency stayed `blocked` in the report although the deadline had not expired. The choice of the next singleton, the retirement of failed builds and the pending decision are now one snapshot under the container lock, so a build that completes — successfully or not — at any point before the pass concludes is shut down or retired rather than left `unattempted`.
- **`Shutdown` racing a managed start could be refused with a stale state.** When a start moved from `starting` to `running` between the running and building claims, `Shutdown` reported `server in state "running", expected "building" or "running"` and did nothing. The call now claims again whenever the state it observed is a live one, so a start that completes (or rolls back) while `Shutdown` is deciding is shut down by that same call; only `starting`, `stopping` and `stopped` are refused.

### Documentation

- Promote accepted pre-v1 bootstrap/DI, router parameter and built-in HTTP feature contracts to ADR/spec, with a [migration guide](docs/guides/pre-v1-migration.md) and example migration notes; the accepted design decisions are recorded in [ADR-022](docs/adr/022-bootstrap-and-di-ownership.md), [ADR-007](docs/adr/007-router-and-routing.md) and [ADR-010](docs/adr/010-middleware-architecture.md), and the delivery plan that scheduled the work was deleted once it landed. Every promoted contract ships in this release (see above); the performance follow-ups landed as the two performance entries above, with the benchmark evidence rule in [CONTRIBUTING](CONTRIBUTING.md#performance-changes).

## [0.18.0] - 2026-09-05

### Fixed

- **Workers drain before DI teardown.** `worker.Register` now attaches the pool to `App.OnDrain`, so workers' bounded cleanup after cancellation completes concurrently with the HTTP drain and before any DI singleton's `Shutdown` runs. Previously the pool was stopped only by the container's reverse-registration `Shutdowner` pass, so a resource registered after the pool could be closed while a worker was still flushing. `Pool.Shutdown` is now idempotent with a stable result — nil once every worker has returned, whatever the caller's context state; `ctx.Err()` only while workers are still running — so the later `Shutdowner` pass returns immediately. `Start` is refused after `Shutdown`, and a `Start` racing a direct `Shutdown` is ordered under the pool mutex so no worker goroutine can be launched past a wait that already began.
- **Worker registration window is uniform.** Every `worker.Register` call after `App.Finalize` returns `worker: Register after app.Finalize`; previously only the first registration (the one creating the pool) was rejected and later ones were silently accepted.
- **Reload and shutdown are coordinated.** A `Reload` in flight when `Shutdown` begins now has its participants, subscribers, and `OnReload` hooks cancelled (their context is bound to the caller's context and the application lifecycle), and `Shutdown` waits for the reload to return after the HTTP/`OnDrain` phase and before DI teardown; at the shutdown deadline it reports `credo: shutdown: reload still in flight` and proceeds. Previously a reload callback could keep running against already-closed DI infrastructure and the reload completed without error. A `Reload` whose context is already cancelled (on arrival, or by the time it acquires the slot) returns `ctx.Err()` before loading a candidate or running any callback. A `Reload` queued behind an in-flight one now returns its own `ctx.Err()` if its context ends first and the not-running error (without reloading) if shutdown begins while it waits.
- **`SIGINT`/`SIGTERM` are serviced during a signal-triggered reload.** Under `Run`, reloads now run off the signal loop's goroutine. Previously a long or cancellation-ignoring `OnReload` hook blocked the loop, so a termination signal was neither acted on nor reset until the reload returned — leaving `SIGKILL` as the only way to stop the process. Coalescing is unchanged: at most one reload runs at a time and signals arriving mid-reload produce one follow-up.
- **Worker pool binding is protected.** The pool is published with `ProvideProtectedValue`, so `Replace[*worker.Pool]` is rejected and the pool wired into the lifecycle and readiness seam cannot diverge from the one DI hands out. A `*worker.Pool` provided outside `worker.Register` is refused with an error.

- **BREAKING (Go API):** `ErrorResponse` now nests an `ErrorBody` (`ErrorResponse.Error`) instead of flat `Code`/`Message`/`Details`/`Errors` fields, and `ErrorInfo.Errors` was renamed to `ErrorInfo.Violations`. Custom `ErrorRenderer` implementations reading `info.Errors` must switch to `info.Violations`.
- **BREAKING (wire, RFC 9457 opt-in):** `RFC9457ErrorRenderer`'s validation extension member was renamed from `errors` to `violations` (`ProblemDetails.Violations`), keeping the extension vocabulary consistent with the default envelope. The `type`, `title`, `status`, `detail`, `instance`, `code`, and `details` members are unchanged.

## [0.11.0] - 2026-08-24

### Changed

- **Breaking:** the machine-readable `Code` is now the primary stable identity of `HTTPError`, and `NewHTTPError`'s optional second argument is that code — not a message key: `NewHTTPError(status int, code ...string)`. The constructor is strict: it panics on a status outside `100..999`, on more than one code argument, and on a code that does not match `^[a-z0-9]+(_[a-z0-9]+)*$` (registration-time misuse fails fast; a panic reached at request time is caught by built-in recovery and rendered as a fail-closed generic 500 that publishes none of the invalid fields). A codeless call materializes `Code` from a frozen, committed `statusToCode` table generated once from Go 1.27's `http.StatusText` (62 entries, fixture-locked; unknown status → `http_<status>`) — the table never tracks the live standard library, so codes cannot silently rename. `WithCode` and message-key last-dot-segment code derivation are removed; message keys become optional presentation attached with the new copy-on-write `WithMessageKey`. The positional argument keeps its Go type while changing meaning, so old keyed calls may compile — the strict grammar turns dotted keys and literal messages into loud panics under test; see the migration table in [docs/releases/v0.11.0.md](docs/releases/v0.11.0.md). See [ADR-009](docs/adr/009-handler-and-error-handling.md).
- **Breaking:** sentinel field state changed: sentinels now materialize their code and carry no stored key — `ErrNotFound.Code == "not_found"`, `ErrNotFound.MessageKey == ""`. `ErrorInfo.MessageKey` continues to carry the effective classification key (now `errors.<code>`) to renderers. Default locale keys for built-in HTTP titles move from `http.*` to `errors.*` (`http.not_found` → `errors.not_found`); `http.validation_failed` and `http.request_timeout` are kept because framework code references them as explicit keys. Bundles using the old defaults must rename.
- **Breaking:** `HTTPError.Error()` now prints machine identity first — `credo: http error: status=…, code=…, key=…, internal=…` — omitting empty segments. String assertions on the old format break.
- Classification is fail-closed at the boundary: a directly constructed `HTTPError` struct with an out-of-domain status or grammar-violating code, and a legacy `HTTPStatus() int` provider returning a value outside `100..999`, are classified as a generic 500 and none of the invalid fields reach the wire.

### Added

- `HTTPError.WithMessageKey(key string)` — copy-on-write presentation-key builder, the successor to passing a key positionally. Title resolution is now two explicit chains: an explicit `MessageKey` resolves i18n bundle → built-in English default → the key itself as literal text; without a key the title resolves bundle(`errors.<code>`) → `http.StatusText` → `"HTTP <status>"`.
- Every classified error now carries a `code` member on the wire: previously code-less bodies (sentinels without derivable keys, unknown statuses, generic 500s) gain the frozen default — a strictly additive RFC 7807 change. Errors whose code was previously derived from a built-in key keep byte-identical bodies.
- An informational drift canary logs (never fails) when Go's `http.StatusText` diverges from the frozen table, so deliberate table updates remain a reviewed decision.

## [0.10.0] - 2026-08-24

### Changed

- **Breaking:** `credo.SuccessRenderer` is now shape-only, completing the symmetry with v0.9.0's `ErrorRenderer`: `func(ctx *Context, info RenderInfo) any`. The renderer receives `RenderInfo{Status, Data, MessageKey, Meta}` and returns the body; the framework owns the write — status, the application JSON profile, and the bodiless-status rule apply centrally. Returning nil writes `Data` plain (selective enveloping); a renderer that commits the response itself keeps full control and its return value is ignored; a renderer panic is caught by built-in recovery like any handler panic. `Context.Render` gains variadic `RenderOption`s — `credo.RenderMessageKey(key)` and `credo.RenderMeta(v)` — carrying the two side channels every envelope needs (resolved message, pagination-style metadata); with no renderer installed they are silently dropped. Migration: change the signature from `func(c, status, data) error` to `func(c, info) any`, build the envelope and `return` it instead of writing; a renderer that wrote its own non-JSON response keeps the write and returns nil only after committing. See [ADR-009](docs/adr/009-handler-and-error-handling.md).
- **Breaking:** `HTTPError.Code` (the HTTP status, an int) is renamed to `HTTPError.Status`. The field's type changes with its name, so nothing breaks silently — code reading `.Code` as an int fails to compile; replace it with `.Status` (or the unchanged `HTTPStatus()` method). `NewHTTPError`'s signature and the sentinels are unaffected. The rename frees the `Code` name for the machine-readable string code below.

### Added

- First-class machine-readable error codes and structured details on the RFC 7807 wire, as extension members: `HTTPError` gains `Code string` and `Details any` with copy-on-write `WithCode(string)` / `WithDetails(any)` builders, and `ProblemDetails` gains matching `code` / `details` members (`omitempty`). When `Code` is unset it is derived from the message key — the segment after the last dot (`"user.email_exists"` → `"email_exists"`, built-in `http.not_found` → `"not_found"`); a dotless literal message yields no code. Validation failures carry `"code": "validation_failed"`, bind failures the decode reason (`"syntax"`, `"type_mismatch"`, …) as the top-level code. Renderers read both off `info.Problem`; `ErrorInfo` gains no duplicate fields. See [ADR-009](docs/adr/009-handler-and-error-handling.md).

- Debug-mode envelope-bypass diagnostic: with a `SuccessRenderer` installed and debug mode on, a handler that writes a body-carrying JSON response through the raw `Response.JSON` helper instead of `Context.Render` triggers `WARN "credo: response bypassed the success envelope"` with the route pattern and name. Deliberate raw endpoints (webhooks, third-party shapes) silence it with the new `credo.MetaRawResponse` route meta (group-inheritable, route overrides group). Framework-internal writes (`Render`, the error pipeline) and the non-JSON writers (`Text`, `Blob`, `XML`, streaming) never trigger it; non-debug runs pay nothing.

### Fixed

- Body-writing response helpers (`Response.JSON`, `Text`, `HTML`, `XML`, `Blob`, `Stream`) now treat body-forbidding status codes — 1xx, 204 No Content, 304 Not Modified — as status-only: the body and the Content-Type header are skipped and the call returns nil (`Stream`'s reader is never read). Previously `JSON(204, body)` failed inside net/http after the header was committed, surfacing as a spurious `"credo: error after response committed"` warning and a misleading `Content-Type: application/json` on a bodiless response; handlers no longer need to special-case 204 themselves. Handler-set headers such as ETag and Cache-Control on a 304 are preserved.

See [ADR-006](docs/adr/006-application-lifecycle.md).
- **Access logging** — `WithAccessLogSkipper(func(*credo.Context) bool)` installs a pre-dispatch predicate that excludes matching requests from the built-in access log without disabling it. The new `credo.MetaAccessLog` route meta (`route.SetMeta(credo.MetaAccessLog, false)`) silences a single route or, by `LookupMeta` inheritance, a whole group; a route-level value overrides its group's, and `middleware.AccessLog` honours the same meta. See [ADR-010](docs/adr/010-middleware-architecture.md).
- **Health checks** — `HealthConfig.LogRequests` (default `false`) keeps `/health` and `/ready` probe requests out of the access log; set it to `true` to log them. Because the meta is applied per route, `true` re-enables logging even under a group that silenced access logging. See [ADR-016](docs/adr/016-health-checks.md).
- **TLS** — `WithTLSFiles(certFile, keyFile)` and `WithTLSConfig(*tls.Config)` configure HTTPS, as do the `server.tls.cert_file` / `server.tls.key_file` config keys. Sources resolve by precedence (`WithTLSConfig` > `WithTLSFiles` > `server.tls.*` > plaintext; whole-source override, never a conflict error). `Run` and `RunContext` serve HTTPS automatically when TLS is configured; the certificate is validated once at preflight, so a bad cert — or an explicitly-set-but-empty/nil source (`WithTLSConfig(nil)`, `WithTLSFiles` with an empty path) — fails fast and rolls the state back to `building` rather than silently downgrading to a lower-precedence source or plaintext. `ServeContext` is TLS-exempt — wrap the listener with `tls.NewListener` for HTTPS. See [ADR-006](docs/adr/006-application-lifecycle.md).
- **HTTP→HTTPS redirect** — `WithHTTPRedirect(addr)` runs a second, plaintext listener that permanently redirects every request to its HTTPS equivalent (301 for GET/HEAD, 308 for other methods). It requires TLS (preflight fails fast otherwise) and binds, serves, and drains with the main server — closing before the main server on drain, and tearing the app down if the redirect listener fails at runtime, so a requested redirect never silently dies. `ServeContext` ignores it. See [ADR-006](docs/adr/006-application-lifecycle.md).
- **Configuration** — typed-snapshot getters over `Unmarshal`: `config.(*Config).Get[T](key) (T, error)` plus `MustGet[T]`, and `(*credo.App).GetConfig[T](key) (T, error)` plus `MustGetConfig[T]`. Each decodes a config section into a value of `T` in one call (the `Must` forms panic, matching the `MustProvide`/`MustResolve` family); there is deliberately no `MustLoad`. They are composition-root sugar — a handler has no `App` accessor, so typed config still flows to services via DI. See [ADR-005](docs/adr/005-configuration-architecture.md).
- **Data access (`store/sqldb`)** — typed terminal methods on `*SelectQuery` (Go 1.27 concrete-type generic methods): `One[T](ctx) (T, error)` and `All[T](ctx) ([]T, error)` return the queried type directly instead of scanning into a caller-supplied destination. `T` drives both the table and the destination, so the query is built model-less (`db.Select().Where(...).One[User](ctx)`). `One` applies `LIMIT 1` (first row; multiple matches are not an error — add `OrderExpr` for determinism) and maps no-row to `store.ErrNotFound`; `All` returns a non-nil empty slice with a nil error when nothing matches. Both use internal execution snapshots and inject the ambient transaction exactly like `Scan`. See [ADR-015](docs/adr/015-data-access.md).
- **Data access (`store/sqldb`)** — `(*SelectQuery).Page[T](ctx, req) (*pagination.Page[T], error)`, a typed pagination terminal completing the `One`/`All`/`Page` family. It runs COUNT + a LIMIT/OFFSET SELECT and returns a ready `*pagination.Page[T]`; `T` drives the table, so the query is built model-less (`db.Select().Where(...).OrderExpr(...).Page[User](ctx, req)`). `BindQuery` still applies `PageRequest.Validate`'s forgiving defaults/clamp policy, while the terminal copies the request and independently enforces strict execution invariants before COUNT. Nil, non-positive, native-offset-overflow, and Bun v1.2.18 signed-int32 LIMIT/OFFSET violations wrap `pagination.ErrInvalidPageRequest`; the caller's request is never mutated and valid custom `PerPage` values above 50 remain honoured. On zero rows SELECT is skipped and the page preserves the snapshot's page/per-page with a non-nil empty slice. COUNT and SELECT use internal execution snapshots and both join the ambient transaction, but a normal Read Committed transaction does not make the two statements share a snapshot. See [ADR-015](docs/adr/015-data-access.md).
- **Data access pagination count contract** — `Page.Total` is the cardinality of the complete logical projection before ordering and the page window: an ungrouped aggregate normally contributes one result row, `Distinct` counts selected projection tuples, `Group` counts groups, and `Group` + `Having` counts the groups left after `Having`. Credo now counts a universal outer `_credo_count_source` derived table after stripping root ORDER/LIMIT/OFFSET/FOR; its behavior is pinned by conformance tests. `Count` and `Page` reject standalone `Having` and direct `UNION`/`INTERSECT`/`EXCEPT` shapes with `sqldb.ErrUnsupportedCountQuery` before database I/O; restructure those shapes behind an outer derived table/CTE and compose an explicit count query, data query, and `pagination.NewPage`. The logical projection is evaluated by the count source; expensive, volatile, or set-returning projections should use that explicit custom composition. A first-class custom-count strategy is deferred until two real consumers need the same abstraction. `Page` retains exact-total metadata; total-free offset windows reserve `Slice[T]`, while keyset pagination reserves the distinct `CursorPage[T]`, rather than overloading `Page` with unknown totals. Logical COUNT also runs the model SELECT hook lifecycle on its private source (`BeforeSelect`, `BeforeAppendModel`, and successful-query `AfterSelect`), so hook-added filters/projections contribute to `Total`; a `Page` that reaches its data SELECT runs the lifecycle once for COUNT and once for SELECT. Count does not scan or mutate a bound model, and nondeterministic hooks/volatile SQL can still differ across the two executions regardless of isolation. MySQL is now the oracle for its unique derived-column-name rule: wildcard and implicit/unaliased projections pass when the server derives unique names, while logical-count `ER_DUP_FIELDNAME` (1060) is wrapped with `ErrUnsupportedCountQuery` after I/O and retains the driver cause. Raw and other non-count 1060 errors remain unchanged. Real tests cover normal mode and `NO_BACKSLASH_ESCAPES`. The outer count query preserves `QueryEvent.Model` for observability while soft-delete policy remains solely on the inner source.
- **Pagination snapshot guidance** — `Page` does not start an implicit transaction. PostgreSQL Read Committed can observe different statement snapshots; an outer read-only Repeatable Read transaction is the documented PostgreSQL/MySQL path when one snapshot is required. MySQL's guarantee is limited to InnoDB ordinary nonlocking reads and configured isolation. SQLite uses the first-read snapshot of an explicit transaction; WAL permits a concurrent writer while rollback-journal mode may serialize it. The pinned modernc SQLite driver does not reliably enforce `sql.TxOptions.Isolation` or `ReadOnly`, so SQLite callers use plain `InTx`; driver-capability validation is deferred as a fail-loud follow-up.
- **Data access (`store`)** — typed transaction scopes: `NewTxScope[T]()` fixes the transaction contract once, and `scope.WithTx`, `GetTx`, `RequireTx`, and `Conn` all use the same `T`. This prevents a concrete transaction from being stored and then silently missed through an interface-typed read. `WithTx` rejects nil and typed-nil transaction handles; `RequireTx` and its free-function counterpart return the new `store.ErrTxMissing` instead of falling back. Distinct scopes isolate multiple logical connections with the same transaction type. See [ADR-015](docs/adr/015-data-access.md).
- **Data access (`store/sqldb`)** — `DB.Conn(ctx) bun.IDB` exposes the active per-DB transaction, or the base DB outside a transaction, for advanced native Bun operations; `DB.RequireTx(ctx)` returns `store.ErrTxMissing` rather than falling back. Native executions participate in the selected transaction but still bypass Credo error mapping. See [ADR-015](docs/adr/015-data-access.md).
- **Data access (`store/sqldb`)** — `WithTxCleanupTimeout(d)` configures how long Credo waits for each nested savepoint creation/release/rollback and fail-safe ambient abort (default five seconds, positive values only). Callback duration is unaffected. Uncertain nested operations synchronously mark shared state rollback-only; an outer callback that swallows the inner error returns the new `ErrTxRollbackOnly` rather than committing.
- **Pagination** — `(*pagination.Page[T]).Map[U](fn func(T) U) *Page[U]` (a Go 1.27 generic method) returns a new page with each record transformed by `fn`, carrying the pagination metadata (`Total`, `Page`, `PerPage`, `TotalPages`) over unchanged. It is the canonical model→DTO step: build `Page[Model]` from `SelectQuery.Page` and `Map` it to `Page[DTO]`, so an intermediate `Page[Model]` no longer means hand-copying metadata. `fn` must be pure — a nil `fn` panics, even for an empty page; for a fallible conversion, map in the service and build with `NewPage`. See the [pagination spec](docs/specs/pagination.md).

### Changed

- **Data access migration cleanup** — `DB.Migrate` now attempts Unlock with a fresh cancellation-detached five-second budget and bounds caller wait even when a driver ignores context. Migration and unlock errors remain joined. An unlock timeout is explicitly an uncertain outcome and is not automatically retried. Production guidance now prefers one deadline-bounded pre-deploy job for multi-replica releases; `app.OnStart(db.Migrate)` remains the dev/single-replica convenience, and mark-on-success is documented as at-least-once bookkeeping that still requires transactional or replay-safe migrations.
- **BREAKING — generated `sqldb` DSNs now fail loud on ambiguous or invalid connection configuration.** Driver-family inference uses exact aliases instead of substring matches; generated PostgreSQL/MySQL DSNs require a non-zero port and serialize IPv6 hosts correctly; positive fractional PostgreSQL connect timeouts round up to one-second units. Conflicting structured fields/driver options and explicit nil `WithDialect` or `WithConnector` values now return secret-safe startup errors, as do known driver/dialect family mismatches. Raw `Config.DSN` and non-nil custom connectors remain the driver-native escape hatches.
- **BREAKING — `sqldb.Config.MaxIdle` is now `*int`.** `nil` makes Credo leave the idle setter untouched (the effective stdlib default remains subject to `MaxOpen`), `new(0)` explicitly disables idle retention, and a positive value is applied exactly. Migrate `MaxIdle: 10` to `MaxIdle: new(10)`. With finite `MaxOpen`, an explicit `MaxIdle > MaxOpen` now fails `Open` instead of being silently clamped. `MaxOpen=0` remains unlimited; Credo does not impose a workload-independent finite default. `MaxIdleTime=0` and `MaxLifetime=0` disable their respective expiry policies. The added `MaxIdleTime` field also changes positional `sqldb.Config` literals: migrate them to keyed fields, which is the supported form for this evolving beta config struct.
- **Cursor/keyset pagination design gate** — the reserved first result is a forward-only `CursorPage[T]`; future total-free offset pagination keeps the separate working name `Slice[T]` pending its own design gate. Cursor execution owns a stable non-null keyset with an explicit unique tie-breaker, uses `per_page + 1`, performs no COUNT, and requires an explicit scope-bound HMAC keyring for public HTTP tokens. No cursor symbols ship yet: implementation remains gated on a concrete consumer, a fail-loud Bun hook boundary for terminal-owned order/window state, invalid-argument transport mapping, canonical wire vectors, and real PostgreSQL/MySQL/SQLite conformance. See [ADR-015](docs/adr/015-data-access.md).
- **BREAKING — `SelectQuery.Count` now counts complete logical projection rows.** It wraps the projection as `_credo_count_source` after removing root ORDER/LIMIT/OFFSET/FOR, so ungrouped aggregate, distinct, and grouped queries return their result-row cardinality instead of Bun's replacement-projection count. The projection can now be evaluated during COUNT. Standalone `Having` and direct compound roots, which previously could error or return a misleading count, fail before I/O with `ErrUnsupportedCountQuery`; use an explicit derived-table count/data composition for those or for expensive/volatile projections. MySQL now decides derived-source output validity at execution: logical-count 1060 is wrapped with `ErrUnsupportedCountQuery` and preserves its cause, while former wildcard/implicit-expression false positives and non-count 1060 are no longer narrowed by a local parser.
- **BREAKING — `pagination.PageRequest.Offset` now returns `(int, error)`.** Migrate `offset := req.Offset()` to `offset, err := req.Offset()` and handle `pagination.ErrInvalidPageRequest` with `errors.Is`. Unlike `Normalize`/`Validate`, `Offset` is strict and non-mutating: it rejects non-positive values and native `int` multiplication overflow instead of silently producing an unsafe offset. `SelectQuery.Page` adds the narrower Bun v1.2.18 signed-int32 LIMIT/OFFSET check and rejects every invalid request before COUNT; it does not clamp valid custom page sizes.
- **Data access (`store/sqldb`)** — curated `SelectQuery.Limit` and `Offset` now reject values outside Bun v1.2.18's signed-int32 storage range with `sqldb.ErrInvalidLimitOffset`; the builder records the error and its terminal returns before database execution instead of allowing an `int`→`int32` narrowing. Values inside the range, including zero and negative values, retain Bun semantics. Raw Bun reached through `Apply` or `Unwrap` remains an explicit escape hatch and is not covered by the curated-method guard.
- **BREAKING — store registration ownership and publication are now explicit.** `WithLifecycle(lc)` no longer succeeds with a warning when the registered value cannot be shut down by DI; pair it with `WithCallerOwnedLifecycle()` and arrange shutdown yourself, or make the registered value implement the complete `store.Lifecycle` contract. A value that already implements `Lifecycle` may no longer supply a second lifecycle or caller-owned opt-out, and a Shutdowner-only value cannot split Shutdown from Ping/Health. Ownership transfers only when `Register` succeeds; every failure remains caller-owned. For a framework-owned value DI is the sole framework shutdown owner: a teardown makes at most one attempt if its live deadline reaches the registration, and may make none if the deadline expires first. Migrate embedded wrappers by removing their redundant `WithLifecycle` option. Migrate named-field wrappers by delegating all Lifecycle methods (framework-owned) or adding the explicit caller-owned option and an `OnShutdown` hook.
- **BREAKING — store names, types, and declared resource identities are unique.** Explicit empty, padded, control-character, and reserved `credo.` names are rejected rather than normalized; omitted names use the pointer-unwrapped, package-qualified named type and unnamed types require `WithName`. Register privately reserves name, DI type, and resource identity, keeps pending entries invisible, and commits Registry visibility only after Ping and authoritative DI publication both succeed. Identity defaults to the top-level Lifecycle value itself; pointer-backed implementations are recommended. A semantic/named wrapper must implement `ResourceIdentity() any` explicitly and return its underlying pointer; Credo does not scan struct fields. Tokens must be non-nil, comparable, reflexively equal, and stable; non-comparable values and NaN-like tokens fail before Ping. Within the `store.Register` ledger, a repeated identity under another type or ownership mode is rejected. Migrate a second interface view to `app.Alias[I, T]()` instead of re-registering it. Raw `app.Provide`, `app.ProvideFactory`, `app.ProvideValue`, `app.ProvideProtectedValue`, or `app.Replace` calls are outside this ledger and must not publish the same lifecycle again; a caller-owned handle must not also be registered in DI as a Shutdowner. Concurrent external DI mutation can still win after the point-in-time preflight; final publication remains authoritative.
- **BREAKING — successful store and Registry DI bindings are protected.** `store.Register[R]` publishes `R` with `ProvideProtectedValue`, and the Registry binding is created protected or, when supplied by the composition root, resolved and validated before its pointer is atomically compare-and-protected against `Replace`. A raced replacement, invalid nil, or failing Registry binding remains unprotected and replaceable before Finalize so composition can repair it and retry. After adoption, later `app.Replace[R]` and `app.Replace[*store.Registry]` calls return an error instead of detaching DI from lifecycle/readiness state. Install test/application substitutes before registration or register the intended lifecycle value on a fresh App.
- **Data access health compatibility** — `store.Health` adds a JSON-excluded typed `Cause error` field, and `store/sqldb.Health` now places ping failures there instead of copying their text into `Details["error"]`. Keyed struct literals and `Lifecycle.Health(ctx) Health` implementations remain source-compatible; positional `store.Health{...}` literals must add the new field or migrate to keyed literals.
- **Data access (`store/sqldb`)** — driver error normalization is now context- and driver-family-aware. PostgreSQL SQLSTATE, strict MySQL error envelopes, and SQLite numeric codes preserve the original cause and driver code in `*store.Error`; constraint, serialization, deadlock, contention, timeout, unavailable, and read-only conditions are distinct. PostgreSQL `57014` consults cancellation/deadline state and maps an active request only when statement timeout is verified. MySQL 1205 and SQLite busy/locked map to contention rather than HTTP timeout; MySQL 1290 is no longer assumed read-only. Loose message matching was removed so domain/hook text such as “duplicate key validation” passes through unchanged.
- **BREAKING — `config.Load` and `config.LoadBytes` now return `*config.Config` instead of `credo.RawConfig`.** The concrete `*config.Config` still satisfies `RawConfig`, so passing the result to `credo.WithRawConfig` or storing it in a `RawConfig`/`credo.RawConfig` variable keeps compiling unchanged; only code that depends on the exact interface return type (for example assigning `config.Load` to a `func(...) (credo.RawConfig, error)` value) needs adjusting. The concrete return type is what carries the new `Get[T]`/`MustGet[T]` methods. See [ADR-005](docs/adr/005-configuration-architecture.md).
- **Lifecycle** — a failed startup (an `OnStart` hook returning an error) or a non-graceful `Serve` failure after the server reached `running` now runs the full teardown chain (readiness withdrawal → `OnPreDrain` → lifecycle cancellation → HTTP/`OnDrain` → DI container shutdown → `OnShutdown`) and ends in the terminal `stopped` state, instead of rolling back to `building`. This attempts to release resources an earlier `OnStart` hook started (workers, locks, connections) instead of leaking them. `OnShutdown` hooks consequently run on every teardown, including a failed startup, so they must be idempotent and must not assume any particular `OnStart` hook completed. Pre-session failures (TLS preflight, listener bind) still roll back to `building` and remain retryable. See [ADR-006](docs/adr/006-application-lifecycle.md).
- **Access logging** — the built-in access logger and `middleware.AccessLog` now share a single emit core (`internal/observe.EmitAccessLog`), keeping their attribute set, `"request completed"` message, and status→level mapping identical. No behavior change for existing callers.
- **TLS** — `Run` and `RunContext` now serve HTTPS when TLS is configured (previously plaintext-only); see **Added** and **Removed**.
- **BREAKING — typed Select terminals now require a model-less query.** `One[T]`, `All[T]`, and `Page[T]` no longer silently replace a model bound through `Select`, `Model`, or `Apply`; they return `sqldb.ErrTypedTerminalModel` before executing. Use `Model(&dest).Relation(...).Scan(ctx)` for bound models and relation loading, and use explicit-destination `Scan` for projections.
- **Data access (`store/sqldb`)** — `DB.Select`, `Insert`, `Update`, and `Delete` now accept at most one optional model argument. Supplying more causes the builder to record `sqldb: <Op> accepts at most one model, got N`; the terminal returns that error without executing instead of silently ignoring extra arguments.
- **BREAKING — `store.TxScope` is now `store.TxScope[T]`.** Construct it with `store.NewTxScope[T]()`; its methods no longer take their own type argument (`scope.WithTx[T](ctx, tx)` becomes `scope.WithTx(ctx, tx)`). The matching `*InScope` free functions now accept `*TxScope[T]`. The old unscoped `store.WithTx` / `GetTx` / `Conn` remain temporarily available but are deprecated because they cannot prevent cross-call concrete/interface mismatch or isolate same-type logical connections.
- **Data access (`store/sqldb`)** — transaction callbacks now have explicit failure semantics. After a successful rollback the exact callback error is returned without SQL mapping; callback and rollback failures retain both causes while only the rollback side is normalized. Nil callbacks return `ErrNilTxCallback` before BEGIN. Nested transactions accept nil/zero options but return `ErrNestedTxOptions` for non-default isolation/read-only options that Bun savepoints cannot apply. Savepoint creation is cancellation-aware; release/rollback remains usable after callback-context cancellation; a nil result after cancellation rolls back. Uncertain nested operations poison the ambient transaction before its bounded abort, preventing scheduler-dependent outer commits. Commit errors remain mapped but are documented as outcome-ambiguous, not unconditional retry signals.

### Removed

- **BREAKING — `(*store.Registry).Add` is removed.** Registry is now a read-only health view; only `store.Register` can create entries. This prevents health-only entries from bypassing startup Ping, DI publication, and shutdown ownership. Migrate direct `Registry.Add(name, lc)` calls to a typed `store.Register[R](app, value, ...)` registration.
- **BREAKING — `App.RunTLS` and `App.RunTLSContext` are removed.** TLS is now server configuration rather than a serve-method variant. Migrate by configuring TLS at construction and calling the plain entry points: `app.RunTLS(cert, key)` → `credo.New(credo.WithTLSFiles(cert, key))` then `app.Run()`; `app.RunTLSContext(ctx, cert, key)` → `WithTLSFiles` then `app.RunContext(ctx)`. For full `crypto/tls` control use `WithTLSConfig`. See [ADR-006](docs/adr/006-application-lifecycle.md).
- **BREAKING — `auth.SetUser` / `auth.GetUser` / `auth.RequireUser` are removed.** The authenticated principal is now reached through generic `*credo.Context` methods instead of `context.Context` helpers: `ctx.SetUser(user)` (T inferred), `ctx.GetUser[T]()`, and `ctx.RequireUser[T]()` (returns `credo.ErrUnauthorized` wrapping the new `credo.ErrUserMissing`). `auth.Middleware` is unchanged at the call site — it now stores the user via `ctx.SetUser`. Migrate handler reads: `auth.GetUser[T](ctx.Context())` → `ctx.GetUser[T]()`. See [ADR-012](docs/adr/012-authentication-and-authorization.md).
- **BREAKING — `sqldb.Paginate` and `sqldb.PaginateRequest` are removed.** The typed `(*SelectQuery).Page[T]` terminal replaces `PaginateRequest` one-for-one: `sqldb.PaginateRequest[User](ctx, q, req)` → `q.Page[User](ctx, req)`. For a fallible model→DTO conversion, fetch a model-less `Page[Model]`, map `modelPage.Records` with ordinary error handling, and construct `pagination.NewPage(dtos, modelPage.Total, modelPage.Page, modelPage.PerPage)`. The ORM-agnostic pagination data shapes remain; the `PageRequest.Offset` signature change is described above. See [ADR-015](docs/adr/015-data-access.md).

### Fixed

- **Pagination** — `pagination.NewPage` now calculates ceiling division as quotient plus remainder, avoiding the `total + perPage - 1` overflow that could produce an invalid `TotalPages` near `math.MaxInt64`.
- **Health/readiness** — named and store checks now share one bounded parallel runner. Per-check deadlines are enforced even when callbacks ignore cancellation; overlapping requests join a stable in-flight probe so a hung dependency cannot accumulate one goroutine per Kubernetes poll. Store checks are independently timeout- and panic-isolated, typed `store.Health.Cause` values are logged and masked by default, arbitrary adapter statuses fail closed, and a custom/store name collision produces an explicit 503 instead of silently overwriting a response entry. All stores remain critical; `DEGRADED` is explicitly readiness-blocking. Optional/critical policy and bounded low-cardinality tags remain separate follow-up decisions. See [ADR-016](docs/adr/016-health-checks.md).
- **Data access (`store/sqldb`)** — Select terminal snapshots and public `SelectQuery.Clone` now preserve the execution fields Bun v1.2.18 omits: explicit connection, builder error, `WherePK`, soft-delete flags, and CTE materialization flags. Credo retains Bun's clone behavior for the rest. Public `Clone` is a top-level builder fork, not a recursive object-graph copy: a bound destination and nested CTE/relation query values may remain shared, so source and clone must not mutate or scan shared values concurrently.
- **Routing** — `App.Mount` is now atomic: a mount that conflicts with an existing explicit route registers nothing. `Mount` makes fourteen radix registrations (every forwarded method on both the exact prefix and the catch-all), and the radix tree has no delete, so a conflict discovered partway through previously stranded the earlier registrations as orphan routes — reachable by dispatch yet hidden from introspection. `Mount` now preflights every method/pattern pair and panics before mutating the tree if any explicit route already occupies one, leaving the router exactly as it was. See [ADR-007](docs/adr/007-router-and-routing.md).
- **Docs** — `WithLogger`'s godoc no longer claims a "nop logger" is used when it is left unset; the framework default logger (a text handler on stderr) is, so access and request logging are on by default with no configuration.

## [0.1.0] - 2026-06-10 — development baseline (untagged)

Initial public development baseline.

### Added

- **Routing** — radix-tree router (adapted from Chi) with `{param}`, regex constraints, and `{path...}` catch-all; named routes with `BuildURI`/`BuildURL`; route Meta with parent-chain lookup; host routing; app-level 404/405/5xx status handlers; trailing-slash redirect; automatic HEAD handling.
- **Context** — pooled `credo.Context` with a `Request`/`Response` split, one-step bind-and-validate (`BindBody`/`BindQuery`), internal rewrites (`Rewrite`/`OriginalPath`), and `Context()` for context-taking APIs.
- **Error handling** — `func(*credo.Context) error` handler signature, RFC 7807 Problem Details responses, pluggable `ErrorRenderer`, built-in panic recovery.
- **Middleware** — four-tier execution (built-in → global → group → route); built-ins on by default: Recover, RequestID, AccessLog (opt-out via `Without*`). Suite: CORS, CSRF (stdlib `CrossOriginProtection`), Secure, Compress, Timeout, RateLimit, Rewrite, ContractGuard.

- **Dependency injection** — generics-based container (`Provide[T]`/`Resolve[T]`/`ProvideFactory`/`Alias`/`Replace`), validated graph freeze (`Finalize`), reverse-order shutdown, and the `credo.Infra` carrier (per-service logger; tracer/metrics with noop fallbacks).

- **Data access** — `store` contracts (universal errors, context-based transaction scope) and the `store/sqldb` Bun wrapper submodule: curated query-builder proxies, `db.InTx`/`RunInTx`, and migrations via a thin `bun/migrate` wrapper (`app.OnStart(db.Migrate)`, mark-applied-on-success default).
