# Built-in HTTP Features Contract

**Status:** Accepted default/API/ownership decisions, pending implementation (2026-09-05). **ADR:** [ADR-010](../adr/010-middleware-architecture.md). **Plan:** [pre-v1 implementation](../plans/pre-v1-implementation.md).

This is P8, a separate behavioral/API minor. The current [middleware spec](middleware.md) remains applicable until the migration lands. Implementation depends on P1's HTTP preparation and shutdown admission gate being in code and tested, preferably after the DI minor. The default activation and configuration-entry decisions below are settled. G4a–G4c were accepted on 2026-09-05: the installation, first-use locale, transport and failure/measurement contracts below are final design decisions awaiting implementation.

## Defaults and the sole public entry point

Promote Recovery, RequestID, AccessLog, i18n locale detection, Compress and Decompress to framework-owned HTTP features. Remove their middleware registration surfaces and the duplicate root/middleware implementations. Keep the `Middleware` type and the Global → Group → Route user chain for application middleware.

The configuration criterion is recorded in [ADR-010](../adr/010-middleware-architecture.md#built-in-http-feature-configuration-criterion) as an accepted amendment pending implementation. The following table applies that criterion; it does not introduce another configuration path.

| Setting or feature | Default | Sole configuration/registration path |
| --- | --- | --- |
| Logger, raw config, server/TLS and timeout settings | Existing constructor defaults | Constructor options through `New(...Option)` |
| Recovery | On | `credo.WithRecoverConfig(cfg)`; `WithoutRecover()` disables regardless of option order |
| RequestID | Off | `app.UseRequestID(cfg...)` with root `RequestIDConfig` |
| AccessLog | Off | `app.UseAccessLog(cfg...)` with root `AccessLogConfig` |
| Response compression | Off | `app.UseCompress(cfg...)` with root `CompressConfig` |
| Request decompression | Off | `app.UseDecompress(cfg...)` with root `DecompressConfig` |
| i18n | Off | `app.UseI18n(cfg...)`; first-use detection through `Detect func(*Context) string` |
| Custom error renderer | Default error rendering | `app.UseErrorRenderer(renderer)` |
| Custom success renderer | Existing `Context.Render` default | `app.UseSuccessRenderer(renderer)` |

- **Constructor settings, decided.** Keep the existing functional-option constructor. Add recovery through `WithRecoverConfig(cfg)`; multiple fields travel in one `RecoverConfig`, without a setter or a separate option for every field. Configuring recovery does not enable it: `WithoutRecover()` wins regardless of option order. Preserve the configurable logger, stack capture switch and stack-size capabilities from the middleware variant. Do not add `WithRecover()`/`UseRecover()` as activation helpers.
- **Optional features, decided.** `Use*` is each feature's actual registration API. Do not also add constructor fields/options or App configuration setters for the same feature. In particular, no parallel `WithRequestID`, `WithAccessLog`, `WithCompress`, `WithDecompress` or `WithI18n` surface. One setting has one public path, even though App stores its configuration internally.
- **Setters, decided.** The proposed `SetRecoverConfig` is withdrawn. Replace `SetErrorRenderer` and `SetSuccessRenderer` with the `Use*` registrations above, each installed once. Renderers may be methods of objects resolved from DI after Finalize, so they remain post-construction registrations. Omission selects the default; repeated setter-based replacement/reset is removed. Preserve the renderer callback's existing nil-result/body-shaping semantics and the rule that a success renderer is used only by `Context.Render`. This concerns App configuration APIs, not request-state operations or route metadata such as `Context.SetUser` and `Route.SetMeta`.

## Registration contract

- A covered config-based `Use*` method accepts zero configs for defaults or one for customization; more than one is a programming error. Renderer registrations take their renderer directly.
- Calling `Use*` requests installation. Remove duplicate `Enabled` switches from the affected feature configs; application bootstrap evaluates external enable flags before making the call. Retain i18n's explicit-source validation and conventional-discovery inactivity. A successful UseI18n call with no conventional catalog records a configured-but-inactive state and consumes the registration. A second call is duplicate misuse regardless of whether discovery found files. Genuine load/validation errors do not consume the registration and may be corrected before freeze.
- Each feature/renderer permits one successful registration, including inactive i18n configuration. A later `Use*` call cannot silently overwrite or merge its configuration. Misuse, including duplicate or late registration, panics under the existing registration policy. i18n I/O/load failures continue to return errors; constructor validation errors continue through `New`'s error result.
- Normalize, validate and prepare off to the side, then publish the feature once. Failed setup leaves no installed feature or consumed successful-registration slot. Snapshot caller-owned configuration slices/maps; retained callbacks and logger/Leveler objects keep their documented concurrency contracts. This is setup-time registration, not runtime reconfiguration.
- HTTP preparation admission or shutdown closes registration through [P1's shared guard](bootstrap-and-di-lifecycle.md#p1-setup-phases-and-ownership). A preparation/shutdown race must not allow an in-progress setup to publish afterward. DI Finalize alone leaves the HTTP registration window open, supporting DI-backed renderers and controllers.
- `Use*` call order does not determine request execution order. Store feature configuration and build one framework-defined HTTP plan; do not append hidden middleware in call order. User middleware ordering continues to follow its existing Global/Group/Route rules.

## HTTP execution and observability contract

- One internal request executor owns request initialization, the user middleware/handler chain, centralized error/panic handling, response finalization, optional access logging and Context release. Small private functions with real responsibilities remain appropriate; this change does not require a generic feature/plugin framework or a public request-stage API.
- Lifecycle-rejected requests take P1's default 503 branch before this executor's feature callbacks. The feature/renderer guarantees below apply to admitted requests; shutdown rejection does not depend on extensions whose DI dependencies may already be closed.
- Preparation/Finalize/compilation failures remain outside request recovery and follow P1's stored failure contract. Recovery handles request execution on its goroutine; preserve `ErrAbortHandler` propagation and committed/hijacked-response guards. Do not write a second response on those paths. Retain centralized error classification/rendering even when recovery or all optional features are disabled. Request cleanup must also run when recovery is disabled or an abort panic propagates.
- Initialize RequestID once per request when enabled, before consumers need it. Retain incoming-ID validation, custom header/generator/limit configuration and lazy request-logger enrichment. `Context.RequestID()` is the canonical accessor and returns empty when no ID has been installed. A disabled RequestID feature performs no automatic ID generation/header echo. AccessLog works independently with an empty ID; enabling either feature does not implicitly enable the other.
- AccessLog observes the completed response after centralized error/panic rendering and the applicable response finalization. Keep status, bytes, duration, route and request metadata in one authoritative observation. It must not infer the final status from a pre-render error as the removed middleware did. AccessLog bytes count output body bytes accepted by the underlying HTTP writer after compression, including bytes emitted by compressor finalization and partial writes. Exclude HTTP headers, framing and TLS overhead; this is not proof of client receipt. Measure duration from entry to the admitted request executor through response/compressor finalization; exclude ResultFilter, log emission and subsequent request cleanup. Preserve Response.Size's own documented meaning; the access observer counts at the output boundary.
- Keep the single AccessLog config's logger, dynamic MinLevel, pre-dispatch Skipper and positive post-response ResultFilter. Preserve `MetaAccessLog` group/route inheritance and the health-probe logging policy. MinLevel and ResultFilter narrow eligibility; the logger's own level filtering still applies. Preserve request attributes and avoid duplicate request-ID enrichment.
- **AccessLog off does not silence framework logging.** Recovery, server errors, lifecycle, health and other framework diagnostics continue through their normal loggers and levels, as do application/Infra logs. AccessLog's switch and MinLevel govern access records only. `WithLogger` does not activate access logging. `WithDebug` enables development diagnostics; it does not change the logger's minimum level, and some debug-mode diagnostics are Warn records.
- Replace the current request-observability-default policy when the implementation lands: logging infrastructure is ready by default, while request correlation and access records are explicitly enabled. An enterprise scaffold can make those choices visible with `UseRequestID` and `UseAccessLog`; plain `New()` must not acquire implicit scaffold/profile behavior.

## Locale and transport features

- **i18n first-use detection, decided.** Keep UseI18n, remove the locale middleware and expose one `I18nConfig.Detect func(*Context) string` callback. The default reads Accept-Language; an empty or unresolvable result selects the configured default language. Detect on the first Locale or translation access and memoize one result for the request. Unused locale/translation performs no detection. An inactive bundle keeps empty Locale/key fallback without invoking the detector. Locale, T, TPlural, automatic error/bind/validation translation and field-display lookup share the same resolver. `translatable` must not use nonempty ctx.locale as the initialization test; the first error translation can initiate resolution. Use separate request-owned memo state and reset it on pool reuse. Mark detection in progress before invoking the callback. Calling Locale/translation recursively from Detect is programming misuse and panics. On detector panic/re-entry, cache the default fallback before error rendering and never invoke that detector again for the request. With recovery enabled the failure follows the request 500 path; with recovery disabled the panic propagates and request cleanup still runs. The fallback state prevents recursive detection during error handling. No concurrency guarantee beyond Context's existing synchronous request lifetime is introduced. First access uses the request state visible then and fixes the result. Later auth, headers or rewrites do not invalidate it. The Context-based signature makes GetUser available but does not extend principal lifetime: auth may not have run, and Timeout/WrapStdMiddleware may restore an earlier request before central rendering. Preserve that behavior. An application requiring its authenticated language in later errors calls Locale after setting the user, before middleware unwinding; an earlier locale read still wins. Detectors must handle absent principals. Preserve exact keys, source validation, catalogs and plural policies. The timing/signature changes receive migration tests. P1's terminal lifecycle 503 invokes no detector. [Performance A2](../plans/wire-hot-paths.md) uses the post-resolution canonical-locale invariant; it must not assume ctx.locale is populated before the first consumer.
- Compress becomes an optional response feature whose writer stays valid through centralized error rendering. Close/finalize it at the framework's response-completion boundary before observing the completed access record and releasing request state. Carry over supported coding negotiation, content-type selection, level configuration and request selection. Preserve HEAD/bodyless, streaming/Flush, committed-response and hijack behavior with explicit contract tests.
- Decompress becomes an optional request-body feature installed **before Global middleware**. Body-reading middleware and binding then consume the same decoded stream. Process as a stream rather than buffering the entire body. Keep the compressed wire-byte limit and the independent decoded-byte limit, supported codings, 400/413/415 classifications, body/header updates and cleanup. Evaluate the transport Skipper once on the original request's method/path/headers, before body transformation and user middleware. Route/auth data are unavailable at selection. Preserve raw body routes, such as signed webhooks, by skipping decompression there; normal server limits still apply. Do not reselect after Rewrite. Compression request selection likewise happens once from the original request; response content-type/coding checks remain part of response handling.
- Keep Timeout, CORS, CSRF, Secure, RateLimit, Rewrite and ContractGuard as user middleware. Their route/group scope and order relative to application policies remain useful. Timeout keeps its cooperative context-deadline contract; it is not forced handler termination or a substitute for HTTP server read/write timeouts. Server body limits and trusted-proxy handling are already core settings and do not need another middleware-to-feature conversion.

## Callback and finalization failures

Recovery configuration applies to request-execution callback panics, including feature selectors, locale detection, renderers and access filters. With recovery disabled, panics propagate after mandatory cleanup. `http.ErrAbortHandler` always propagates as the transport-abort sentinel. Returned runtime errors still use central error handling regardless of recovery activation.

| Failure with recovery enabled | Required behavior |
| --- | --- |
| Feature/handler panic before commitment | Classify as 500 through request recovery; never retry the failed callback |
| Error renderer or error-rendering extension fails before commitment | Use the callback-free framework default 500 body/encoder, honoring HEAD/body rules; do not recursively invoke the failing extension |
| Locale detector panics or re-enters | Cache default locale, invoke request recovery and never detect again for this request |
| ResultFilter panics after finalization | Keep the completed response, emit a framework error diagnostic and skip this access record; never retry the filter |
| Failure after commitment/hijack | Preserve committed status/body and existing hijack/abort guards; do not write a second error envelope |

Compression finalization errors are observed, not discarded. If output has started, log the transfer failure and abort incomplete output with http.ErrAbortHandler where required; never append a JSON error to a partial compressed stream. Preserve the actual committed status and accepted body byte count in observation: a transmitted 200 does not become a fictional 500. Transfer failure has its own framework Error diagnostic, independently of AccessLog selection. When no response has started, use the existing central/fallback error rules with the failed path disabled.

The callback-free fallback is bounded and does not invoke custom renderers, locale/message-key resolvers or application encoder callbacks. Request cleanup remains mandatory on normal completion, fallback, escaping panic and abort. Lifecycle rejection still uses P1's separate 503 branch before feature callbacks, irrespective of recovery configuration.

## Cleanup and migration in the same HTTP change

- Remove `middleware.Recover`, `middleware.RequestID`, `middleware.AccessLog`, `middleware.Compress` and `middleware.Decompress`, migrating needed configuration and implementation to root/internal ownership. Remove i18n's hidden global middleware registration. The old built-in middleware wrappers and the duplicate implementations collapse into the HTTP executor's feature logic.
- Remove `WithoutRequestID` and `WithoutAccessLog`; optional features are disabled by omitting their `Use*` calls. Remove `WithAccessLogLogger`, `WithAccessLogMinLevel`, `WithAccessLogSkipper` and `WithAccessLogResultFilter`; their fields belong to the single `UseAccessLog` config. Retain `WithoutRecover` as the sole recovery opt-out and `WithRecoverConfig` for customization.
- Remove `middleware.GetRequestID` in favor of `Context.RequestID`. Audit the old RequestID key exposure and feature-only helpers; delete those with no remaining supported purpose. Remove unused/duplicate `Default*Config`, normalization and option helpers for converted features, retaining one normalization/validation path per feature. Shared helpers still used by remaining middleware and helpers enforcing real protocol/error contracts are not dead code.
- Migrate `SetErrorRenderer`/`SetSuccessRenderer` callers to single `Use*` registration. Remove their setter APIs and do not introduce `SetRecoverConfig` or duplicate constructor renderer options. Existing route/group recovery overrides and repeated RequestID middleware installation are deliberate API removals: adopt app-wide configuration or application-owned custom middleware. AccessLog selection remains available through metadata and filters; do not retain a second pre-render logger implementation as a compatibility wrapper. The downstream application scan supports renderer rename-only migrations and removal of scoped recovery; the [migration guide](../guides/pre-v1-migration.md) records that evidence's limits. Migrate the SaaS example and compression integration tests explicitly.
- Move behavior tests with their implementation, then remove duplicate-wrapper/default/helper tests whose independent contract has disappeared. Update testutil, examples, benchmarks and consumer migration guidance for explicit opt-ins. Preserve upstream copyright attribution in moved adapted files and update NOTICES locations; adaptation history is not erased by relocation.
- At implementation time, update ADR-009/010/013/014, relevant HTTP/context/middleware/i18n specs, guides, root and middleware package docs, development-guide defaults/naming policy, CHANGELOG and TODO together. Historical feature names must not remain presented as callable APIs. These accepted target contracts do not make the replacement APIs available in the current runtime.

## Acceptance checks for the implementation

- Default App: recovery works; RequestID/access logging/compression/decompression/i18n remain inactive without their `Use*` registrations. Central error responses and filtered framework Error/Warn/Info/Debug records remain independent of access logging.
- Configured/disabled recovery, incoming/generated/absent ID, lazy logger enrichment, independent RequestID/AccessLog activation, access filters/meta/levels, renderer-selected final status and panic responses have positive contract coverage. Verify the `WithDebug`/logger-level distinction.
- Registration covers default/custom/extra configs, duplicate success, failed setup without partial state, inactive-i18n duplicate rejection, immutable config snapshots, DI-Finalize-before-Use, HTTP-preparation/shutdown rejection and attempted late publication. Renderer tests cover DI-backed registration and existing body semantics. P1's preparation/shutdown gate tests must pass before P8 implementation begins.
- Transport/locale checks cover returned errors, panic, 404/405, HEAD/bodyless responses, mounted handlers, streaming/hijack/abort cleanup, original-body selection, both body limits and custom locale detectors. Representative `Use*` call-order permutations produce the same runtime plan.
- Lazy i18n requires zero/one detector-call checks, first/cached Locale and translation reads, first access from an early middleware or error path, auth not yet run, request restoration, later mutations/rewrites, explicit post-auth Locale, empty/unresolvable default fallback and pool reuse without stale memo state. Assert detector panic/re-entry runs once, recovery-enabled 500, recovery-disabled propagation and no second detection from error rendering. Performance comparisons distinguish unused i18n, first resolution and subsequent translation accesses.
- Transport tests verify decoded data in Global middleware, raw-body Skipper paths, original-request selection surviving Rewrite and both size limits. Observe post-compression accepted body bytes, including finalizer/partial writes, and duration through finalization excluding filter/log time. Cover renderer fallback, ResultFilter panic, compressor Close failure, committed-status preservation, no second body, abort propagation and cleanup with recovery enabled and disabled.
- Compare the existing wire benchmarks with equivalent enabled-feature sets and a separate default profile. Wrappers are currently constructed at compile time: removing them is an API/maintenance simplification, not evidence of an allocation or latency improvement. Measure before claiming one.
