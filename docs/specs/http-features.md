# Built-in HTTP Features

**Status:** Implemented (HTTP minor, 2026-09-05) **Implementation:** root package — `executor.go`, `features.go`, `recover.go`, `requestid.go`, `accesslog.go`, `compress.go`, `decompress.go`, `i18n.go` **ADR:** [ADR-010](../adr/010-middleware-architecture.md#built-in-http-feature-configuration-criterion)

Panic recovery, request IDs, access logging, response compression, request-body decompression, locale detection and the custom renderers are framework-owned HTTP features of the root package. They are not middleware: one internal request executor runs them in a fixed order around the user's Global → Group → Route chain, so they observe the final response — error envelopes and panic responses included — and cannot be scoped to a group or route. The [middleware spec](middleware.md) covers the user chain; this document is the feature contract.

## Defaults and the sole public entry point

| Setting or feature | Default | Sole configuration/registration path |
| --- | --- | --- |
| Logger, raw config, server/TLS and timeout settings | Existing constructor defaults | Constructor options through `New(...Option)` |
| Recovery | On | `credo.WithRecoverConfig(cfg)`; `WithoutRecover()` disables it regardless of option order |
| RequestID | Off | `app.UseRequestID(cfg...)` with `RequestIDConfig{Header, Generator, Limit}` |
| AccessLog | Off | `app.UseAccessLog(cfg...)` with `AccessLogConfig{Logger, MinLevel, Skipper, ResultFilter}` |
| Response compression | Off | `app.UseCompress(cfg...)` with `CompressConfig{Skipper, Level, Types}` |
| Request decompression | Off | `app.UseDecompress(cfg...)` with `DecompressConfig{Skipper, MaxBytes}` |
| i18n | Off | `app.UseI18n(cfg...)`; first-use detection through `I18nConfig.Detect func(*Context) string` |
| Custom error renderer | Default error rendering | `app.UseErrorRenderer(renderer)` |
| Custom success renderer | Plain JSON through `Context.Render` | `app.UseSuccessRenderer(renderer)` |

- **Constructor settings.** Recovery is the one feature that is on by default, so it follows the constructor rule: `WithRecoverConfig(cfg)` carries the logger, the stack-capture switch and the stack size in one `RecoverConfig`, and `WithoutRecover()` is the only opt-out. Configuring recovery never re-enables it; `WithoutRecover` wins regardless of option order. There is no `WithRecover()`/`UseRecover()` activation helper.
- **Optional features.** `Use*` is each feature's only public path. There are no parallel constructor options (`WithRequestID`, `WithAccessLog`, `WithCompress`, …), no App setters and no `Enabled` switches inside the configs: calling `Use*` installs the feature, leaving it out leaves the feature off, and application bootstrap evaluates external enable flags before making the call.
- **Renderers.** `UseErrorRenderer` and `UseSuccessRenderer` install each renderer once. Renderers may be methods of objects resolved from DI after `Finalize`, so they remain post-construction registrations. Omission selects the default. The renderer callbacks keep their nil-result/body-shaping semantics, and a success renderer is used only by `Context.Render`. This rule concerns App configuration; request-state and route-meta mutators such as `Context.SetUser` and `Route.SetMeta` are unaffected.

## Registration contract

- A config-based `Use*` method accepts zero configs for the defaults or one config for customization; more than one config panics (`credo: App.UseX accepts at most one config`). Renderer registrations take their renderer directly and panic for nil.
- Each feature and each renderer permits one successful registration; a second call panics (`credo: App.UseX called twice`). A later call never silently overwrites or merges configuration. A successful `UseI18n` whose conventional discovery found no catalogs records a configured-but-inactive state and still consumes the registration; genuine load/validation errors are returned, do not consume it and may be corrected before preparation.
- Configuration is validated and normalized off to the side, then published once: a rejected call (bad `Level`, negative `MaxBytes`, typed-nil `MinLevel`, a credential `RequestIDConfig.Header` such as `Authorization`, `Proxy-Authorization` or `Cookie`, nil renderer, too many configs) leaves nothing installed. Caller-owned slices are copied at registration. Retained callbacks and logger/`Leveler` values keep their documented concurrency contracts. This is setup-time registration, not runtime reconfiguration.
- Registration closes at HTTP preparation admission or at shutdown admission through the [shared guard](bootstrap-and-di-lifecycle.md#p1-setup-phases-and-ownership) (`credo: App.UseX called after app was compiled or shut down`). Publication happens under the preparation mutex, so a preparation admitted while a `Use*` call was still validating can never be followed by a late publication. DI `Finalize` alone leaves the HTTP registration window open, which is what allows DI-backed renderers and controllers.
- `Use*` call order does not determine request execution order. The App stores each feature's normalized configuration and the executor applies them in one framework-defined plan; nothing is appended in call order. User middleware keeps its Global/Group/Route ordering rules.

## Request execution

`App.ServeHTTP` first applies the lifecycle admission gate: a request arriving after the App stopped, or while it is stopping without a prepared handler, takes the callback-free 503 branch and never reaches the executor. Admitted requests run through `App.execute`, which owns the following order:

1. **RequestID** (when installed): validate the incoming header value against the limit and the allowed character set, or generate one; store it on the Context, echo it on the response header and enrich the request-scoped logger lazily on first `Context.Logger` use.
2. **AccessLog start** (when installed and the pre-dispatch `Skipper` returned false): record the entry timestamp.
3. **Decompress** (when installed and the `Skipper`, evaluated once on the original request's method, path and headers, returned false): an `identity` coding passes through; an empty body drops the header; a supported coding replaces the body with the decoded stream bounded by `MaxBytes`, sets `ContentLength` to -1 and removes `Content-Encoding`; an unsupported coding or coding list answers 415 `unsupported_content_encoding` and a corrupt stream header answers 400 `bind_failed`, both rendered centrally without running any user middleware.
4. **Compress** (when installed, the `Skipper` returned false and `Accept-Encoding` negotiates gzip or deflate): install the pooled compressing writer around the response writer. Content-type selection and the `Content-Encoding`/`Vary` decision happen at first write, so the writer stays installed through centralized error rendering and error envelopes are compressed like handler output. HEAD and bodiless responses, streaming (`Flush`), committed responses and hijacked connections keep their behavior — a body-forbidding status (1xx, 204, 304) never starts a compressor, whatever its `Content-Type`, because even an empty compressed stream is a body net/http rejects; a rewrite does not re-evaluate the selection.
5. **User chain:** Global middleware → dispatch → Group → Route → handler. A returned error goes through centralized error classification and rendering (custom renderer, i18n translation, status handlers) exactly as before.
6. **Recovery** (unless `WithoutRecover`): a panic anywhere in steps 1–5 or in the callbacks below is logged through `RecoverConfig` (request-scoped logger by default, optional dedicated logger, stack capture on by default, bounded by `StackSize`) and rendered as a generic 500 unless the response was already committed or hijacked. `http.ErrAbortHandler` always propagates. With recovery disabled the panic propagates after the cleanup below.
7. **Finalization:** close the compressor. A `Close` failure is a framework `Error` diagnostic; if no output was committed the request falls back to the central 500 with compression disabled, and if output had started the incomplete stream is aborted with `http.ErrAbortHandler` — never by appending a JSON body to a partial compressed stream. The pooled writer is released.
8. **AccessLog observation** (when started): `MetaAccessLog` silence → final status (an escaped panic with recovery disabled uses the 500 fallback) → `MinLevel` admission → `AccessLogEntry` snapshot → `ResultFilter` → logger selection → emission through `internal/observe.EmitAccessLog`, where the logger's own level filtering still applies.
9. **Cleanup:** the Context is released to the pool in a defer, so it runs on normal completion, fallback, escaping panic and abort alike.

Central error classification and rendering exist even when recovery and every optional feature are off. Preparation, Finalize and compilation failures are outside request recovery and follow the [stored preparation contract](lifecycle.md).

## Observability contract

- `Context.RequestID()` is the canonical accessor and returns `""` when no ID was installed. Without `UseRequestID` no ID is generated or echoed. RequestID and AccessLog are independent: access records carry an empty `request_id` when only access logging is installed, and enabling one never enables the other.
- **request_id sourcing rule** (shared by access logging and recovery): the `request_id` attribute is added explicitly only when the target logger does not already carry it — when a dedicated `Logger` was configured, or when no request-scoped logger was set (`Context.HasRequestLogger`). The rule is convention-based: `HasRequestLogger` reports that a request-scoped logger was set, not which attributes it carries, so middleware that replaces the logger without deriving from `ctx.Logger()` silently drops the ID. Enrich with `ctx.AddLogAttrs`; reserve `ctx.SetLogger` for wholesale replacement.
- **Access-log record.** Status maps to the record level: `1xx/2xx/3xx → Info`, `4xx → Warn`, `5xx+ → Error`. `MinLevel` (`slog.Leveler`; nil means Info; a typed-nil provider panics at registration; a concurrency-safe `slog.LevelVar` supports runtime changes and is read once per eligible request) is an admission threshold, never a level rewrite. `Skipper` (`true = skip`) runs before dispatch and sees request data only. `MetaAccessLog: false` on the matched route, or inherited from a group, silences the record; a route-level value overrides a group-level one and a non-bool value fails open. `ResultFilter` (`true = emit`) runs after the final response with a pooled Context that must not be retained; it cannot restore an entry rejected by `MinLevel`. A dedicated `Logger` receives the standard fields and an explicit request ID but does not inherit arbitrary `ctx.AddLogAttrs` enrichment.
- **Measurements.** `AccessLogEntry.Bytes` counts the body bytes the underlying transport writer accepted after compression, compressor trailers and partial writes included; headers, framing and TLS overhead are excluded and the count is not proof of client receipt. `Response.Size` keeps its own meaning (bytes handed to the response). `Duration` runs from executor entry through response and compressor finalization and excludes `ResultFilter`, log emission and Context release. `Route` is the matched route's registered pattern (`/v1/jobs/{job_id}`), emitted as `route` whenever a route matched; `path_original` is emitted when the served path differs from the client path; `RouteName` is filter metadata only. `RemoteAddr` comes from `Request.RealIP`.
- **AccessLog off does not silence framework logging.** Recovery, server errors, lifecycle, health and other framework diagnostics continue through their normal loggers and levels, as do application and `Infra` logs. `UseAccessLog` and `MinLevel` govern access records only. `WithLogger` does not activate access logging. `WithDebug` enables development diagnostics and does not change the logger's minimum level; some debug-mode diagnostics are Warn records.
- Health probes registered by `UseHealth` set `MetaAccessLog` to `HealthConfig.LogRequests` (default false), so probe traffic is silent even when access logging is installed.

## Locale and transport features

- **i18n first-use detection.** `I18nConfig.Detect func(*Context) string` is the sole detector callback; the default reads `Accept-Language`, and an empty or unresolvable result selects the configured default language. Detection runs on the first `Locale`, `T`, `TPlural`, automatic error/bind/validation translation or field-display lookup of a request and its result is memoized in request-owned state that is reset on pool reuse. A request that never touches locale or translation performs no detection; an inactive bundle keeps empty `Locale` and key fallback without invoking the detector. The first access uses the request state visible at that moment — headers, the route when already matched, the user when authentication already ran — and later auth, header changes or rewrites do not re-run it. The Context-based signature exposes `GetUser` but does not extend principal lifetime: authentication may not have run yet, and `Timeout`/`WrapStdMiddleware` may restore an earlier request before central rendering. An application that needs its authenticated language in later errors calls `Locale` after setting the user and before middleware unwinding; an earlier read still wins. Detectors must handle absent principals.
- **Detector failures.** Calling `Locale` or a translation from inside `Detect` is programming misuse and panics (`credo: recursive locale detection …`). A detector panic caches the default locale for the request before error rendering and never invokes the detector again for that request, so error rendering translates with the default and cannot recurse into the detector; with recovery enabled the request takes the 500 path, with recovery disabled the panic propagates after cleanup. The lifecycle 503 branch invokes no detector.
- **Compress** keeps its writer valid through centralized error rendering and finalizes it at the response-completion boundary before the access record is observed. Supported codings are gzip and deflate, selected by `Accept-Encoding` quality values; `Level` is 1–9 (zero selects 5; other values panic at registration); `Types` accepts exact media types and `type/*` wildcards and defaults to the common textual types. Responses that already carry a `Content-Encoding` are passed through.
- **Decompress** runs before Global middleware, so body-reading middleware and binders consume the same decoded stream; the body is processed as a stream, never buffered whole. Supported codings are `gzip`/`x-gzip` and `deflate` (zlib-wrapped per RFC 9110, raw DEFLATE tolerated); multiple gzip members are not concatenated. The server-wide `max_body_bytes` bounds the compressed wire bytes and `MaxBytes` (default `DefaultDecompressMaxBytes`, 4 MiB) bounds the decoded bytes; reading past it surfaces as the framework's regular 413. The transport `Skipper` is evaluated once on the original request and is the way to keep raw bodies for routes such as signed webhooks; route and auth data are unavailable at selection and a rewrite does not reselect. Without `UseDecompress`, `BindBody` rejects a non-identity `Content-Encoding` with 415.
- Timeout, CORS, CSRF, Secure, RateLimit, Rewrite and ContractGuard remain user middleware: their route/group scope and their order relative to application policies stay useful. Timeout keeps its cooperative context-deadline contract. Server body limits and trusted-proxy handling are core settings, not middleware.

## Callback and finalization failures

Recovery configuration applies to every request-execution callback: feature selectors, locale detection, renderers and access filters. With recovery disabled, panics propagate after mandatory cleanup. `http.ErrAbortHandler` always propagates as the transport-abort sentinel. Returned runtime errors use central error handling regardless of recovery.

| Failure with recovery enabled | Behavior |
| --- | --- |
| Feature/handler panic before commitment | Classified as 500 through request recovery; the failed callback is never retried |
| Error renderer or error-rendering extension fails before commitment | The callback-free framework default 500 body/encoder is used, honoring HEAD/body rules; the failing extension is not invoked recursively |
| Locale detector panics or re-enters | Default locale cached, request recovery invoked, no second detection for this request |
| `ResultFilter` panics after finalization | Completed response kept, framework `Error` diagnostic (`credo: access-log result filter panicked`) emitted, this access record skipped; the filter is never retried |
| Failure after commitment/hijack | Committed status/body preserved with the existing hijack/abort guards; no second error envelope |

Compression finalization errors are observed, not discarded: they carry their own framework `Error` diagnostic independently of access-log selection, the actual committed status and accepted byte count are preserved in the access record (a transmitted 200 never becomes a fictional 500), and started output is aborted rather than patched. The callback-free fallback is bounded and invokes no custom renderer, locale/message-key resolver or application encoder callback. Request cleanup runs on normal completion, fallback, escaping panic and abort.

## Contract tests

The root test package covers the contract: default App (recovery only; RequestID, AccessLog, Compress, Decompress and i18n inactive without their `Use*` calls; framework Error/Warn/Info/Debug records independent of access logging), recovery configured/disabled, incoming/generated/absent IDs and lazy logger enrichment, independent RequestID/AccessLog activation, access filters/meta/levels/dedicated loggers, registration misuse (duplicate configs, duplicate calls, failed setup without partial state, inactive-i18n duplicate rejection, late registration after preparation or shutdown, `Use*` call-order permutations), DI-backed renderers, compressed error/404/panic envelopes, HEAD and bodiless responses, original-request selection surviving `Rewrite`, decoded bodies in Global middleware, both body limits, post-compression byte counts, `ResultFilter` and detector panics with recovery enabled and disabled, and the lazy-locale matrix (zero/one detections, first access from middleware or error paths, auth not yet run, explicit post-auth `Locale`, default fallback, pool reuse). `wire_benchmark_test.go` compares the default profile with equivalent enabled-feature sets.
