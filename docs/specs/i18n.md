# i18n Spec

**Status:** Implemented (beta) **Package:** root (`i18n.go`; locale resolution in `context.go`), `internal/i18n/` **ADR:** [ADR-013](../adr/013-internationalization.md) **Guide:** [Internationalization guide](../guides/localization.md) **Sources:** go-i18n (MIT)

The others illustrate the contract or describe current behaviour, which is not guaranteed.

This spec is the contract for i18n registration, catalog sources, the locale detector and message-key resolution.

## Detector contract

UseI18n is a framework-owned HTTP feature under the [HTTP contract](http-features.md#locale-and-transport-features): it installs no middleware. The one detector signature is `Detect func(*Context) string`; nil reads `Accept-Language`, and an empty or unresolvable result selects the configured default. `Locale`, `T`/`TPlural` and automatic error/bind/validation/field translation share first-use resolution and request memo state, reset on pool reuse. A request that never touches locale or translation never invokes the detector. Inactive i18n (no `UseI18n`, or one whose conventional discovery found no catalogs) never invokes it either: `Locale` returns empty and `T`/`TPlural` return the key. The first access uses the request state visible at that moment — headers, the route when already matched, the user when authentication already ran — and later authentication, header changes, rewrites and request restoration do not re-run it.

The Context-based signature exposes `GetUser`, but authentication may not have run yet when the detector first runs, so detectors must handle an absent principal. A user set inside `Timeout` or a wrapped stdlib middleware stays the request's user for the outer layers and the central error rendering. An application that needs its authenticated language in later errors calls `Locale` after setting the user; an earlier read still wins, since the locale is memoized for the request.

Calling `Locale` or a translation from inside `Detect` is programming misuse and panics (`credo: recursive locale detection: …`). A detector panic caches the default locale for the request before error rendering and never invokes the detector again for that request, so error rendering translates with the default and cannot recurse into the detector; with recovery enabled the request takes the 500 path, with recovery disabled the panic propagates after cleanup. The terminal lifecycle 503 invokes no detector.

## Public API

```go
type I18nMessages map[string]string
type I18nFields map[string]string

type MessageScope uint8

const (
    MessageScopeError MessageScope = iota
    MessageScopeValidation
    MessageScopeBind
)

type MessageRef struct {
    Scope MessageScope
    Code  string
}

type MessageKeyResolver func(MessageRef) string

type I18nConfig struct {
    Dir               string
    DirFS             fs.FS
    Default           string
    Detect            func(*Context) string
    Messages          I18nMessages
    Fields            I18nFields
    ResolveMessageKey MessageKeyResolver
}

func (app *App) UseI18n(cfg ...I18nConfig)
func (ctx *Context) Locale() string
func (ctx *Context) T(key MessageKey, data ...map[string]any) string
func (ctx *Context) TPlural(key MessageKey, count any, data ...map[string]any) string
```

`UseI18n` accepts zero or one config and returns nothing; when it panics and when the start fails is under [Registration and start phase](#registration-and-start-phase). `Default` is `en`. `Detect` defaults to `Accept-Language` and runs lazily ([Detector contract](#detector-contract)). `Locale` returns the matched locale (the `Default` language when detection yields nothing usable), or empty when i18n is inactive. `T` and `TPlural` take the key as a [`MessageKey`](#message-key-resolution) and return the key itself, as a `string`, when i18n is inactive or the key is missing; what a miss logs is under [Plurals and lookup](#plurals-and-lookup).

## Sources and precedence

`Messages` and `Fields` are a one-language programmatic base attached to the effective `Default`. `Dir`/`DirFS` provide file-backed multi-language catalogs. The framework copies the maps, without retaining them, and compiles their templates at the `UseI18n` call; the files are read in the start phase.

Load order:

```text
1. Messages / Fields for Default
2. Dir or DirFS catalogs, merged by language + exact key
```

The second layer overrides collisions; keys found only in the base survive. `Messages` and `Fields` are separate catalogs. Messages contain templates; fields contain technical-path-to-display-name mappings.

| Configuration | Result |
| --- | --- |
| zero config | the RawConfig `i18n` section, then conventional `locales/` discovery |
| `Messages` | map-only default-language bundle |
| `Messages + Fields` | map-only field-aware bundle |
| maps + explicit `Dir`/`DirFS` | maps as base, files as override |

With neither `Dir` nor `DirFS` set, the RawConfig `i18n` section supplies `dir`, which is an explicit source, and `default`, used when `Default` is empty; this applies with programmatic maps too. A programmatic map without an explicit file source turns conventional discovery off. Conventional discovery reads `locales/` in the process working directory.

## Registration and start phase

`UseI18n` returns nothing. It validates what needs no I/O, compiles and copies the programmatic catalog (a snapshot of `Messages` and `Fields` taken at the call) and records the configuration; it does no I/O. A framework start step named `i18n` reads the catalogs and publishes the bundle; it runs first in the start walk, before any component, and is reported in the internal tier. The rationale is in [ADR-013](../adr/013-internationalization.md#registration-and-the-start-phase).

| Condition | Where it fails |
| --- | --- |
| more than one config; `Dir` and `DirFS` together; a second call, even when the first left i18n inactive; a call after preparation or shutdown | panic at the call |
| invalid `Default` tag; empty programmatic key or value; programmatic template that does not compile; `Fields` with no `Messages` and no file source; `i18n` RawConfig section that does not decode | panic at the call |
| absent conventional `locales/`, or one that yields no message | Warn from the start phase; i18n inactive; no failure |
| missing/empty explicit source (`Dir`, `DirFS`, `i18n.dir`), even with maps | start failure |
| malformed or read-denied source; a language directory without `messages.json`; a file template that does not compile | start failure; nothing published |

A start failure rolls the App back like any other start failure and is reported in the `*credo.LifecycleError` that `Run` (or `App.Start`) returns, under the name `i18n`. A call either installs the registration, which a second call then finds, or panics before installing anything; a catalog that fails to load fails the start. The start step logs `credo: i18n loaded` (Info, with `default`) when the bundle is active, and `credo: i18n inactive, locale directory not found or empty` (Warn) when conventional discovery finds no catalogs; the [startup feature list](http-features.md#startup-visibility) shows `i18n` only when it is active. The bundle is published whole after every source validates and before the listener accepts, and is immutable afterwards; request handling performs no filesystem access. An App that called `UseI18n` has something to start, so `ServeHTTP` refuses it until `App.Start` has succeeded.

## File format

```text
locales/
├── en/
│   ├── messages.json
│   └── fields.json
└── tr/
    ├── messages.json
    └── fields.json
```

Each subdirectory whose name is a BCP 47 tag is a language directory and must contain `messages.json`; `fields.json` is optional. A subdirectory whose name is not a BCP 47 tag, and a file beside the language directories, is ignored.

`messages.json` accepts a string shorthand or CLDR plural object:

```json
{
  "required": "{{.field}} is required",
  "items": {
    "one": "{{.count}} item",
    "other": "{{.count}} items"
  }
}
```

`fields.json` is an exact map:

```json
{
  "email": "email address",
  "address.city": "city"
}
```

Use `DirFS` when plural forms or multiple languages must be embedded in the binary.

## Message-key resolution

Framework error presentation never adds a namespace prefix. Exact key selection is:

1. explicit `HTTPError.MessageKey` or `Violation.MessageKey`;
2. `ResolveMessageKey` with a scope and code;
3. bare code/reason.

```go
ResolveMessageKey: func(ref credo.MessageRef) string {
    switch ref.Scope {
    case credo.MessageScopeValidation:
        return "validation." + ref.Code
    case credo.MessageScopeBind:
        return "request." + ref.Code
    default:
        return "problem." + ref.Code
    }
},
```

This callback is the opt-in namespace policy. It applies only while i18n is active; with inactive i18n the key is the explicit `MessageKey` or the bare code. A returned empty key is misuse and fails closed. The selected key reaches an `ErrorRenderer` as `ErrorInfo.MessageKey`, with the resolved text as `ErrorInfo.Message`; a validation or bind violation carries its key in `Violation.MessageKey`.

A message key is a catalog key and never text. Its type is `credo.MessageKey`, an alias of `validation.MessageKey`, `type MessageKey string`, taken by `Context.T`, `Context.TPlural`, `HTTPError.WithMessageKey`, `HTTPError.MessageKey`, `ErrorInfo.MessageKey`, `RenderMessageKey`, `RenderInfo.MessageKey` and `Violation.MessageKey`; `ResolveMessageKey` returns a `string`, since it computes keys, and the pipeline converts it. An untyped literal is a key as written (`c.T("orders.title")`); a `string` variable, or a concatenation with one, does not compile as a key and converts explicitly: `c.T(credo.MessageKey("status." + code))`.

An explicit key miss — literal text given as a key included — falls back to the built-in message for the error's code, then to the status text; the key is never rendered. In debug the pipeline warns with the key, the code and the route. Literal client text is a message, set with `WithMessage`, which is never looked up:

```go
return credo.NewHTTPError(http.StatusNotFound, "record_not_found").
    WithMessage("Kayıt bulunamadı")
```

The framework sets no explicit key of its own: `middleware.Timeout`'s 503 carries the code `request_timeout` and no key, so `ResolveMessageKey` maps it as it maps every other code, and the framework's rejections that carry a client value render their code's built-in message with the value in `Details`. `testutil.CheckMessageKeys` fails an application's test for a key its catalogs do not define ([ADR-009](../adr/009-handler-and-error-handling.md#one-error-channel-keys-messages-and-fault-codes)). It reads the sources without compiling them, so what it checks is what is written:

| Written as | Checked as |
| --- | --- |
| a literal: the first argument of a call of a method named `T` or `TPlural`, the argument of `WithMessageKey` or `RenderMessageKey`, a value given to a `MessageKey` field, a constant or variable declared with type `MessageKey`, a conversion to `MessageKey` | one key: fails when no catalog defines it |
| a constant declared with type `MessageKey`, named at a call | one key, where the constant is declared |
| a concatenation of literals and string constants only | one key, the joined text |
| a concatenation that begins with a literal or a string constant, the joined leading text ending in `.`, followed by a computed part | a family: fails when no catalog defines a key that begins with the prefix and continues after it |
| anything else: a computed key with no literal prefix, a prefix that does not end in `.`, a variable, a parameter, a constant declared without the key type and passed alone | reported as not provable, with the forms above as the remedy |

A string constant is read by its name, since the sources are not type-checked: a constant declared in the function that uses it, else one declared at package level in the package of the file, else, for `pkg.Name`, the package-level constant of the directory under the source roots whose path ends with the most elements of the import path. A name is not read, and the expression is reported, when the function also declares it as a variable, a parameter or a type anywhere in its body (a prefix constant and a local of the same name do not share a function, whichever block the local is in), when the sources do not declare it, when one package declares it with different values (files for different platforms), and when two directories match the import path equally well without agreeing. A family is proved by its prefix only: that each computed member has a message is what the debug warning of a miss shows at run time ([Plurals and lookup](#plurals-and-lookup), [ADR-013](../adr/013-internationalization.md#one-key-type-and-key-families)).

An implicit miss of an error-scope key (the top-level `validation_failed` and `bind_failed` included) falls back to the built-in English message for the code, then to `http.StatusText(status)`, then to `HTTP <status>`. Validation- and bind-scope misses keep the violation's safe source message. Resolver-generated keys are never shown as messages merely because lookup missed.

## Validation, bind, and fields

Validation and bind translation happens in the root error pipeline, not inside the validation engine. The top-level keys use error scope with codes `validation_failed` and `bind_failed`. Nested validation uses validation scope; nested decode reason uses bind scope.

`Violation.MessageKey` is optional, exact, and `json:"-"`. The resolved wire entry remains:

```json
{"field":"email","code":"required","message":"email address is required"}
```

`field` stays technical. For template data, Credo looks up the exact field path in the selected locale's Fields catalog. A miss uses the raw path; there is no default-language field fallback because that would mix languages within one sentence.

## Plurals and lookup

`T` renders Other. `TPlural` uses CLDR cardinal rules from `golang.org/x/text/feature/plural`, adds `count` to a copied data map, and falls back to Other for an uninterpretable count. File messages support zero/one/two/few/many/other. Programmatic strings always render Other.

Message lookup tries the selected language then Default. A key that neither defines is a miss: `T` and `TPlural` return the key, and in debug mode (`WithDebug`) each miss logs one Warn, `credo: translation key is not in the catalog; the key is returned as the text: add the key to the catalog or correct it at the call`, with `key`, `locale` (the request's resolved locale) and `route`, the attributes the error pipeline's warning for a missing message key carries with `code` in place of `locale`. Outside debug mode a miss logs nothing, and a call with i18n inactive is not a miss: there is no catalog to look the key up in.

A miss returns the key and not an empty string because the result goes into a field of a response the application builds: an empty string would blank that field without a trace, and a key is seen at once. The error pipeline can refuse to render a key because it has the code's built-in message to fall back on; `T` has no other text.

The engine is immutable and concurrency-safe once the start phase has published it; no request-time filesystem access occurs.

## Internal boundary

`internal/i18n` imports no root package. Its `Bundle` owns compiled templates, field maps, language matching, and key-level merge. Root code supplies strings at the boundary and performs error classification. BCP 47 and CLDR behavior comes from `golang.org/x/text`.
