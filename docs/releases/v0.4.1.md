# Credo v0.4.1

Credo v0.4.1 is a patch release: the `store/sqldb` SQLite error classifier now recognizes the [ncruces/go-sqlite3](https://github.com/ncruces/go-sqlite3) driver, so its failures map to the same semantic `store.Err*` sentinels as the modernc and mattn drivers. There are no API changes and no behavioral breaks.

The root module and Bun SQL wrapper are published in lockstep:

| Module | Version |
| --- | --- |
| `github.com/credo-go/credo` | `v0.4.1` |
| `github.com/credo-go/credo/store/sqldb` | `v0.4.1` |

## Requirements and installation

This release requires Go 1.27. At publication time Go 1.27 is pre-GA, so the repository selects `go1.27rc2`; a newer compatible Go 1.27 toolchain can be used when available.

```sh
go get github.com/credo-go/credo@v0.4.1
go get github.com/credo-go/credo/store/sqldb@v0.4.1
```

Applications that do not use SQL only need the root module.

## Highlights

- **ncruces/go-sqlite3 error classification** — the driver returns typed error codes (`Code() ErrorCode`, `ExtendedCode() ExtendedErrorCode`) that previously satisfied neither the modernc `Code() int` interface nor the mattn field shape, so its errors passed through unclassified and `errors.Is(err, store.ErrAlreadyExists)`-style branches never matched. The classifier now extracts those codes structurally (reflection over package path and method shape); no SQLite driver becomes a Credo dependency. The original driver error remains in the chain, so existing `errors.As`/`errors.Is` checks against driver types keep working.
- **Documented driver recognition** — the data access guide now states which drivers each family's classification recognizes (SQLSTATE-based for PostgreSQL; the strict error envelope for MySQL; modernc, mattn, and ncruces for SQLite) and that errors from unrecognized drivers pass through unmapped.

## Upgrade notes

No action required. Applications using the ncruces driver (`driver: sqlite3` with `github.com/ncruces/go-sqlite3/driver` imported) gain semantic error mapping automatically; previously unclassified driver errors now arrive wrapped as `*store.Error` with the original cause preserved in the error chain.

The required test, race, real-database, lint, release-gate, and CodeQL checks pass for the release candidate. An additional full-lint canary remains non-blocking while third-party analyzer IR support catches up with the Go 1.27 release candidate.
