# Credo v0.16.0

Credo v0.16.0 is the **architecture seams** release: an internal refactor that
gives the kernel and feature packages clearer boundaries, a small batch of
breaking API clean-ups announced below with migration notes, and three
additive operational features — a per-worker readiness policy, a route
pattern attribute in access logs, and redaction-safe config copies. Credo
remains Beta and pre-1.0.

The root module and Bun SQL wrapper are published in lockstep:

| Module | Version |
| --- | --- |
| `github.com/credo-go/credo` | `v0.16.0` |
| `github.com/credo-go/credo/store/sqldb` | `v0.16.0` |

## Requirements and installation

This release requires Go 1.27.

```sh
go get github.com/credo-go/credo@v0.16.0
go get github.com/credo-go/credo/store/sqldb@v0.16.0
```

Applications that do not use SQL only need the root module.

## Breaking changes

Four changes require source updates. Each fails at compile time or at
construction (panic), never silently at request time.

### `middleware.Rewrite` takes a single `RewriteConfig`

`Rewrite(rules ...RewriteRule)` and `RewriteWithConfig(cfg)` are replaced by
one constructor that follows the package-wide config-struct convention. The
rule list lives in `RewriteConfig.Rules` next to the optional `Skipper`.

```go
// before
middleware.Rewrite(
    middleware.RewriteRule{From: "/v1/{path...}", To: "/api/v1/{path}"},
)

// after
middleware.Rewrite(middleware.RewriteConfig{
    Rules: []middleware.RewriteRule{
        {From: "/v1/{path...}", To: "/api/v1/{path}"},
    },
})
```

A malformed `From` pattern now panics when the middleware is built instead of
being matched literally.

### `App.Mux()` removed

`*App` satisfies the `Routes` introspection interface directly. Replace
`credo.Walk(app.Mux(), fn)` with `credo.Walk(app, fn)` (same for
`WalkRoutes`).

### `auth.Middleware` panics on a nil authenticator

A missing authenticator is a wiring error and now fails fast at construction
(`auth: Middleware requires a non-nil authenticator`) instead of turning every
request into a 401. The reflection-based typed-nil probe and the
`auth.ErrAuthenticatorRequired` sentinel are removed.

### CORS `AllowOrigins` uses the strict shared origin grammar

`CORSConfig.AllowOrigins` entries are parsed with the same rules as the
websocket adapter's `AllowedOrigins`: `scheme://host[:port]`, `http`/`https`
only, no path, query, fragment, or userinfo, case-insensitive host, implied
default port, and at most one wildcard standing for exactly the left-most DNS
label. `https://*.example.com` matches `https://app.example.com` but not
`https://example.com` or `https://a.b.example.com`.

The former prefix/suffix glob (a `*` anywhere, such as
`https://api-*-prod.example.com`) and blank entries are gone; invalid entries
panic when `middleware.CORS` is built. A matched origin is echoed back in the
request's own serialization, and a malformed `Origin` header never matches.
`"*"` and `AllowOriginFunc` are unchanged.

## Worker readiness policy

`worker.WithReadiness` binds a worker to the readiness probe under explicit,
opt-in conditions. Nothing is bound by default — a failed metrics reporter must
not take an instance out of rotation.

```go
worker.MustRegister(app, recovery,
    worker.WithSchedule("@every 5m"),
    worker.WithStartImmediately(),
    worker.WithReadiness(worker.ReadinessPolicy{
        RequireFirstSuccess: true,             // startup barrier
        FailWhenFailed:      true,             // unready once the failure threshold is exhausted
        MaxSuccessAge:       15 * time.Minute, // unready when the last success is too old
    }),
)
```

`RequireFirstSuccess` stays satisfied once met; `MaxSuccessAge` is not applied
before the first success; both are scheduled-worker conditions, while
`FailWhenFailed` applies to every kind. The contribution is reported in the
`/ready` body as a check named `worker:<name>`, sharing the name space of
`AddReadinessCheck` (collisions fail closed). `worker.Register` and
`app.UseHealth()` may run in either order. `worker.Info` gains `LastSuccess`.

## Access-log route pattern

`AccessLogEntry.Route` carries the matched route's registered pattern
(`/v1/jobs/{job_id}`) and is emitted as the `route` attribute by both the
built-in access logger and `middleware.AccessLog` whenever a route matched.
Deployments that must not persist identifiers from concrete paths can keep
this value-free attribute and drop `path`/`path_original` in the slog handler
passed to `WithAccessLogLogger`; Credo adds no field transformer of its own.

## Redaction-safe config copies

`config.Config` keeps its state behind one private pointer and declares
`String`, `GoString`, and `LogValue` on the value type, so formatting or
logging a dereferenced copy (`*cfg`) is redacted exactly like the pointer.
Copying a `Config` no longer copies a mutex. A nil `*Config` formats as fmt's
usual `<nil>`.

## Lifecycle and documentation

- `App.OnStart` and `App.OnShutdown` now panic at registration when given a
  nil hook, matching the other hook registrars; post-compile registration
  panics name the API as `Type.Method`.
- Every public package closes its package documentation with a
  machine-readable `// Maturity: <label>` line aligned with the README's
  "Maturity by Area" table, enforced by `maturity_test.go`.
- The README-only placeholder directories `observability/`, `pubsub/`,
  `grpc/`, and `openapi/` are removed; planned areas live in `TODO.md`.

## Internal architecture refactor

The kernel and feature packages were reorganized behind clearer seams with no
public API change: `internal/faultstatus`, `internal/observe`,
`internal/pattern`, `internal/origin`, `internal/static`, and the
`internal/health` engine; a `routeRegistrar` interface between routes and the
app; typed option overlays and phase-split `New`/`serve`; a provider model and
framework-provider seam in the DI container; a single pending-reservation
ledger in `store.Registry`; per-driver `sqldb` error classifiers; a
policy-driven worker loop; closure-based validation rules; and a split
websocket handshake. `architecture_test.go` pins the allowed in-module import
matrix.

## Unchanged

Routing, context, binding, the error envelope, configuration loading, store
contracts, and the reload model carry over as they are. `store/sqldb`
participates in this release through the internal classifier and count
refactors, which preserve its behavior and error texts, and the lockstep
version bump.
