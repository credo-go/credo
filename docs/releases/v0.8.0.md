# Credo v0.8.0

Credo v0.8.0 makes the underlying `http.Server` reachable. Until now the framework mapped a fixed set of fields from configuration and left the rest of the standard library's surface unavailable, so every field Go added implied a Credo release. This one option ends that. The project remains Beta and pre-1.0. Everything here is additive — no source changes are required.

The root module and Bun SQL wrapper are published in lockstep:

| Module | Version |
| --- | --- |
| `github.com/credo-go/credo` | `v0.8.0` |
| `github.com/credo-go/credo/store/sqldb` | `v0.8.0` |

## Requirements and installation

This release requires Go 1.27.

```sh
go get github.com/credo-go/credo@v0.8.0
go get github.com/credo-go/credo/store/sqldb@v0.8.0
```

Applications that do not use SQL only need the root module.

## Highlights

- **`credo.WithHTTPServer(fn func(*http.Server))`** ([ADR-006](../adr/006-application-lifecycle.md)) — a callback that receives the server the framework built, so `Protocols` (including H2C), `HTTP2`, `ConnState`, `BaseContext`, `ConnContext`, `TLSNextProto`, and `DisableClientPriority` are all reachable without an option per field. It runs after every framework-set field — timeouts, `MaxHeaderBytes`, `MaxHeaderValueCount`, the `ErrorLog` bridge — so it is the last word on all of them, config keys included.
- **Three fields stay framework-owned** and are re-imposed when the callback returns: `Handler` (the App is the router; a replacement would bypass the middleware tiers, the error pipeline, and route introspection while the App still reported itself as serving), `Addr` (the listener is bound from it and `app.Addr()` reports it), and `TLSConfig`. TLS keeps its documented precedence chain: a Credo TLS source overwrites the callback's value at startup, and with no Credo TLS source the server runs under `Serve`, which ignores `TLSConfig` — a callback can never quietly upgrade a listener the operator configured as plaintext. The `WithHTTPRedirect` listener is a fixed-function 301/308 responder and is deliberately excluded.
- **`server.max_header_value_count`** — Go 1.27's `http.Server.MaxHeaderValueCount` as a config key, for parity with `max_header_bytes`: both are operational integers tuned per environment. Zero keeps net/http's own default of 500 rather than freezing a number into Credo; a negative value is rejected by `credo.New`, because net/http reads everything below 1 as the default and a typo would otherwise silently do nothing. Requests over the limit receive `431`, written straight to the connection by `net/http` and therefore never logged — count them at a proxy or through a `ConnState` hook.
- **`ServeContext`'s H2C claim is now true.** Its documentation listed H2C among the listeners it enables, but it supplies the listener only; the server still came from the framework, so `Protocols` was unreachable and H2C could not be served at all. It works through `WithHTTPServer`, and a test proves it end to end.

## Serving H2C

```go
app, err := credo.New(credo.WithHTTPServer(func(s *http.Server) {
	s.Protocols = new(http.Protocols)
	s.Protocols.SetHTTP1(true)
	s.Protocols.SetUnencryptedHTTP2(true)
}))
```

That works under `Run`, `RunContext`, and `ServeContext` alike. Applications that could not previously enable H2C or tune HTTP/2 stream limits now do so here; nothing else changes.

## Upgrade notes

No source changes are required, and no wire behavior changes on its own. Two things are worth knowing:

- The callback is the last word, so a value it sets overrides the matching config key. If an application sets, say, `ReadTimeout` both in `server` config and in the callback, the callback wins.
- Everything set through the callback is restart-only. The `*http.Server` is built once per session, so a reload cannot change it; `max_header_value_count` behaves the same way and reports "restart required" like the other server keys.

The required test, race, real-database, lint, release-gate, and CodeQL checks pass for the release candidate. An additional full-lint canary remains non-blocking while third-party analyzer IR support catches up with Go 1.27.
