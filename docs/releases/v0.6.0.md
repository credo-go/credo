# Credo v0.6.0

Credo v0.6.0 hardens request handling: an application can opt into rejecting unknown JSON members, a `ContractGuard` switch closes the "body without a `Content-Type`" gap, and `time.Duration` fields bind again. Under the hood, every internal JSON decode now runs on `encoding/json/v2`. The project remains Beta and pre-1.0; there are no intentional behavioral breaks for HTTP clients in this release.

The root module and Bun SQL wrapper are published in lockstep:

| Module | Version |
| --- | --- |
| `github.com/credo-go/credo` | `v0.6.0` |
| `github.com/credo-go/credo/store/sqldb` | `v0.6.0` |

## Requirements and installation

This release requires Go 1.27.

```sh
go get github.com/credo-go/credo@v0.6.0
go get github.com/credo-go/credo/store/sqldb@v0.6.0
```

Applications that do not use SQL only need the root module.

## Highlights

- **Strict request bodies (opt-in)** — `credo.WithStrictBodies()` or `server.strict_bodies: true` makes `Request.BindBody` reject JSON object members that map to no field of the target, with the usual 400 RFC 7807 response and the new reason `unknown_field` (`BindReasonUnknownField`, i18n key `bind.unknown_field`, member path and byte offset included). The default stays lenient: unknown members are ignored, which is the right posture for public or versioned APIs whose clients deploy independently. Enable it where client and server ship together and a misspelled member should fail loudly rather than silently drop. The switch is app-wide (one posture per service, no per-call option) and affects JSON only; XML and form decoders are unchanged. Case-insensitive member matching still runs first, so `{"Name": …}` binds to a `name` field, and a repeated known member is reported as `duplicate_field`. [ADR-008](../adr/008-context-design.md) is revised accordingly.
- **`ContractConfig.RequireContentType`** — by default a request without a `Content-Type` header passes a route's `MetaAccept` contract. With `RequireContentType: true`, a request that carries a body (positive or unknown `Content-Length` — chunked transfer and HTTP/2 streams included) but no or an empty `Content-Type` is rejected with 415. Bodiless requests (`GET`, `Content-Length: 0`) and routes without `MetaAccept` are unaffected, so the switch arms a declared contract rather than adding a new one. Services that hand-rolled a missing-`Content-Type` check can replace it with `middleware.ContractGuard(middleware.ContractConfig{RequireContentType: true})`. Flipping the default is a v1 item.
- **`time.Duration` binding fixed** — since v0.4.0 any bind target with a `time.Duration` field failed every request with 400 `invalid_value`: `encoding/json/v2` has no default Duration representation, and Go 1.27 ships without the `format:` struct-tag option (removed before the v2 GA, go.dev/issue/79071), so no tag could work around it. `BindBody` now enables the v1-compatible `FormatDurationAsNano` option: `{"timeout": 5000000000}` binds 5s, a string fails with `type_mismatch`. Human-readable durations (`"5s"`) are best expressed as a named type implementing `encoding.TextUnmarshaler`.
- **`encoding/json/v2` for internal decoding** — JSON configuration files, i18n locale files, `testutil` log assertions, and the release gate now decode with json/v2. `validation.Errors` additionally implements the v2 `MarshalJSONTo` interface (`MarshalJSON` is unchanged). Response encoding (`Response.JSON`, Problem Details) is untouched in this release; the json/v2 output profile is planned as its own release.

## Upgrade notes

No source changes are required. Two behavioral differences are worth knowing:

- JSON configuration files and JSON locale files now reject duplicate object members and invalid UTF-8 at load time instead of taking the last value or substituting U+FFFD. A file with a repeated key fails `config.Load` with a syntax error naming the member.
- Targets with `time.Duration` fields, which previously could not be bound at all, now accept integer nanoseconds. Clients that were sending such fields and receiving 400 will start succeeding.

Enabling `server.strict_bodies` is a deliberate contract change for your clients: review the API surface for fields clients may send that the server does not model before turning it on.

The required test, race, real-database, lint, release-gate, and CodeQL checks pass for the release candidate. An additional full-lint canary remains non-blocking while third-party analyzer IR support catches up with Go 1.27.
