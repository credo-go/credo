# Credo v0.15.0

Credo v0.15.0 is the **hermetic & strict configuration** release: four
additive, opt-in features for deployments where configuration must come from a
known file and nothing else. Defaults are unchanged everywhere — existing
applications upgrade without source or behavior changes. Credo remains Beta
and pre-1.0.

The root module and Bun SQL wrapper are published in lockstep:

| Module | Version |
| --- | --- |
| `github.com/credo-go/credo` | `v0.15.0` |
| `github.com/credo-go/credo/store/sqldb` | `v0.15.0` |

## Requirements and installation

This release requires Go 1.27.

```sh
go get github.com/credo-go/credo@v0.15.0
go get github.com/credo-go/credo/store/sqldb@v0.15.0
```

Applications that do not use SQL only need the root module.

## Hermetic config loading

`config.WithoutProcessEnv()` and `config.WithoutDotenv()` disable the
process-environment and `.env` sources entirely, bootstrap keys included:
`WithoutProcessEnv` also ignores the env-sourced `CREDO_ENV` and
`CREDO_ENV_FILE`, and `WithoutDotenv` never reads a `.env` file from any path.

```go
rawCfg, err := config.Load(
    config.WithFiles("config.json"), // required: Load fails if missing
    config.WithoutProcessEnv(),
    config.WithoutDotenv(),
)
```

With both set, only the listed files (or the `LoadBytes` document) are read —
a stray `.env` in the working directory or a `CREDO_*` variable in the
environment can no longer alter configuration. `Reload`/`Stage` replay the
opt-outs, so a disabled source cannot leak in at reload time.
`WithoutDotenv` combined with `WithDotenvPath` is rejected as contradictory.

Note that `config.WithPrefix("")` is not — and has never been — a way to
disable environment variables: an empty prefix removes the filter and merges
every process environment variable. Disabling is now its own explicit option.

## Strict typed decoding

`config.WithStrictDecoding()` makes every typed decode from the store strict:
unknown keys (nested sections included) are errors that name the offending key
path, and weak string coercion (`"123"` → int, `"true"` → bool) is off.
Duration strings (`"5s"`), `encoding.TextUnmarshaler` fields, and native
numeric conversions (a JSON number into an int field) keep decoding.

The policy rides on the Config instance, so one option covers
`Unmarshal`/`Get`/`MustGet`, the `Stage` candidate (and therefore
`OnConfigChange` reload subscriber validation), and the framework's own decode
of the `server` section in `credo.New` — a typo under `server.*` fails startup
instead of silently using a default.

Strict decoding targets typed sources and pairs with the hermetic opt-outs
above: string env/`.env` overrides on typed fields do not decode under strict
mode, and every struct that decodes a section must cover all of that section's
keys. Unknown-key errors never contain configuration values; type-mismatch
errors may quote the offending value. The default remains weak decoding;
whether strict becomes the default at v1 is tracked in the v1 Gate.

## Reload-signal opt-out

`credo.WithoutReloadSignals()` disables SIGHUP-triggered reloads under
`Run()` with subscribe-and-ignore semantics: the signal is still captured, so
a stray SIGHUP (logrotate postrotate, a forgotten `ExecReload`) can never fall
through to its default action and terminate the process, but it is logged at
Info instead of triggering `App.Reload`. SIGINT/SIGTERM shutdown handling and
programmatic `App.Reload` are unaffected; the option is a no-op on Windows.

The three signal policies are each one API away: reload (`Run`, the default),
logged no-op (`Run` + `WithoutReloadSignals`), and raw Unix disposition
(`RunContext`/`ServeContext`, which install no signal handlers).

## Redacted config formatting

`*config.Config` now implements `String()`, `GoString()`, and
`slog.LogValuer` with a metadata-only description —
`config.Config(N keys, values redacted)` — so formatting a Config with fmt
verbs or logging it as an slog attribute can never leak configuration values
or key names, mirroring the existing `Changes` doctrine of keys-only logging.

## Unchanged

Source precedence, discovery, env-specific file derivation, `.env` semantics,
weak decoding as the default, `Run`'s SIGINT/SIGTERM handling, and the reload
model all carry over as they are. `store/sqldb` participates in this release
only through the lockstep version bump.
