# Credo v0.5.0

Credo v0.5.0 makes a running service reloadable: `systemctl reload` / `SIGHUP` (or a programmatic `app.Reload`) re-reads the configuration, hands each changed section to a typed subscriber after validating it, and rotates file-based TLS certificates — all without dropping connections. This release also moves the project to the Go 1.27 GA toolchain. The project remains Beta and pre-1.0; there are no intentional behavioral breaks in this release.

The root module and Bun SQL wrapper are published in lockstep:

| Module | Version |
| --- | --- |
| `github.com/credo-go/credo` | `v0.5.0` |
| `github.com/credo-go/credo/store/sqldb` | `v0.5.0` |

## Requirements and installation

This release requires Go 1.27 (GA). The repository no longer pins a release-candidate toolchain.

```sh
go get github.com/credo-go/credo@v0.5.0
go get github.com/credo-go/credo/store/sqldb@v0.5.0
```

Applications that do not use SQL only need the root module.

## Highlights

- **`app.Reload(ctx)` and `SIGHUP`** — a trigger-driven partial reload ([ADR-020](../adr/020-reload-and-partial-config-reload.md)). Under `app.Run()` on Unix, `SIGHUP` now calls `Reload` within `WithReloadTimeout` / `server.reload_timeout` (default 30s) instead of terminating the process; signals arriving mid-reload coalesce, and a failed reload is logged but never stops the server. `RunContext` and `ServeContext` stay signal-free; there is no `SIGHUP` on Windows, where the programmatic `Reload` is the only trigger.
- **Typed per-section subscribers** — `app.OnConfigChange[T](key, fn)` registers a subscriber that receives `T` re-decoded from the new snapshot whenever a leaf under `key` changes. Every affected `T` is decoded — and validated, when it has a `Validate() error` method — from a staged candidate *before* anything is published, so a bad edit aborts the reload with the old snapshot untouched. Subscriber errors and recovered panics are joined and returned; later subscribers still run. Changed keys with no subscriber are logged once at `WARN` as `restart required` (key paths only). `app.OnReload(fn)` hooks run FIFO on every reload.
- **File-based TLS certificate rotation** — `WithTLSFiles` and `server.tls.*` now serve the key pair through `GetCertificate` backed by an atomic pointer and re-read it on every reload. Rotating a certificate in place needs no config change; changing the `server.tls.*` paths moves the pair on the next reload. New handshakes see the new certificate immediately, open connections are untouched, and a pair that fails to load keeps the current certificate serving. `WithTLSConfig` is never touched.
- **`config` reload primitives** — `*config.Config` implements `config.Reloader` (`Reload() (Changes, error)`) and the two-phase `config.Stager` (`Stage() (Staged, error)`; `Staged` is a `RawConfig` over the candidate plus `Changes()` and `Commit()`). `Changes` is the sorted symmetric difference of leaf key paths (values are never retained) with `Affects(prefix)`, `Keys()`, and `Empty()`. Concurrent readers observe either the old or the new snapshot, never a mix; `CREDO_ENV` is fixed at first load. A custom `WithRawConfig` store opts in by implementing either interface.
- **Deployment guide** — the new [`docs/guides/deployment.md`](../guides/deployment.md) covers the signal table, a systemd unit with `ExecReload`, `TimeoutStopSec` versus `WithShutdownTimeout`, the `EnvironmentFile=` caveat, container and Kubernetes idioms, the certbot deploy hook, and an admin-endpoint pattern for synchronous reload failures. The configuration guide gained a "Reloading Configuration" section and a **Reloadable** column in the server reference.
- **Go 1.27 GA** — the modules, CI, and CodeQL workflows select the toolchain from `go.mod` (`go 1.27`) with no RC pin. Dependency bumps: go-limiter v1.2.0, `golang.org/x/text` v0.41.0, modernc.org/sqlite v1.56.0.

## Upgrade notes

No source changes are required. Two behavioral differences are worth knowing:

- `SIGHUP` under `app.Run()` used to terminate the process (Go's default). It now triggers a reload. Supervisors that relied on `SIGHUP` as a stop signal should use `SIGTERM`.
- `WithTLSFiles` / `server.tls.*` no longer populate `tls.Config.Certificates`; the pair is served through `GetCertificate`. This is only observable to tests that inspected the resolved config's `Certificates` slice.

`OnConfigChange` panics at registration when the app's `RawConfig` implements neither `config.Stager` nor `config.Reloader` — a subscription that could never fire is a startup bug, consistent with the framework's panic-vs-error policy. Everything else about reload is an error: `Reload` before the server is running, a failed re-read, a failed validation, or a failed subscriber.

The required test, race, real-database, lint, release-gate, and CodeQL checks pass for the release candidate. An additional full-lint canary remains non-blocking while third-party analyzer IR support catches up with Go 1.27.
