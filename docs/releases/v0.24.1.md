# Credo v0.24.1

Credo v0.24.1 is a bug-fix release for the lifecycle components of [v0.24.0](v0.24.0.md). It fixes three defects in how the App treats one resource that several bindings hold: the resource was started once per holder — a borrowed one included, through a wrapper over it; a holder that reached the resource through one of its consumers kept both from shutting down; and a value the container refused after its constructor built it was never released. Each fix changes what an application can observe — read [Check this first](#check-this-first). No exported API is added, removed or renamed. Credo remains Beta and pre-1.0.

The root module and Bun SQL wrapper are published in lockstep:

| Module | Version |
| --- | --- |
| `github.com/credo-go/credo` | `v0.24.1` |
| `github.com/credo-go/credo/store/sqldb` | `v0.24.1` |

## Requirements and installation

This release requires Go 1.27.

```sh
go get github.com/credo-go/credo@v0.24.1
go get github.com/credo-go/credo/store/sqldb@v0.24.1
```

Applications that do not use SQL only need the root module. `store/sqldb` has no code changes; its `go.mod` follows the root module.

## Check this first

| If your application… | In v0.24.0 | From v0.24.1 |
| --- | --- | --- |
| binds one resource whose type has `Start` under several types — the pointer and an interface an adapter constructor returns, or the handle and a wrapper that embeds it | `Start` ran once per binding whose type showed it | the resource is started once, through the first holder the start walk reaches whose binding plans a `Start` |
| binds a resource with `credo.Borrowed()` and also builds a wrapper over it whose type shows `Start` | the App started the borrowed resource through the wrapper, and never stopped it | the resource is not started: a borrowed resource is the caller's to start and to stop, through every holder |
| binds an interface view of a resource through a constructor that reads it from a service using that resource | neither the service nor the resource was shut down; the drain reported each as `kept_open` by the other | the service stops first, then the resource, once |
| has a constructor whose value the container refuses after it returned — a `ResourceIdentity` that returns an unusable token, or a component found only on its built value that depends on an ingress one | the construction failed and the value was dropped without its `Shutdown` or `Close` | the construction still fails, and the drain releases the value in order when no other holder carries it |

## Fixed: a shared resource is started once

[ADR-024](../adr/024-lifecycle-components.md#resource-identity-one-resource-one-teardown) makes the values that share a resource identity one component with one teardown. The start walk did not apply the same identity: it called `Start` for every binding whose type showed the method, so a resource bound as its pointer and as an interface an adapter constructor returns, or as a handle and a wrapper that embeds it, was started twice and shut down once.

```go
app.ProvideValue(pool) // *Pool has Start and Shutdown
app.Provide[PoolView](func(p *Pool) PoolView { return p }) // the same pointer
```

`Start` now runs once per resource, through the first holder the walk reaches whose binding plans a `Start`. A resource that any holder borrows is not started at all. `credo.Borrowed()` promises that the caller starts and stops the value, but a constructor that wrapped a borrowed handle — `type OrdersPool struct{ *Pool }` — showed `Start` through the embedding, and the App started the caller's resource while it still left the teardown to the caller.

## Fixed: a holder that reaches the resource through a consumer keeps the drain order

The drain groups the holders of one resource into one component, which waits for the consumers of every holder. It also took on every holder's dependencies, so a holder that obtained the resource through one of its consumers made the resource wait for that consumer while the consumer waited for the resource:

```go
app.ProvideValue(producer) // *Producer, a component
app.Provide[*OrderService](NewOrderService) // func(*Producer) *OrderService
app.Provide[EventPublisher](func(s *OrderService) EventPublisher {
	return s.Producer() // the same *Producer
})
```

`Finalize` accepted the graph, and `Shutdown` stopped neither the service nor the producer; the `*credo.LifecycleError` reported each as `kept_open` by the other. A dependency that would close such a cycle, contributed by a holder that reached the resource through another holder, is that holder's route to a value it shares, not something the resource's teardown needs, so it is dropped: the service stops first, then the producer. Every other dependency holds: a holder's own — what a wrapper's own fields use — and a real dependency between two groups. When the service is itself bound under a second view as well, its dependency on the producer still orders the drain, whichever is registered first.

## Fixed: a value the container refuses is released

A constructor can return a value that the container then refuses: its `ResourceIdentity` returns a token that is nil or not comparable, or it is a component found only on its built value that depends on an ingress one. The construction fails, and the value was dropped although only the App ever held it, so its `Shutdown` or `Close` never ran. The drain now releases such a value in dependency order, or the single bounded late cleanup does when its construction completed after the drain's deadline.

A value refused because its holders disagree — on `Shutdown` against `credo.Closer()`, or on the owner when another holder is borrowed — is not released: it is the shared resource itself, and releasing it would close what its owner still holds.

## Unchanged

Everything else is as in [v0.24.0](v0.24.0.md): the component model, the registration options, the tiers, the bootstrap order and the DI surface. The full list of changes is in the [CHANGELOG](../../CHANGELOG.md).
