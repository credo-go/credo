# Credo v0.17.0

Credo v0.17.0 is the **request body encoding** release: binding now fails loud on a compressed body it was never asked to decode, developer errors in bind targets stop masquerading as client errors, and the new `middleware.Decompress` is the deliberate, bounded opt-in for accepting compressed uploads. It also carries the small follow-ups from the GoFr v1.60.0 and Echo v5.1.0–v5.3.1 reviews. Credo remains Beta and pre-1.0.

The root module and Bun SQL wrapper are published in lockstep:

| Module | Version |
| --- | --- |
| `github.com/credo-go/credo` | `v0.17.0` |
| `github.com/credo-go/credo/store/sqldb` | `v0.17.0` |

## Requirements and installation

This release requires Go 1.27.

```sh
go get github.com/credo-go/credo@v0.17.0
go get github.com/credo-go/credo/store/sqldb@v0.17.0
```

Applications that do not use SQL only need the root module.

## Breaking changes (wire)

Two response contracts change. Neither affects compilation.

### Undecoded `Content-Encoding` is 415, not 400

`Request.BindBody` rejects a request whose `Content-Encoding` is anything other than `identity` with **415 Unsupported Media Type** and the code `unsupported_content_encoding` (`credo.CodeUnsupportedContentEncoding`) before any decoder runs. Previously the compressed bytes reached the JSON decoder and came back as a misleading 400 `bind_failed`/`syntax`.

Applications that accept compressed bodies opt in per route or group:

```go
app.Group("/ingest").Middleware(middleware.Decompress())
```

Clients that never send `Content-Encoding` see no difference.

### Invalid bind targets are 500, not 400

A nil or non-pointer bind target (and a non-struct target for query/form binding) is a developer error. `BindBody`/`BindQuery` now return **500** with the code `invalid_bind_target` (`credo.CodeInvalidBindTarget`); the reason is logged as the error's internal cause and never reaches the client. Previously it was a 400 whose message exposed the developer-error text.

## Request decompression

`middleware.Decompress(cfg ...DecompressConfig)` unwraps `gzip` (and `x-gzip`) and `deflate` (zlib-wrapped per RFC 9110, raw DEFLATE tolerated) request bodies using only the standard library.

```go
app.Group("/ingest").Middleware(middleware.Decompress(middleware.DecompressConfig{
    MaxBytes: 16 << 20, // bound on the decompressed body; default 4 MiB
}))
```

The decompressed stream is wrapped in `http.MaxBytesReader(MaxBytes)`, so reading past the bound fails with the same 413 as any oversized body; the server-wide `max_body_bytes` keeps bounding the compressed wire bytes. The middleware removes `Content-Encoding` and sets `ContentLength` to -1 before the handler runs, so `BindBody` and handlers see a plain stream. Unsupported codings (`br`, `zstd`, or a list such as `gzip, br`) return 415 with the same code as above; a corrupt stream header returns 400 `bind_failed`; a body declared empty passes through with the header dropped; a negative `MaxBytes` panics at construction. Multiple gzip members are not concatenated.

Why not by default: decompression turns a small wire body into a potentially huge one, so accepting compressed uploads must be a deliberate decision with its own bound.

## Follow-ups from upstream reviews

- **Access-log cost gate.** Both access-log producers return before building the attribute set when the target logger is not enabled for the record's level, so a Warn-only access logger no longer pays per-request attribute cost for 2xx traffic.
- **Content-Type fallback.** When `mime.ParseMediaType` rejects malformed parameters, `BindBody` now takes the bare type, trimmed and lowercased (RFC 9110 case-insensitive matching), so `Application/JSON; charset` still decodes as JSON instead of returning 415.
- **CI hardening.** Workflow-level concurrency groups cancel superseded PR runs, every job carries a timeout, and every action is pinned to a full commit SHA.
- **Docs.** CORS behind a reverse proxy (one layer must answer), and a configuration-guide note that formatting or logging a `Config` is always redacted.

## Unchanged

Routing, context, the error envelope, configuration loading, store contracts, the worker pool, and the reload model carry over as they are. `store/sqldb` participates in this release only through the lockstep version bump.
