# Credo v0.20.1

Credo v0.20.1 is a patch release for the `worker` package: one fix to how a run that ends during shutdown is classified, and a correction to the v0.20.0 migration notes. There are no API changes. Credo remains Beta and pre-1.0.

The root module and Bun SQL wrapper are published in lockstep:

| Module | Version |
| --- | --- |
| `github.com/credo-go/credo` | `v0.20.1` |
| `github.com/credo-go/credo/store/sqldb` | `v0.20.1` |

## Requirements and installation

This release requires Go 1.27.

```sh
go get github.com/credo-go/credo@v0.20.1
go get github.com/credo-go/credo/store/sqldb@v0.20.1
```

Applications that do not use SQL only need the root module. `store/sqldb` is unchanged apart from its root-module requirement.

## v0.20.0 documentation correction: `restart` is now `restarts`

The v0.20.0 notes and migration tables missed one log change. If you upgraded to v0.20.0 and query or alert on worker logs, check this:

| Before v0.20.0 | From v0.20.0 |
| --- | --- |
| log attribute `restart` on the continuous `worker run failed` line: the number of failed runs, `1` on the first failure | `restarts`, equal to `Info.Restarts`: the restarts that actually started, `0` on the first failure |

The behavior shipped in v0.20.0 and is unchanged here; only the documentation was incomplete. The [CHANGELOG](../../CHANGELOG.md), the [pre-v1 migration guide](../guides/pre-v1-migration.md#workers) and the in-repository v0.20.0 release notes now carry the row.

## Fixed: an error joined with the shutdown cancellation is a failure

A worker that finishes its last work while the application stops may report both facts at once:

```go
<-ctx.Done()
return errors.Join(ctx.Err(), flushErr)
```

This used to be classified as a graceful stop, because one branch of the joined error matched `context.Canceled`: the worker ended as `stopped` with no failure line, no counter change and an empty `LastError`, and the failed final write was lost. The gap predates v0.20.0.

A return value is now a graceful stop only when it is nil or nothing but a context error — every branch of its unwrap/join tree must end in `context.Canceled` or `context.DeadlineExceeded`:

- A single wrap chain is still graceful: `fmt.Errorf("query: %w", ctx.Err())`, a `*url.Error` around a cancelled dial, a join of several context errors.
- A joined error that carries any other error is a failure, recorded and logged with its full text. This includes `errors.Join(ctx.Err(), flushErr)` and `fmt.Errorf("%w: %w", ErrFlush, ctx.Err())` — `ErrFlush` alone would have been a failure too.
- An error that wraps others is judged by what it wraps, never by its own `Is` method; `Is` is honored on errors that wrap nothing.

What you may notice after upgrading: a worker that returns such an error during shutdown now writes one Error line (`worker run failed` or `scheduled worker run failed`) and keeps the error in `LastError`; a scheduled worker's `ConsecutiveFailures` advances, and the worker ends as `failed` if that exhausts `WithMaxConsecutiveFailures` or `WithMaxRestarts`. The loop ends either way. If the second error is only noise caused by the cancellation, return `ctx.Err()` alone.

## Documentation

The worker guide now states that a run timeout and a shutdown are told apart by which came first: when the timeout fires first and shutdown follows, the cause stays `ErrRunTimeout` and the run is a timed-out failure, nil return included. The [worker spec](../specs/worker.md) and [ADR-023](../adr/023-worker-system.md) record the graceful-stop rule above.

## Unchanged

Registration, options, the `Info` snapshot and its JSON, run timeouts, restart and failure limits, log messages and readiness integration are as in [v0.20.0](v0.20.0.md).
