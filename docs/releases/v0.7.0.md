# Credo v0.7.0

Credo v0.7.0 finishes the move to `encoding/json/v2`: JSON responses and RFC 7807 Problem Details now encode under a documented, overridable profile. It also closes an observability gap — the standard library's own server diagnostics were going to stderr instead of your logger. The project remains Beta and pre-1.0. This release contains **intentional wire changes** for JSON responses; see the upgrade notes.

The root module and Bun SQL wrapper are published in lockstep:

| Module | Version |
| --- | --- |
| `github.com/credo-go/credo` | `v0.7.0` |
| `github.com/credo-go/credo/store/sqldb` | `v0.7.0` |

## Requirements and installation

This release requires Go 1.27.

```sh
go get github.com/credo-go/credo@v0.7.0
go get github.com/credo-go/credo/store/sqldb@v0.7.0
```

Applications that do not use SQL only need the root module.

## Highlights

- **JSON responses encode with `encoding/json/v2`** ([ADR-021](../adr/021-json-output-profile.md)). `Response.JSON`, `Context.Render`'s fallback, and both Problem Details writers share one application-level profile. Two axes are set by the framework: map keys are sorted (`Deterministic`, matching what v1 always did — byte-stable responses, golden files, and diffs) and `time.Duration` encodes as integer nanoseconds. The Duration decision is forced by the standard library: json/v2 has no default Duration representation, and the `format:` struct tag was removed before the v2 release (go.dev/issue/79071), so without this option any response carrying a Duration would fail to encode. It also mirrors `BindBody`, which decodes nanoseconds, so a Duration round-trips unchanged.
- **`credo.WithJSONOptions(opts ...jsonv2.Options)`** — the escape hatch. Options are applied after the framework profile, so each one overrides that axis and leaves the rest intact: `jsonv2.FormatNilSliceAsNull(true)` restores `null` for empty arrays, `jsontext.EscapeForHTML(true)` restores `<` escaping, and `jsonv1.DefaultOptionsV1()` turns on full legacy mode. Construction-time only, with no per-call variant — one posture per application, the same rule as `WithStrictBodies`.
- **Problem Details stay deterministic.** RFC 7807 bodies re-apply sorted map ordering after the application profile, even when the application disabled it. Error bodies are a framework contract consumed by clients, translators, and tests.
- **`http.Server.ErrorLog` is bridged into the application logger.** The standard library reports TLS handshake failures, listener accept errors, panics that escape the framework recovery, and superfluous `WriteHeader` calls through `Server.ErrorLog`. That field was nil, so all of it went to the `log` package's stderr output, invisible to structured logging. Those records now arrive at `ERROR` with `component=net/http`, message text unchanged. The `WithHTTPRedirect` listener shares the bridge. Note that header-limit rejections (`431`) are written straight to the connection by `net/http` and are still never logged — the deployment guide documents this.

## Upgrade notes

**JSON response bytes change in four ways.** Each is opt-out per axis with `WithJSONOptions`; run your response snapshot tests against this release before upgrading a client that parses strictly.

| Change | Before | Now | Opt-out |
| --- | --- | --- | --- |
| nil slice / nil map | `null` | `[]` / `{}` | `jsonv2.FormatNilSliceAsNull(true)`, `jsonv2.FormatNilMapAsNull(true)` |
| `omitempty` | drops Go zero values | drops JSON-empty values (`""`, `null`, `[]`, `{}`); numbers and bools are always written | `jsonv1.OmitEmptyWithLegacySemantics(true)`, or switch the field to `omitzero` |
| `<` `>` `&` | escaped (`<`) | literal | `jsontext.EscapeForHTML(true)` |
| Trailing newline | `\n` after the value | none | no option restores it — the newline came from v1's streaming `Encoder` and was never part of the JSON value |

`jsonv1.DefaultOptionsV1()` restores the first three at once. If a client depends on `null` for empty arrays, prefer the single-axis option over full legacy mode so the rest of the profile keeps working.

Server diagnostics that previously appeared on stderr now flow through your logger. If a log pipeline was scraping stderr for `http: TLS handshake error`, point it at the structured records instead — filter on `component=net/http`.

No source changes are required.

The required test, race, real-database, lint, release-gate, and CodeQL checks pass for the release candidate. An additional full-lint canary remains non-blocking while third-party analyzer IR support catches up with Go 1.27.
