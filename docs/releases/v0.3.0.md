# Credo v0.3.0

Credo v0.3.0 adds policy controls for the framework's built-in and configurable HTTP access loggers. The project remains Beta and pre-1.0; existing access-log defaults are preserved.

The root module and Bun SQL wrapper are published in lockstep:

| Module | Version |
| --- | --- |
| `github.com/credo-go/credo` | `v0.3.0` |
| `github.com/credo-go/credo/store/sqldb` | `v0.3.0` |

## Requirements and installation

This release requires Go 1.27. At publication time Go 1.27 is pre-GA, so the repository selects `go1.27rc2`; a newer compatible Go 1.27 toolchain can be used when available.

```sh
go get github.com/credo-go/credo@v0.3.0
go get github.com/credo-go/credo/store/sqldb@v0.3.0
```

Applications that do not use SQL only need the root module.

## Highlights

- **Dedicated access-log sink** — `credo.WithAccessLogLogger` routes authoritative built-in access records to a separate `*slog.Logger` while preserving the standard fields and request ID.
- **Status-derived minimum level** — `credo.WithAccessLogMinLevel(slog.Leveler)` admits records at or above a dynamic threshold. Status still determines the emitted level: 1xx/2xx/3xx are Info, 4xx are Warn, and 5xx+ are Error. A concurrency-safe `slog.LevelVar` can update the threshold at runtime.
- **Post-response filtering** — `credo.WithAccessLogResultFilter` receives an immutable `credo.AccessLogEntry` snapshot containing request and observed result data. It runs after route-meta silencing and the minimum-level gate.
- **Configurable middleware parity** — `middleware.AccessLogConfig` now exposes `Logger`, `MinLevel`, `Skipper`, and `ResultFilter` for route/group-specific policies or a deliberate second sink.
- **Documented observation boundaries** — the built-in logger remains authoritative for final error-renderer status, bytes, and duration. `middleware.AccessLog` observes results at its configured middleware position.

## Upgrade notes

This release is additive and requires no migration. Existing applications continue to log all status classes by default, using Info for 1xx/2xx/3xx, Warn for 4xx, and Error for 5xx responses.

Use `WithAccessLogMinLevel(slog.LevelWarn)` to retain only 4xx/5xx records. Request-level exclusions belong in `WithAccessLogSkipper`; route/group exclusions belong in `credo.MetaAccessLog`; result-dependent decisions belong in `WithAccessLogResultFilter`.

The built-in access logger remains enabled by default. When adding `middleware.AccessLog`, keep both only when a second record or route/group-specific sink is intentional; otherwise disable the built-in with `credo.WithoutAccessLog()` to avoid duplicates.

The required test, race, real-database, lint, release-gate, and CodeQL checks pass for the release candidate. An additional full-lint canary remains non-blocking while third-party analyzer IR support catches up with the Go 1.27 release candidate.
