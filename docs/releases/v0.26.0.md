# Credo v0.26.0

Credo v0.26.0 is the **pre-v1 reshaping** release. It reshapes the contracts v1 will freeze so that each has one way to do each thing:

- An error has one status channel.
- A request value or a route meta entry is a typed key.
- Route meta is read after the match by a routed middleware tier.
- Configuration decodes strictly through typed section descriptors, and is live where it must follow a reload.
- The access log is one observer of the final response.
- The Context is not pooled.
- Validation names a field as the client sent it.
- JWT verification has its own package.
- `store/sqldb` counts only a query it can prove.

The parallel APIs left beside each contract go, and application modules are new.

The root module and Bun SQL wrapper are published in lockstep:

| Module | Version |
| --- | --- |
| `github.com/credo-go/credo` | `v0.26.0` |
| `github.com/credo-go/credo/store/sqldb` | `v0.26.0` |

## Requirements and installation

This release requires Go 1.27.

```sh
go get github.com/credo-go/credo@v0.26.0
go get github.com/credo-go/credo/store/sqldb@v0.26.0
```

Applications that do not use SQL only need the root module. `store/sqldb` requires `credo v0.26.0` exactly. No dependency moves in this release. An application that imports `auth` without `auth/jwtauth` no longer links `github.com/golang-jwt/jwt/v5`; the module stays a requirement of the root module.

## Check this first

The compiler finds every removed or renamed call ([What the compiler finds](#what-the-compiler-finds)). It does not find the changes below: code that builds as before and behaves differently. They are listed in order of how likely they are to reach a running application.

## One error channel

An error's status comes from:

- `*HTTPError`;
- `*fault.Error`, new in this release;
- the validation errors;
- `*BindError`;
- any other `fault.Provider`.

Anything else renders 500.

A domain layer returns `fault.New(fault.KindAlreadyExists, "domain_taken")`, and the handler returns it unchanged. The pipeline renders the kind's status with the fault's code and details, and logs `Internal`.

A message key is a `credo.MessageKey` the catalog defines, never text. Literal client text is `HTTPError.WithMessage`. `testutil.CheckMessageKeys` fails a test for each key in the sources that no catalog defines.

## Typed keys and one context head

`credo.NewKey[T](name)` makes a key that binds its type to its name. The same key reads a value with `c.Get`, reads a route's meta with `GetMeta`, and is the `context.Context` key that stdlib code reads with `ctx.Value`.

The request's values and its `context.Context` are one head. A value set inside `middleware.Timeout` or a wrapped stdlib middleware outlives the scope that set it. `c.Within(ctx, next)` runs the rest of the chain with a changed context. `Request.Std()` hands the request, with its current context, to stdlib code.

## A routed tier, and a mount is a route

The user tiers are PreRouting → routed → Group → Route:

- `app.PreRouting` (renamed from `GlobalMiddleware`) runs before the match, on every request, 404 and 405 included. CORS, `Rewrite`, Secure and rate limiting belong there.
- `app.Middleware` runs on every route and mount after the match. Authentication and `ContractGuard`, which read route meta, belong there. `ContractGuard` without a route fails closed.

A mounted request carries its mount as its route.

## Observers of the final response

`app.AddObserver(o)` adds an observer that sees each request's final `*credo.Exchange`. It runs after error rendering, recovery and compressor finalization, so the status, bytes, duration and classified `ErrorCode` agree with the access record. The access log is one such observer. Its `ResultFilter` takes the `Exchange`, and `AccessLogConfig.Attrs` adds application attributes in a reserved `attrs` group.

## Configuration: strict, typed and live

Configuration decodes strictly: an unknown key or a cross-kind value fails, naming the key path. `config.WithWeakDecoding()` is the opt-in to the previous coercion.

`config.Section[T]("app")` names a section and its type once:

- `app.Provide(AppSection.Decode)` binds a snapshot;
- `app.GetConfig(AppSection)` reads one during registration;
- `app.Provide(LimitsSection.Live)` binds a `*config.Live[T]`.

A reload validates every live section it changes before it publishes anything. It replaces those sections as one generation and then runs their `OnChange` callbacks. `App.Reload` returns a `config.ReloadResult` with what changed, what was replaced, what needs a restart and which file keys a later source overrides.

A section has one nature: reading it both as a snapshot and as live fails. Certificate files rotate when they change on disk.

## Validation by source, slices and nested values

A violation of a query or form bind names its field as the client sent it. A slice of structs is validated element by element. A field with rules validates its nested value once those rules pass.

## JWT in `auth/jwtauth`

The JWT authenticator and its types move to `auth/jwtauth`, with shorter names. An application that does not verify JWTs no longer compiles golang-jwt.

## `store/sqldb` through Bun's exported API

The wrapper reads no private Bun field. A Bun upgrade is checked by the count conformance tests, against SQLite and real PostgreSQL and MySQL.

`Count` and `Page` run Bun's native count, and only on a query whose total the wrapper can prove; anything else fails before I/O with `ErrUnsupportedCountQuery`, naming the remedy. That remedy is `PageWithCount[T](ctx, req, count)`, which pages with a count the repository supplies. `ApplyFilter(func(*sqldb.Filter))` scopes a select, an update and a delete with one predicate function. Only the wrapper's `Conn` chooses a connection.

## Application modules

`credo.Module` (`Services` and `Handlers`) and `app.UseModules(mods...)` register every module's services before any module's handlers resolve, whatever the order in which the modules are listed. `testutil.WithModules` places a test's overrides between the two phases.

## The last prunings

Each contract keeps one spelling, and the parallel APIs go:

- **Store transactions:** the type-only free functions and the `…InScope` functions go, so `store.TxScope`'s methods remain; `sqldb.RunInTx` and `RunInTxWith` go, so `db.InTx` and `InTxWith` remain.
- **Store sentinels:** `store.ErrDuplicate` and the `ErrConflict` umbrella go; each sentinel matches its own kind.
- **Routing introspection:** the `Walk` family and the `Routes` interface go; `app.Routes()` is the one introspection call.
- **Root internals:** the `RouteContext` alias and `Response.Reset` go, and so do `NewRequest` and `NewResponse`. `NewContext` stays, and its godoc names what a Context without an App lacks.
- **Rewriting:** `Context.Rewrite` and `IsRewriting` go, so a path is rewritten before routing or not at all.
- **Static URLs:** `StaticRoute.BuildURI(filePath string)` escapes each segment and returns an error for a path no URL can represent.

## The cost of an unpooled Context

The Context is one allocation of 896 bytes per request. At saturation behind `net/http` that costs 3.2% of throughput (144,374 → 139,755 requests per second), +1 allocation per request and no measurable latency change at 30,000 requests per second ([ADR-008](../adr/008-context-design.md#one-allocation-per-request)).

## What an application keeps

After the deletions, an application writes:

- an error with its status as an `*HTTPError` or a `fault.Error`;
- a catalog key, or `WithMessage`;
- typed keys made with `credo.NewKey[T]`;
- `c.Within` to change the request's context;
- `PreRouting` for what runs before the match, and `app.Middleware` for what reads route meta;
- `config.Section[T]` descriptors, a live section for what must follow a reload, and `WithWeakDecoding()` only by choice;
- a `ResultFilter` over the `*credo.Exchange`;
- `PageWithCount` for a query `sqldb` cannot count;
- a `store.TxScope` with `db.InTx`.

## Internal

- The ADRs and specs carry each decision of the pre-v1 reshaping, with its rejected alternatives. The specs v1 freezes (router, context, middleware with HTTP features, lifecycle and config, the error contract included) separate their normative contract from a closing Current Behaviour section that is not guaranteed; no contract changed in the move. Every other spec names its normative sections in a one-line header. The frozen specs' examples run as `Example*` tests with checked output, so a drift between a spec and the code fails the build.
- The guides name the handler's `*credo.Context` `c`, and read configuration through section descriptors.
- `examples/saas` keeps Secure and CORS on `PreRouting` and verifies its tokens with `auth/jwtauth`. It declares its log level a live section, while `app` stays static.
- The machine-code grammar is shared by the root and `fault` in `internal/machinecode`. The header, query and cookie credential extraction is shared by the API-key and JWT authenticators in `internal/credential`. `middleware.Rewrite` and the router share `internal/wirepath` and the matcher in `internal/pattern`.
- `architecture_test.go` pins that `auth`'s import graph has no golang-jwt, and `TestBunBoundary_NoUnsafe` that `store/sqldb` uses no `unsafe`.

## Unchanged

These are as in [v0.25.0](v0.25.0.md):

- the error envelope;
- binding, apart from the bind-target status;
- the router's matching;
- the built-in HTTP features, apart from the access log running as an observer;
- the lifecycle, DI and components;
- workers;
- `httpclient`;
- the API-key and Basic authenticators;
- the `store/sqldb` query API, apart from `Count`, `Page` and the removed functions.
