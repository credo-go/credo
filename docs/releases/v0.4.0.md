# Credo v0.4.0

Credo v0.4.0 makes request binding strict and structured: JSON bodies are decoded with Go 1.27's standard `encoding/json/v2` under strict semantics, and every decode failure now carries a typed, machine-readable reason rendered as RFC 7807 Problem Details. The project remains Beta and pre-1.0; this release contains deliberate behavioral breaks called out below.

The root module and Bun SQL wrapper are published in lockstep:

| Module | Version |
| --- | --- |
| `github.com/credo-go/credo` | `v0.4.0` |
| `github.com/credo-go/credo/store/sqldb` | `v0.4.0` |

## Requirements and installation

This release requires Go 1.27. At publication time Go 1.27 is pre-GA, so the repository selects `go1.27rc2`; a newer compatible Go 1.27 toolchain can be used when available.

```sh
go get github.com/credo-go/credo@v0.4.0
go get github.com/credo-go/credo/store/sqldb@v0.4.0
```

Applications that do not use SQL only need the root module.

## Highlights

- **Typed bind errors** — `BindBody`/`BindQuery` decode failures return the new `*credo.BindError` carrying a machine-readable `Reason` (`syntax`, `type_mismatch`, `invalid_value`, `empty_body`, `trailing_data`, `duplicate_field`), the affected field path, the expected type, and the JSON byte offset. The error pipeline renders it as `400 Bad Request` with `type: "https://credo.dev/errors/binding"` and a single validation-shaped `errors[]` entry, so clients consume decode and validation failures through one format while the 400/422 split keeps the parse/validate distinction.
- **Single JSON value per body** — content after the first JSON value (a second document, or trailing garbage) is rejected with reason `trailing_data`; trailing whitespace remains accepted.
- **Duplicate members rejected** — repeated JSON object members, previously last-value-wins, are rejected with reason `duplicate_field`. Case-variant repeats (`{"name":…,"Name":…}`) are also caught.
- **`encoding/json/v2` decoding** — `BindBody` JSON decoding runs on the standard v2 package. Member-name matching against struct fields stays v1-compatible case-insensitive, and unknown members remain accepted, so well-formed existing payloads keep binding unchanged.
- **Localizable decode messages** — client messages translate through `bind.<reason>` i18n keys with the same fallback chain and `{{.field}}` translation as validation messages; the response title uses `http.bind_failed`.

## Upgrade notes

This release changes observable behavior for malformed JSON payloads:

- Requests whose body contains content after the first JSON value now fail with 400 `trailing_data` instead of being silently accepted.
- Requests with duplicated JSON object members now fail with 400 `duplicate_field` instead of silently keeping the last value.
- Decode-error responses gained structured `errors[]` detail; previously they carried only a generic title such as `invalid JSON body`. Clients that parsed error titles should switch to the stable `errors[].code` reason values.

Well-formed payloads are unaffected: unknown members remain accepted, member matching remains case-insensitive, XML and form binding semantics are unchanged, and body-size overruns keep their dedicated 413 classification. Server-side, the underlying decoder error is preserved on `BindError.Internal` for logging and never exposed to clients.

The required test, race, real-database, lint, release-gate, and CodeQL checks pass for the release candidate. An additional full-lint canary remains non-blocking while third-party analyzer IR support catches up with the Go 1.27 release candidate.
