# Credo v0.23.0

Credo v0.23.0 is a **bug-fix release**. It fixes defects found while shipping v0.22.0, in the HTTP write path (informational statuses, flushes), in routing (an empty catch-all rest, repeated and reserved parameter names), in YAML configuration parsing and in the release gate. Three of the fixes change behavior an application can observe — a catch-all matches an empty rest, a pattern that repeats a parameter name panics at registration, and a YAML config with more than one document fails to load — so read [Check this first](#check-this-first). `Response` gains `FlushError`; nothing is removed or renamed. `store/sqldb` has no code changes; its tag follows the lockstep policy. Credo remains Beta and pre-1.0.

The root module and Bun SQL wrapper are published in lockstep:

| Module | Version |
| --- | --- |
| `github.com/credo-go/credo` | `v0.23.0` |
| `github.com/credo-go/credo/store/sqldb` | `v0.23.0` |

## Requirements and installation

This release requires Go 1.27.

```sh
go get github.com/credo-go/credo@v0.23.0
go get github.com/credo-go/credo/store/sqldb@v0.23.0
```

Applications that do not use SQL only need the root module. No dependency version changes in this release.

## Check this first

| If your application… | Before v0.23.0 | From v0.23.0 |
| --- | --- | --- |
| registers a catch-all such as `/files/{path...}` | `/files/` answered 404, or was redirected to a sibling `/files` route | `/files/` reaches the catch-all with `path` = `""`; `/files` without a route of its own is redirected to `/files/`; `POST /files/` on a GET-only catch-all is 405 |
| registers both `GET /files` and `GET /files/{path...}` | `/files/` was redirected to `/files` | `/files/` is served by the catch-all with an empty `path`; handle the empty value, or register `GET /files/` |
| mounts a handler (`Mount("/admin", h)`, `Mount("/t/{tenant}", h)`) | `/admin/` was redirected to `/admin` (404 with `WithRedirectTrailingSlash(false)`) | `/admin/` and `/t/acme/` reach the mounted handler as its root `/` |
| serves files with `Static("/static", fsys)` | `/static/` was redirected to `/static` | `/static/` serves the index directly |
| uses a parameter name twice in one pattern — a route, a group or mount prefix joined to it, a rewrite rule, a host pattern | registered; `RouteParam` read the first capture, `RouteParams` and `URLParam` the last | panics at registration: `duplicate parameter name "id"` |
| names a mount prefix parameter `_mount`, or a group prefix parameter `_static` under `Static` | registered; the child read the rest of the path as `_mount`, `Static` served the prefix value as the file path | panics at registration: `the parameter name "_mount" is reserved` |
| has a host parameter without a name (`{}`, `{:[a-z]+}`) or with an empty constraint (`{org:}`) | registered | `app.Host` panics |
| loads a YAML config with a `---` after the first document, a trailing `---` included | loaded the first document; the rest was dropped without a word | fails to load: `yaml: a config file holds one document; found another after the first` |
| sends Early Hints (`WriteHeader(103)`) before its final status | the final status was dropped: the client saw 103, then an implicit 200 | the 103 goes out at once; the final status follows as written |
| flushes before its first write and returns an error afterwards | the error envelope was appended to the flushed 200 | the error is logged (`credo: error after response committed`), as after any other commit |
| calls `http.NewResponseController(w).Flush()` where no writer in the chain can flush | returned nil | returns `http.ErrNotSupported` and commits nothing |
| calls `WriteHeader` with a code outside 100–999 | the response was recorded as committed with that code; the client got an empty 200 | panics before anything is recorded, as net/http does; recovery answers 500 |

## Changed: a catch-all matches an empty rest

`/files/{path...}` serves `/files/` with `path` = `""`, as chi and `net/http.ServeMux` do. The catch-all used to need at least one byte, so the prefix followed by a slash never reached it. That reached every catch-all the framework registers itself: a mount never saw its own root through `/admin/`, and `Static` served `/static/` only through a redirect to `/static`.

Static, regex and plain candidates keep their priority over the catch-all, and a `{name}` or `{name:regex}` parameter still never matches an empty segment. A catch-all that lacks the request method makes `POST /files/` a 405 like any other candidate. `BuildURI` and `BuildURL` accept an empty catch-all value and build the prefix with the slash (`/files/`), which now routes back. The rewrite middleware's `{name...}` already matched an empty rest; the router now agrees with it ([router spec](../specs/router.md#url-parameters), [migration guide](../guides/pre-v1-migration.md#router)).

## Changed: a pattern names each parameter once

A name is how a capture is read, so a pattern that uses a name twice panics at registration:

```go
app.GET("/a/{id}/b/{id}", h)
// panic: credo: pattern: duplicate parameter name "id" in "/a/{id}/b/{id}"
```

The check runs on the whole registered pattern — a route, a group prefix joined to its routes, a `Mount` prefix, `Static` under a parametric group — and on the `From` pattern of a rewrite rule, as in chi and `net/http.ServeMux`. Before, such a pattern registered and one request gave different answers: `RouteParam("id")` returned the first capture, `RouteParams()["id"]` and `credo.URLParam` the last, and the rewrite middleware filled its target from the last.

`app.Host` applies the same rule to host parameters and rejects two related faults: `{a}.{a}.example.com` kept only the leftmost label's value, `{}` and `{:[a-z]+}` made a parameter readable only as `RouteParam("")`, and `{org:}` compiled to a constraint no label matches.

`Mount` and `Static` reserve the name of the capture they add below their prefix. `Mount("/t/{_mount}", h)` handed the child the rest of the path as its `_mount` path value, and a group prefix `/t/{_static}` under `Static` had its value served as the file path. Both panic, and a name either prefix repeats is reported against the pattern the caller wrote:

```go
app.Mount("/t/{_mount}", h)
// panic: credo: Mount "/t/{_mount}": the parameter name "_mount" is reserved
```

## Changed: a YAML config holds one document

The YAML parser read the first document of a stream and dropped the rest without a word: `a: 1` / `---` / `b: 2` loaded `{a: 1}`, a second document with a syntax error loaded as well, and a file that opened with two `---` markers loaded an empty config. `Load`, `LoadBytes`, `Reload` and `Stage` now fail with `yaml: a config file holds one document; found another after the first`, or with the second document's syntax error, as JSON already rejected trailing data.

A trailing `---` opens an empty second document and is rejected too: delete the marker. A leading `---` and a closing `...` belong to the one document, and an empty or comment-only file is still an empty config. To migrate a multi-document file, merge it into one mapping; the application ran with the first document only, so its values are the ones in effect ([config spec](../specs/config.md#single-pass-loader-model), [migration guide](../guides/pre-v1-migration.md#configuration)).

## Fixed: an informational status is not the final one

`WriteHeader(103)` for Early Hints, or any 1xx other than 101, is sent at once and no longer recorded as the response status. `Response` used to record it and drop the handler's real status, so the client saw 103 followed by an implicit 200; under `UseCompress` the compression writer also made its decision on the 1xx and left the body uncompressed. `Response.Status()` and `Committed()` stay 0 and false until the final status; 101 Switching Protocols remains final.

A status outside 100–999 now panics before `Response` or the compression writer records anything, as net/http's own check does. The response used to be recorded as committed with the invalid code, so recovery could not answer, the access record carried that code and the exchange ended with an empty 200; recovery now answers 500.

## Fixed: a flush commits the response

net/http writes status 200 when a flush comes before any status, but `Response` stayed uncommitted. An error the handler returned afterwards was rendered into a response already on the wire, its envelope appended to the flushed 200. A flush is now recorded as the commit it is, so such an error is logged (`credo: error after response committed`) as after any other commit; a flush a stdlib middleware makes through `WrapStdMiddleware` is recorded the same way.

`Response` gains `FlushError`, which `http.ResponseController` prefers: it reports `http.ErrNotSupported` and commits nothing when no writer in the chain can flush, where the controller used to report success. Under `UseCompress`, a flush before the first write sent the 200 header without `Content-Encoding` while the body that followed was compressed; the compression decision is now made at the flush, so the flushed header carries `Content-Encoding` ([context spec](../specs/context.md#response-struct)).

## Fixed: release candidate validation stays in its clone

`scripts/releasegate` confines its git commands to the throwaway clone it creates (`GIT_CEILING_DIRECTORIES`), so a directory that is not a repository root fails instead of resolving to an enclosing work tree. Go 1.27's `testing.T.TempDir` places test directories under `GOTMPDIR`; with `GOTMPDIR` inside a Credo checkout, the gate's own tests wrote the synthetic `v0.11.0` and `store/sqldb/v0.11.0` tags into that checkout. A checkout where the tests ran that way restores the published tags:

```sh
git fetch --force origin refs/tags/v0.11.0:refs/tags/v0.11.0 refs/tags/store/sqldb/v0.11.0:refs/tags/store/sqldb/v0.11.0
```

Published tags and releases were never affected.

## Internal

- The DI container no longer re-checks aliases and `BindMany` collections at `Finalize`: `Alias` and `BindMany` reject those faults when the binding is made and no registration is ever removed, so the checks could never report anything. No behavior change.
- Tracked files no longer point at an untracked contributor file; the dependency allowlist that the import-boundary test enforces is described in [CONTRIBUTING.md](../../CONTRIBUTING.md#coding-standards).

## Unchanged

The rest of the router, the middleware chain, the error pipeline, configuration loading for JSON and `.env`, the DI container, workers and `store/sqldb` are as in [v0.22.0](v0.22.0.md). The full list of changes is in the [CHANGELOG](../../CHANGELOG.md).
