# Credo v0.2.0

Credo v0.2.0 is the framework's first tagged release. The project remains Beta and pre-1.0: the integrated core is ready for real application development, while APIs may still evolve before v1.

The root module and Bun SQL wrapper are published in lockstep:

| Module | Version |
| --- | --- |
| `github.com/credo-go/credo` | `v0.2.0` |
| `github.com/credo-go/credo/store/sqldb` | `v0.2.0` |

## Requirements and installation

This release requires Go 1.27. At publication time Go 1.27 is pre-GA, so the repository selects `go1.27rc2`; a newer compatible Go 1.27 toolchain can be used when available.

```sh
go get github.com/credo-go/credo@v0.2.0
go get github.com/credo-go/credo/store/sqldb@v0.2.0
```

Applications that do not use SQL only need the root module.

## Highlights

- **Integrated application core** — radix routing and host routing, pooled request context, typed configuration snapshots, generics-based dependency injection and validation, centralized RFC 7807 errors, authentication, i18n, health probes, workers, and the outbound HTTP client share one lifecycle and error model.
- **Production-oriented data access** — the stdlib-only `store` contracts and pinned Bun adapter provide semantic errors, typed transaction scopes, guarded registration, typed `One`/`All`/`Page` terminals, logical-projection counts, pool diagnostics, migration controls, and PostgreSQL/MySQL/SQLite classification.
- **WebSocket server adapter** — exact-pinned `coder/websocket` integration with secure defaults, Credo handlers, bounded reads, subprotocol policy, and application-managed graceful drain.
- **Explicit shutdown ordering** — `OnPreDrain` and `OnDrain` let subsystems stop admission and finish DI-dependent work before infrastructure teardown.
- **Server and middleware hardening** — configured TLS and HTTP-to-HTTPS redirect, access-log filtering, CSRF protection based on the standard library, atomic mounts, and bounded health execution.

## Upgrade notes for early users

Early adopters using pseudo-versions should review the [full changelog](https://github.com/credo-go/credo/blob/v0.2.0/CHANGELOG.md).

### Breaking changes

- Authentication user access moved to generic methods on `*credo.Context`; the former `context.Context` accessors were removed.
- `config.Load` and `LoadBytes` now return `*config.Config`, and TLS is configured before `Run`; `RunTLS` and `RunTLSContext` were removed.
- `sqldb.Config.MaxIdle` is now `*int`, and malformed DSNs fail during construction instead of being accepted silently.
- SQL terminals are typed and model-less. The former `Paginate`/`PaginateRequest` path was replaced by `Page[T]`, and `PageRequest.Offset` now returns `(int, error)`.
- `SelectQuery.Count` counts the complete logical projection. Strict pagination rejects invalid or overflowing windows before database I/O.
- Store registration now has explicit lifecycle ownership and identity rules; mutable `Registry.Add` access was removed and successfully adopted bindings are replace-protected.
- Custom adapters can use the generic `store.TxScope[T]` transaction carrier.

The required test, race, real-database, lint, and CodeQL gates pass for this release. An additional full-lint canary remains non-blocking while third-party analyzer IR support catches up with the Go 1.27 release candidate.

## Beta boundaries

OpenTelemetry/Prometheus integration, pub/sub, and gRPC remain planned. Cursor pagination and several broader infrastructure abstractions remain deliberately deferred until concrete consumers establish their contracts.
