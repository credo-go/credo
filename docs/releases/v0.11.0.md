# Credo v0.11.0

Credo v0.11.0 is the error-code-inversion release: the machine-readable `Code` becomes the primary, stable identity of every HTTP error, and the message key becomes what it always should have been — optional presentation. `NewHTTPError`'s second argument now takes the code, a frozen status-to-code table supplies defaults, and strict validation turns malformed identifiers into loud developer failures instead of malformed wire bytes. The project remains Beta and pre-1.0. **This release is breaking**: the constructor's positional argument changes meaning while keeping its Go type, so migration requires the mechanical audit below — the strict code grammar turns the dangerous cases into panics under test.

The root module and Bun SQL wrapper are published in lockstep:

| Module | Version |
| --- | --- |
| `github.com/credo-go/credo` | `v0.11.0` |
| `github.com/credo-go/credo/store/sqldb` | `v0.11.0` |

## Requirements and installation

This release requires Go 1.27.

```sh
go get github.com/credo-go/credo@v0.11.0
go get github.com/credo-go/credo/store/sqldb@v0.11.0
```

Applications that do not use SQL only need the root module.

## Breaking: `Code` is the identity, the message key is presentation

v0.10.0 introduced the machine-readable `Code` but derived it from the message key's last dot-segment when unset. That coupled the stable wire contract to a presentation string: renaming a translation key silently renamed the code clients match on. v0.11.0 inverts the relationship ([ADR-009](../adr/009-handler-and-error-handling.md)):

```go
func NewHTTPError(status int, code ...string) *HTTPError
```

- **The optional second argument is the machine code**, validated against `^[a-z0-9]+(_[a-z0-9]+)*$`.
- **A codeless call materializes the default** from a frozen `statusToCode` table — generated once from Go 1.27's `http.StatusText`, lower-snake-cased, committed, and fixture-locked (62 entries; `404` → `"not_found"`, `418` → `"im_a_teapot"`). An unknown status yields `http_<status>` (`499` → `"http_499"`). The table never tracks the live standard library — an informational canary logs drift, and updating the table is a deliberate, reviewed decision.
- **Message keys attach via the new copy-on-write `WithMessageKey`**; `WithCode` and key-to-code derivation are removed.

```go
// identity + presentation, explicitly separated
return credo.NewHTTPError(409, "email_exists").
    WithMessageKey("user.email_exists").
    WithDetails(map[string]string{"field": "email"})
```

### Strict construction, fail-closed classification

`NewHTTPError` panics on a status outside `100..999`, on more than one code argument, and on a grammar-violating code (dotted keys and literal sentences included — exactly the old second-argument styles). Registration-time misuse fails fast at startup; a panic reached at request time is caught by built-in recovery and rendered as a generic 500. The same fail-closed rule guards the classification boundary: a hand-built `HTTPError` struct with an invalid status or code, or a legacy `HTTPStatus() int` provider returning an out-of-domain value, classifies as a generic 500 and none of the invalid fields reach the wire.

### Title resolution: two explicit chains

- **Explicit `MessageKey`**: i18n bundle → built-in English default → the key itself as literal text (unchanged 3-level fallback).
- **No key**: bundle lookup under `errors.<code>` (e.g. `errors.not_found`) → `http.StatusText` → `"HTTP <status>"`.

Default locale keys for built-in HTTP titles accordingly move from `http.*` to `errors.*`. `http.validation_failed` and `http.request_timeout` are kept, because framework code sets them as explicit keys.

### Sentinels and `Error()`

Sentinels are constructed through the same path, so their stored field state changes: `ErrNotFound.Code == "not_found"` and `ErrNotFound.MessageKey == ""`. Renderers are unaffected — `ErrorInfo.MessageKey` still carries the effective classification key (now `errors.not_found`). `HTTPError.Error()` prints machine identity first, omitting empty segments:

```
credo: http error: status=409, code=email_exists, key=user.email_exists, internal=…
```

### Wire impact

Errors whose code was previously **derived** from a built-in key keep byte-identical bodies (`404` carried `"not_found"` before and after). Previously code-less responses — sentinels without a derivable segment, unknown statuses, generic 500s — **gain** a `code` member with the frozen default: a strictly additive RFC 7807 extension change. Bind failures keep the decode reason as their code and validation failures keep `validation_failed`.

## Migration from v0.10.0

The positional argument keeps the same Go type while changing meaning, so old calls may compile. Audit every `NewHTTPError` second argument, every `WithCode` chain, and every direct `HTTPError{...}` literal:

| v0.10.0 | v0.11.0 |
| --- | --- |
| `NewHTTPError(s, key).WithCode(code)` | `NewHTTPError(s, code).WithMessageKey(key)` |
| `NewHTTPError(s, "user.not_found")` | `NewHTTPError(s, "user_not_found").WithMessageKey("user.not_found")` |
| `NewHTTPError(s, "literal message")` | `NewHTTPError(s, "stable_code").WithMessageKey("literal message")` |
| `NewHTTPError(s)` / sentinels | unchanged call site; stored fields change as below |
| `ErrNotFound.Code == ""` | `ErrNotFound.Code == "not_found"` |
| `ErrNotFound.MessageKey == "http.not_found"` | `ErrNotFound.MessageKey == ""`; use `ErrorInfo.MessageKey` for the effective key |
| `HTTPError{Status: s, Code: code, MessageKey: key}` | `NewHTTPError(s, code).WithMessageKey(key)` |
| `HTTPError{Status: s, MessageKey: key}` | `NewHTTPError(s, oldDerivedCode).WithMessageKey(key)` |
| default locale key `http.not_found` | `errors.not_found` |

To preserve wire parity for a previously derived code, pass the old derived segment explicitly and keep the old key via `WithMessageKey` — status, code, and title bytes then match v0.10.0 exactly. Also update: assumptions that a sentinel's `Code` is empty or its `MessageKey` prepopulated; direct `HTTPError` marshaling snapshots; `Error()` string assertions and log fixtures; and locale bundles using the old `http.*` defaults. The strict grammar means the riskiest old call shapes (dotted keys, literal messages in the second argument) fail loudly under test instead of shipping malformed codes.

## Upgrade notes

Applications that only used codeless `NewHTTPError(status)` calls, the sentinels, and renderers reading `ErrorInfo` compile and behave unchanged apart from the additive `code` member and the in-memory sentinel field state. Applications that passed message keys or literals positionally must migrate per the table; the compiler will not find those sites, but the test-time panics will.

The required test, race, real-database, lint, release-gate, examples, and CodeQL checks pass for the release candidate. An additional full-lint canary remains non-blocking while third-party analyzer IR support catches up with Go 1.27.
