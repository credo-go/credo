# Credo v0.19.0

Credo v0.19.0 is the **pre-v1 contracts** release. It ships the bootstrap and DI ownership model, endpoint-owned path parameter names, one canonical wire form for URL matching and generation, and framework-owned HTTP features behind single `Use*` registrations — the four behavioural themes accepted on 2026-09-05 — together with two measured performance packages and the fixes from three review passes over that tree. Several changes are breaking; the [pre-v1 migration guide](../guides/pre-v1-migration.md) maps every removed or changed API to its replacement. Credo remains Beta and pre-1.0.

The root module and Bun SQL wrapper are published in lockstep:

| Module                                  | Version   |
| --------------------------------------- | --------- |
| `github.com/credo-go/credo`             | `v0.19.0` |
| `github.com/credo-go/credo/store/sqldb` | `v0.19.0` |

## Requirements and installation

This release requires Go 1.27.

```sh
go get github.com/credo-go/credo@v0.19.0
go get github.com/credo-go/credo/store/sqldb@v0.19.0
```

Applications that do not use SQL only need the root module.

## Breaking changes

Every break fails at compile time, at registration (panic or error) or at `Finalize`, never silently at request time — except the wire-form change, which alters what a route matches and what `RouteParam` reports and is called out separately below.

### Bootstrap and DI ownership

- **`Resolve` is admitted only after `Finalize`.** Constructors never run during registration. A composition root that resolves services before `Run` adds an explicit, error-checked `app.Finalize()` after its last DI write; `Run`'s implicit Finalize remains a safeguard. `Finalize` is DI-only: routes, hooks and renderers stay open until the App prepares to serve.
- **`Replace`/`MustReplace` return the superseded instance** — `(old T, existed bool, err error)`. The container no longer closes the old value; its cleanup belongs to the caller. `if err := app.Replace…` becomes `if _, _, err := …`.
- **Dependency-ordered shutdown.** `Shutdown` closes consumers before the singletons they were constructed from (constructor parameters, aliases, `BindMany` edges), reverse registration order as the tie-break. Each `Shutdowner` gets one attempt bounded by the shared context; a callback that ignores the deadline keeps its dependencies blocked and is reported, never retried. A build that completes after the context ended gets one fixed five-second cleanup attempt. Failure or incompleteness returns `*DIShutdownError`.
- **Terminal construction results.** A constructor's value, error or panic is shared by every caller with no retry; a constructor panic surfaces as `*DIPanicError`, so `MustResolve` panics with that error. Once teardown begins `Resolve` returns an error wrapping `ErrDIClosed`.
- **`ProvideFactory` and `MustProvideFactory` are removed.** Register typed constructors with explicit dependency parameters.

### Router

- **Path parameter names belong to the endpoint.** Routes that share a dynamic segment may name it differently (`/customers/{id}` and `/customers/{customer_id}/timeline`), so the "conflicting parameter name" registration panic is gone. Registering the same method on the same shape under another name still panics, now spelling out both call sites.
- **`BuildURI`/`BuildURL` validate and escape their values.** Values are decoded parameter values: checked against their constraint, percent-encoded per segment (`a/b` → `a%2Fb`), host labels validated and never encoded. Empty values, invalid UTF-8, constraint failures and a value whose wire spelling shows its parameter's delimiter are errors. Callers that pre-escaped values pass raw values now.

### Wire form

**Route parameters are percent-decoded once and constraints apply to the decoded value.** Matching runs on the canonical form of `URL.EscapedPath()`: every escape of an unreserved or non-ASCII byte is decoded, the escapes of the RFC 3986 reserved characters and of `%` are kept. Consequences:

- `/caf%C3%A9`, `/caf%c3%a9` and `/%63af%C3%A9` all reach a route registered as `/café`; `%2D` is `-` (§2.3), while `%3B` is not `;` (§2.2): it never meets static `;` text or a `;` delimiter, reaches a mounted app as `%3B`, and a captured `%3B` decodes to `;`.
- `RouteParam` reports decoded values: `%2F` is `/` inside one segment, `%252F` is `%2F`, `%31` is `1` and satisfies `[0-9]+`, `+` stays `+`.
- A regex constraint matches the whole decoded value, never a prefix, and a `{name}` or `{name:regex}` parameter never spans a raw slash — `/{name}.json` no longer matches `/a/b.json`; use `{name...}`.
- A candidate that decodes to invalid UTF-8 answers 400 `invalid_path_encoding`. `Context.Rewrite` takes a wire-form target; mounted handlers receive the raw remainder with `URL.RawPath` set.

### Built-in HTTP features

- **A default App enables panic recovery only.** Request IDs and access records are opt-in: `app.UseRequestID()` and `app.UseAccessLog()`. Recovery is configured with `credo.WithRecoverConfig`; `WithoutRecover()` wins regardless of option order.
- **Converted middleware is removed.** `middleware.Recover`, `RequestID`, `AccessLog`, `Compress`, `Decompress`, their config types, `GetRequestID` and `RequestIDKey`, plus `WithoutRequestID`, `WithoutAccessLog` and the four `WithAccessLog*` options. The replacements are the root `UseRequestID`, `UseAccessLog`, `UseCompress` and `UseDecompress` registrations with `RequestIDConfig`, `AccessLogConfig`, `CompressConfig` and `DecompressConfig`; handlers read the ID with `ctx.RequestID()`.
- **One request executor** runs Request ID → access-log start → decompression → compression writer → user chain → error rendering → recovery → compressor finalization → access-log observation, whatever the `Use*` call order. The access record observes the committed status and post-compression bytes; error envelopes and panic responses are compressed like handler output; decompression runs before Global middleware.
- **`SetErrorRenderer`/`SetSuccessRenderer` are replaced by `UseErrorRenderer`/`UseSuccessRenderer`** (single install; a renderer may be a method of a DI-resolved service).
- **`I18nConfig.Detect` is `func(*Context) string` and runs lazily** on the first `Locale`/translation of a request, memoized per request; `UseI18n` installs no middleware.

## Added

- `App.Has[T]()`, `App.AdoptValue[T](validate)` and `App.ConfigExists(key)` for registration-time reads that never construct; `store.Register` and `worker.Register` adopt pre-provided values through `AdoptValue`.
- DI diagnostics `ErrDIClosed`, `*DIPanicError` and `*DIShutdownError` (an immutable per-singleton snapshot with blockers, failure and timing).
- **Bootstrap teardown**: `App.Shutdown` is accepted in the `building` state and drains without servers, so composition roots and `ServeHTTP`-only tests can release DI resources.
- **Lifecycle 503**: a request reaching `ServeHTTP` after the App stopped receives `service_unavailable` from a callback-free branch.
- `Response` implements `io.ReaderFrom`: `Stream` and `io.Copy` into a response no longer allocate a 32 KiB buffer per call, delegate large sources to net/http's writer (sendfile on plaintext TCP) and keep `Size()` and the commit rule exact, including when the source panics mid-stream.

## Performance

Error bodies encode with a JSON option set joined once (`ErrorOptions` 26.7 ns / 1 alloc → 0.6 ns / 0 allocs), translation lookups for a resolved locale use a canonical-string table (`UseI18n_T` 1.10 µs / 13 allocs → 0.19 µs / 1 alloc), access logging without a `ResultFilter` checks the logger level before building the entry (136 ns / 1 alloc → 66 ns / 0 allocs), and the 4 KiB `StreamReaderOnly` path went from 5.36 µs / 32.8 KiB / 3 allocs to 0.21 µs / 24 B / 2 allocs. Every change carries a `-count=10` benchstat comparison in its pull request; the evidence rule is in [CONTRIBUTING](../../CONTRIBUTING.md#performance-changes).

## Fixed

- Compressing a bodiless 204/304 with a compressible `Content-Type` no longer aborts the connection.
- Static pattern text with non-ASCII or percent-encoded spellings now matches; generation writes static text in its wire spelling and trailing-slash redirects spell `Location` for the wire.
- URL generation rejects values that could not route back instead of producing a 404 or 400 URI, and a `%` delimiter in a pattern is matched as its `%25` unit.
- DI shutdown no longer leaves a build that completes during the pass — successfully or not — unattempted or its dependencies blocked.
- `App.Shutdown` racing a managed start no longer refuses with a stale `running` state: a start that reaches `running` (or rolls back to `building`) while the call is deciding is claimed by that same call.

## Unchanged

Configuration loading, validation, the error envelope, health probes, store contracts and the public worker API carry over as they are. `store/sqldb` participates in this release through the lockstep version bump and the `AdoptValue`-based Registry adoption described above.
